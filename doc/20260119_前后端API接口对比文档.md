| **路由** | `GET /users/profile` | `GET /users/{user_id}/profile` | ⚠️ 路径不一致 |

## 7. 总结与差异分析

### 7.1 主要差异类型

#### 7.1.1 响应格式差异（最常见）

**问题**: 后端统一使用 `ResponseSchemaModel` 包装响应，前端期望直接返回数据对象。

**影响范围**: 几乎所有接口

**解决方案**:
1. **推荐方案**: 前端统一处理响应格式，在API拦截器中自动提取 `data` 字段
2. **备选方案**: 后端提供配置选项，支持直接返回数据（不推荐，破坏统一性）

---

#### 7.1.2 路径不一致

**问题**: 前端和后端的路由路径不匹配。

**影响范围**: 
- 用户画像: `/users/profile` vs `/users/{user_id}/profile`
- 路线图状态: `/roadmaps/{id}/status` vs `/roadmaps/{id}/status-check`
- 编辑记录: `/roadmaps/{roadmap_id}/edit-records` vs `/roadmaps/{task_id}/edit-records`
- 内容管理: `/roadmaps/...` vs `/content/...`
- 封面图: `/roadmaps/{id}/cover-image/generate` vs `/roadmaps/roadmap/{id}/cover-image/generate`
- 管理员接口: `/admin/users/invite` vs `/admin/invite-user`

**解决方案**:
1. **推荐方案**: 统一使用RESTful风格，以资源为主体
2. 用户画像: 改为 `/users/profile`，从JWT自动提取user_id
3. 编辑记录: 统一使用 `roadmap_id` 而非 `task_id`
4. 内容管理: 统一使用 `/content/...` 前缀
5. 管理员接口: 统一使用 `/admin/users/...` 格式

---

#### 7.1.3 字段名不一致

**问题**: 前端期望的字段名与后端返回的字段名不一致。

**影响范围**:
- 列表响应: `items` vs `roadmaps`
- 黑名单统计: `active_tokens`, `expired_tokens` vs `sample_tokens`
- Waitlist: `position` vs `is_new`

**解决方案**:
1. **推荐方案**: 统一字段命名规范
2. 列表响应: 统一使用 `items` 字段
3. 黑名单统计: 添加 `active_tokens` 和 `expired_tokens` 字段
4. Waitlist: 添加 `position` 字段

---

#### 7.1.4 接口缺失

**问题**: 前端调用的接口在后端不存在。

**影响范围**:
- 内容重试接口: `/content/tutorials/{id}/{id}/retry`
- 内容批量重试: `/content/roadmaps/{id}/retry-failed`

**解决方案**:
1. **推荐方案**: 后端实现缺失的接口
2. **备选方案**: 前端使用现有的regenerate接口替代

---

### 7.2 优先级建议

#### 🔴 高优先级（阻塞性问题）

1. **响应格式统一**: 前端需要统一处理 `ResponseSchemaModel` 格式
2. **路径统一**: 用户画像、编辑记录、内容管理等关键路径需要统一
3. **接口缺失**: 内容重试相关接口需要实现

#### 🟡 中优先级（功能性问题）

1. **字段名统一**: 列表响应、统计字段需要统一
2. **参数不一致**: 分页参数、查询参数需要统一
3. **HTTP方法不一致**: DELETE vs POST（批量删除）

#### 🟢 低优先级（优化项）

1. **可选参数支持**: 重试接口的参数支持
2. **分页参数**: 回收站等接口的分页支持
3. **文档完善**: API文档和类型定义完善

---

### 7.3 修复建议

#### 前端修复（推荐）

1. **统一响应处理**: 在 `apiClient` 拦截器中自动提取 `data` 字段

// frontend-next/lib/api/client.ts
apiClient.interceptors.response.use(
  (response) => {
    const { data } = response;
    
    // 统一响应格式处理
    if (data && typeof data === 'object' && 'code' in data && 'msg' in data && 'data' in data) {
      const apiResponse = data as APIResponse<any>;
      
      // 验证业务状态码
      if (apiResponse.code !== 200) {
        throw new Error(apiResponse.msg);
      }
      
      // 自动提取data字段
      response.data = apiResponse.data;
      return response;
    }
    
    return response;
  },
  (error) => {
    // 错误处理
    return Promise.reject(error);
  }
);
