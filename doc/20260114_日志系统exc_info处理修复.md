# 日志系统 exc_info 处理修复

**日期**: 2026-01-14  
**类型**: Bug 修复  
**优先级**: 高  
**状态**: ✅ 已修复

## 🐛 问题描述

在执行 Tavily Keys 批量添加脚本时，触发了后端日志系统的 bug：

```
TypeError: cannot unpack non-iterable bool object
at backend/app/utils/log_formatters.py:114
```

### 错误场景

当代码使用 `logger.error(exc_info=True)` 记录异常时（Python logging 标准用法），`exc_info` 参数为布尔值 `True`，而不是异常信息元组 `(type, value, traceback)`。

### 错误堆栈

```python
File "backend/app/utils/log_formatters.py", line 114, in format_exception_compact
    exc_type, exc_value, exc_traceback = exc_info
    ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^
TypeError: cannot unpack non-iterable bool object
```

## 🔧 修复方案

### 修复文件

**`backend/app/utils/log_formatters.py`**

### 修复内容

在 `format_exception_compact` 函数中添加对 `exc_info=True` 的处理：

```python
def format_exception_compact(exc_info) -> str:
    """
    简化异常堆栈输出
    
    Args:
        exc_info: (type, value, traceback) 元组或 True（表示使用 sys.exc_info()）
    """
    if not exc_info or exc_info == (None, None, None):
        return ""
    
    # ✅ 新增：处理 exc_info=True 的情况
    if isinstance(exc_info, bool) and exc_info:
        import sys
        exc_info = sys.exc_info()
    
    # 再次检查是否为有效的异常信息
    if not exc_info or exc_info == (None, None, None):
        return ""
    
    exc_type, exc_value, exc_traceback = exc_info
    # ... 后续处理
```

### 修复逻辑

1. **检测布尔值**: 使用 `isinstance(exc_info, bool)` 检测是否为布尔值
2. **获取异常信息**: 当 `exc_info=True` 时，调用 `sys.exc_info()` 获取当前异常
3. **二次验证**: 再次检查获取到的异常信息是否有效
4. **正常处理**: 继续原有的异常格式化逻辑

## 🎯 根本原因

之前在优化日志系统时（`20260114_日志系统优化完成.md`），`format_exception_compact` 函数假设 `exc_info` 始终是元组，但忽略了 Python logging 标准用法中 `exc_info=True` 的情况。

### Python Logging 标准行为

```python
# 方式1: exc_info=True（推荐，更简洁）
logger.error("操作失败", exc_info=True)
# logging 内部会自动调用 sys.exc_info()

# 方式2: 显式传递
import sys
logger.error("操作失败", exc_info=sys.exc_info())
```

两种方式在 Python 标准 logging 中都应该被支持。
