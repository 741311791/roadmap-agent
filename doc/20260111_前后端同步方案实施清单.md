## 九、常见问题

### Q1: 如何手动触发同步？

```bash
# 方式 1: Make
make sync

# 方式 2: npm
cd frontend-next && npm run sync:backend

# 方式 3: 直接运行脚本
./scripts/sync-frontend-backend.sh
```

### Q2: 如何跳过 Pre-commit 检查？

```bash
# 不推荐，但紧急情况下可以使用
git commit --no-verify -m "message"
```

### Q3: 如何在 CI 中禁用同步检查？

在 `.github/workflows/` 中修改触发条件，或者在 commit message 中添加 `[skip ci]`。

### Q4: 如何处理 Breaking Changes？

1. 在 PR 中明确标注 Breaking Changes
2. 提供迁移指南
3. 先更新前端调用代码
4. 合并时通知团队

### Q5: 生成的类型可以手动修改吗？

不推荐。生成的类型在 `types/generated/` 中，会被覆盖。

如需自定义类型，放在 `types/custom/` 中。
