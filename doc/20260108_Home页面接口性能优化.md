# Home 页面接口性能优化

**日期**: 2026-01-08  
**优化人员**: AI Assistant  
**目标**: 优化 Home 页面的两个主要接口调用性能

---

## 一、问题分析

### 1.1 性能瓶颈

Home 页面调用两个接口加载数据较慢：
1. `GET /api/v1/users/{user_id}/roadmaps` - 获取用户路线图
2. `GET /api/v1/featured/roadmaps` - 获取精选路线图

### 1.2 根本原因

**数据量过大**:
- Home 页面只需要显示 **3 个用户路线图** + 1 个 Create 卡片
- Home 页面只需要显示 **4 个精选路线图**
- 但前端请求了默认的 **50 条**数据（或更多）

**影响**:
- 查询了不必要的数据
- 传输了更多的 JSON 数据
- 前端需要处理更多数据

---

## 二、优化方案

### 2.1 前端优化：精确传递 limit 参数

**文件**: `frontend-next/app/(app)/home/page.tsx`

#### 用户路线图优化

```typescript
// ❌ 优化前：使用默认 limit=50
const response = await getUserRoadmaps(userId);

// ✅ 优化后：只获取 4 条（显示 3 条 + 判断是否有更多）
const response = await getUserRoadmaps(userId, 4, 0);
```

**减少数据量**: 50条 → 4条 = **92% 减少**

#### 精选路线图优化

```typescript
// ❌ 优化前：获取 8 条
const response = await getFeaturedRoadmaps(8, 0);

// ✅ 优化后：只获取 5 条（显示 4 条 + 判断是否有更多）
const response = await getFeaturedRoadmaps(5, 0);
```

**减少数据量**: 8条 → 5条 = **37.5% 减少**

## 四、后端架构优势

### 4.1 已有的性能优化

后端代码已经实现了良好的性能优化：

#### 批量查询避免 N+1 问题

**用户路线图服务** (`user_service.py`):
```python
# ✅ 批量查询任务信息
task_result = await session.execute(
    select(RoadmapTask).where(RoadmapTask.roadmap_id.in_(roadmap_ids))
)

# ✅ 批量查询进度信息
progress_result = await session.execute(
    select(
        ConceptProgress.roadmap_id,
        func.count(ConceptProgress.id).label("completed_count"),
    )
    .where(
        ConceptProgress.user_id == user_id,
        ConceptProgress.roadmap_id.in_(roadmap_ids),
        ConceptProgress.is_completed == True,
    )
    .group_by(ConceptProgress.roadmap_id)
)
```

**优势**:
- 避免了 N+1 查询问题
- 使用单次查询获取所有相关数据
- 在内存中构建关联关系

### 4.2 数据库查询优化

#### 索引使用

确保以下字段有索引：
- `roadmap_metadata.user_id` (已有)
