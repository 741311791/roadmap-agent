# 日志系统全进程覆盖完成

**日期**: 2026-01-14  
**类型**: Backend  
**影响范围**: FastAPI 应用 + Celery Worker 进程

---

## 问题分析

### 原有问题

1. **`setup_logging()` 未被调用**
   - FastAPI 应用（`main.py`）：未初始化日志配置 ✗
   - Celery Worker（`celery_app.py`）：未初始化日志配置 ✗

2. **错误日志文件功能未生效**
   - `_setup_error_log_file()` 只有在调用 `setup_logging()` 时才会执行
   - 导致错误日志文件功能对所有进程都不可用

3. **Celery Worker 进程隔离**
   - Celery Worker 是独立进程（`celery -A app.core.celery_app worker`）
   - 不会执行 `main.py`，只导入 `celery_app.py`
   - 需要单独初始化日志配置

---

## 修复方案

### 修复1：FastAPI 应用日志初始化

**文件**: `backend/app/main.py`

```python
# ✅ 在模块导入时就初始化日志系统
from app.config.logging_config import setup_logging
setup_logging()

import structlog
```

**效果**:
- uvicorn 启动 FastAPI 应用时自动初始化日志
- 所有后续的 `structlog.get_logger()` 调用使用正确配置
- 错误日志文件功能正常工作

---

### 修复2：Celery Worker 日志初始化

**文件**: `backend/app/core/celery_app.py`

#### 父进程初始化

```python
# ✅ Celery Worker 独立进程需要初始化日志系统
from app.config.logging_config import setup_logging
setup_logging()

from celery import Celery
```

#### 子进程重新初始化

```python
@worker_process_init.connect
def on_worker_process_init(**kwargs):
    """Worker 子进程初始化时调用"""
    # ✅ 第一步：子进程重新初始化日志系统
    from app.config.logging_config import setup_logging
    setup_logging()
    
    # 后续步骤：事件循环、数据库引擎重置等
```

**效果**:
- Celery Worker 主进程和子进程都正确初始化日志
- RotatingFileHandler 在子进程中正确工作
- 所有 Celery 任务的错误都会被记录到文件

## 为什么需要在子进程中重新初始化？

### Celery prefork 模式特性

| 特性 | 说明 |
|-----|------|
| **进程模型** | 主进程 fork 出多个子进程 |
| **全局变量** | 子进程继承父进程的全局变量 |
| **文件句柄** | RotatingFileHandler 的文件句柄可能失效 |
| **线程锁** | logging 模块的线程锁在子进程中失效 |

### 需要重新初始化的组件

1. **日志系统**：确保 RotatingFileHandler 正确工作
2. **事件循环**：避免 "Event loop is closed" 错误
3. **数据库引擎**：强制子进程创建新的连接池
4. **litellm 状态**：清除跨 event loop 的异步队列

### 第三方库日志降噪

为避免日志污染，以下第三方库的日志级别被限制为 WARNING：

| 库类别 | 库名称 | 原因 |
|--------|--------|------|
| **数据库** | `sqlalchemy.*` | 防止输出大量 SQL 语句 |
| **AWS SDK** | `botocore`, `aiobotocore`, `boto3`, `s3transfer` | 防止 S3 签名和事件详细日志 |
| **HTTP 客户端** | `httpx`, `httpcore`, `urllib3` | 防止 HTTP 请求详细日志 |
| **LLM 客户端** | `LiteLLM`, `litellm`, `openai` | 防止 LLM 调用详细日志 |
| **任务队列** | `celery`, `celery.app.trace` | 减少 Worker 日志 |
| **其他** | `aiohttp`, `asyncio` | 减少异步库详细日志 |

### 日志级别配置

|------|-------------|------------|
| **production** | WARNING | WARNING+ |
| **testing** | WARNING | WARNING+ |
| **development (DEBUG=True)** | DEBUG | WARNING+ |

## 配置说明

### 环境变量

| 变量 | 默认值 | 说明 |
|-----|-------|------|
| `ENABLE_ERROR_LOG_FILE` | `True` (研发环境) | 是否启用错误日志文件 |
| `ERROR_LOG_FILE_PATH` | `logs/err.log` | 日志文件路径 |
| `ERROR_LOG_FILE_MAX_SIZE` | `10485760` (10MB) | 单文件最大大小 |
| `ENVIRONMENT` | `development` | 运行环境 |
| `DEBUG` | `False` | 调试模式 |

### 日志文件特性

- **仅记录警告和错误**：最小日志级别 WARNING
- **自动轮转**：单文件超过 10MB 自动覆盖
- **不保留备份**：`backupCount=0`
- **可读格式**：`时间 | 级别 | 模块 | 消息`
