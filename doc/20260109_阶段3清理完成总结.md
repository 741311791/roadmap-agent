## 二、问题 1：消除版本后缀 ✅

### 问题描述

**文件：** `backend/app/services/content_retry_service.py`

```python
# ❌ 同时存在两个版本
async def get_failed_content_items_v2(...)  # 新版本，基于 concept_metadata
def get_failed_content_items(...)            # 旧版本，基于 framework_data
```

**违反规范：** 不允许函数名有 v1/v2 之分

### 解决方案

**步骤 1：** 将 `get_failed_content_items_v2` 的逻辑合并到 `get_failed_content_items`

```python
# ✅ 统一版本
async def get_failed_content_items(
    self,
    session: AsyncSession,
    roadmap_id: str,
) -> Dict[str, List[Dict]]:
    """
    基于 concept_metadata 表获取失败的内容项目（细粒度检测）
    
    策略：
    - 查询 concept_metadata 表，按内容类型分别判断失败状态
    - 从 framework_data 中提取完整的 concept_data 和 context
    """
```

**特点：**
- **异步调用**：需要数据库 session
- **细粒度检测**：基于 `concept_metadata` 表的状态字段
- **完整数据**：包含 concept_data 和 context

**步骤 2：** 更新引用

```python
# backend/app/tasks/content_generation_tasks.py
# 修改前
failed_items = content_retry_service.get_failed_content_items(roadmap_metadata.framework_data)

# 修改后
failed_items = await content_retry_service.get_failed_content_items(
    session=session,
    roadmap_id=roadmap_id
)
```

## 三、问题 2：合并双重试服务 ✅

### 问题描述

**存在两个文件：**
- `backend/app/services/retry_service.py` (490 行)
  - 包含：`execute_retry_failed_task` 函数（后台任务执行）
- `backend/app/services/retry_service_new.py` (395 行)
  - 包含：`RetryService` 类（数据准备、策略判断）

**冲突：**
```python

```

### 架构分析

| 文件 | 职责 | 关键内容 |
|------|------|----------|
| `retry_service.py` | 执行后台任务 | `execute_retry_failed_task` 函数 |
| `retry_service_new.py` | 准备数据、策略判断 | `RetryService` 类 + 3 个 prepare 方法 |

**合并策略：** 将两者合并到同一个文件，保持职责分离

### 解决方案

**新的 `retry_service.py` 结构：**

```python
# ===== 第一部分：RetryService 类（数据准备 + 策略判断）=====
class RetryService:
    """
    重试服务
    
    职责：
    - 识别失败的内容项（委托给 ContentRetryService）
    - 创建重试任务
    - 调度后台任务执行
    - 智能重试策略（checkpoint 恢复 vs 内容重试）
    """
    
    def __init__(self):
        self.roadmap_crud = RoadmapCRUD(RoadmapMetadata)
        self.task_crud = TaskCRUD(RoadmapTask)
        self.concept_crud = ConceptCRUD(ConceptMetadata)
        self.content_retry_service = ContentRetryService()  # ✅ 依赖注入
    
    async def prepare_retry_failed_content(...)
    async def prepare_regenerate_content(...)
    async def prepare_retry_task(...)


def get_retry_service() -> RetryService:
    """获取 RetryService 实例"""
    return RetryService()


# ===== 第二部分：后台任务执行函数 =====
async def execute_retry_failed_task(
    retry_task_id: str,
    roadmap_id: str,
    items_to_retry: dict,
    user_preferences: LearningPreferences,
    user_id: str,
):
    """
    后台执行重试失败任务
    
    包含：
    - Agent 调用
    - 进度通知
    - 数据库更新
    - ExecutionLog 记录
    """
```

---

### 改进 3：统一依赖方向 ✅

**架构层次：**

```
┌─────────────────────────────────────────┐
│  API 层 (endpoints/retry.py)           │
└──────────────┬──────────────────────────┘
               │ depends on
┌──────────────▼──────────────────────────┐
│  Service 层 (RetryService)              │
│  - prepare_retry_failed_content         │
│  - prepare_regenerate_content           │
│  - prepare_retry_task                   │
└──────────────┬──────────────────────────┘
               │ delegates to
┌──────────────▼──────────────────────────┐
│  ContentRetryService                    │
│  - get_failed_content_items             │
└──────────────┬──────────────────────────┘
               │ queries
┌──────────────▼──────────────────────────┐
│  Database (concept_metadata)            │
└─────────────────────────────────────────┘
```

**特点：**
- API 层只调用 Service 层
- Service 层之间可以相互调用（委托模式）
- 避免跨层依赖（Task 层不再调用 API 层）
