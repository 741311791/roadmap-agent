# 中间件日志错误修复

> **修复日期**: 2026-01-09  
> **错误类型**: TypeError - structlog 日志方法调用错误

---

## 问题描述

**错误信息**:
```
TypeError: _make_filtering_bound_logger.<locals>.make_method.<locals>.meth() 
missing 1 required positional argument: 'event'
```

**触发位置**: `backend/app/middleware/opera_log_middleware.py:114`

**根本原因**: 
structlog 的日志方法（`logger.info()`, `logger.warning()`, `logger.error()`）需要第一个位置参数为 `event` 字符串，不能直接使用 `**kwargs` 展开字典。

---

## 错误代码

```python
# ❌ 错误写法
log_data = {
    "http_request_completed": True,  # 这个作为键，不是 event
    "method": method,
    "path": path,
    ...
}
logger.warning(**log_data)  # 缺少第一个 event 参数
```

---

## 修复方案

```python
# ✅ 正确写法
log_data = {
    "method": method,
    "path": path,
    "status_code": status_code,
    "duration_ms": round(duration_ms, 2),
    "client_host": client_host,
    "user_id": user_id,
}

if error:
    log_data["error"] = error

# 将 event 作为第一个参数传入
if status_code and status_code >= 500:
    logger.error("http_request_completed", **log_data)
elif status_code and status_code >= 400:
    logger.warning("http_request_completed", **log_data)
else:
    logger.info("http_request_completed", **log_data)
```

## 学习要点

### structlog 日志方法签名

```python
# structlog 的标准调用方式
logger.info("event_name", key1=value1, key2=value2, ...)
logger.warning("event_name", **kwargs)
logger.error("event_name", exc_info=True, **kwargs)
```

**关键规则**:
1. 第一个参数必须是事件名称字符串（`event`）
2. 后续参数为键值对，可以使用 `**kwargs` 展开
3. 不能省略第一个 `event` 参数
