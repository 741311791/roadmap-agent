### ✅ P1-4.1: TaskCRUD 缺少 get_latest_by_roadmap_id 方法（新发现）

**文件**: `backend/app/crud/crud_task.py`

**问题**: 修复 Intent Analysis 404 时引入的新错误

**原子事实**:
- Line 91: `await task_crud.get_latest_by_roadmap_id(db, roadmap_id)`
- TaskCRUD 类中不存在此方法
- Python 方法查找失败，抛出 `AttributeError`

**修复**: 添加缺失的方法
```python
async def get_latest_by_roadmap_id(
    self,
    session: AsyncSession,
    roadmap_id: str,
) -> Optional[RoadmapTask]:
    """
    获取指定路线图的最新任务
    
    按 created_at 降序排列，返回第一条记录。
    """
    result = await session.execute(
        select(RoadmapTask)
        .where(RoadmapTask.roadmap_id == roadmap_id)
        .order_by(RoadmapTask.created_at.desc())
        .limit(1)
    )
    return result.scalar_one_or_none()
```

**影响**: Intent Analysis 接口恢复正常

### ✅ P2-5: LLM 输出格式错误

**文件1**: `backend/prompts/structure_validator.j2`

**问题**: Prompt 约束不足，LLM 生成了未定义的 `split_module` 操作

**修复**: 添加严格的操作类型约束章节：
```jinja2
[4. Structural Suggestion Operations - 严格限制]

⚠️ 你只能使用以下 8 种操作类型，禁止创造任何新的操作

1. add_concept
2. add_module
3. add_stage
4. modify_concept
5. reorder_stage
6. reorder_module
7. reorder_concepts
8. merge_modules

❌ 严禁使用: split_module, delete_module, rename_* 等
```

**文件2**: `backend/app/agents/structure_validator.py`

**修复**: 添加重试机制（最多3次），在重试时将错误信息反馈给 LLM

**影响**: LLM 输出非法操作时自动重试，提高成功率

### ✅ P2-6: Event Loop 冲突

**问题**: Celery Worker fork 后，litellm 的异步 Queue 仍绑定到旧的 event loop

**修复**: 增强 litellm 重置逻辑：

```python
litellm.failure_callback = []

litellm._async_failure_callback = []
```

**影响**: Celery Worker 重启后不再出现 RuntimeError
