# 本地错误日志文件功能开发完成

## 需求回顾

用户需求：**在本地环境加入错误日志收集功能，生成err.log文件**

关键要求：
- ✅ 架构改动最小化
- ✅ 只针对本地环境
- ✅ 可读性优先（非JSON格式）
- ✅ 单文件最大10MB
- ✅ 不需要备份文件
- ✅ 包含WARNING级别

## 实现方案

采用 **方案C：配置驱动** 实现，通过环境变量控制功能开关。

### 核心特点

1. **最小改动**：仅修改2个配置文件（settings.py、logging_config.py）
2. **配置驱动**：通过 `ENABLE_ERROR_LOG_FILE` 环境变量控制
3. **仅本地启用**：默认禁用，需手动在 `.env` 中开启
4. **可读性优先**：纯文本格式 `时间 | 级别 | 来源 | 消息`
5. **自动轮转**：单文件最大10MB，超过自动覆盖

### 技术实现

**基础架构**：Python 标准库 `logging.handlers.RotatingFileHandler`

**集成方式**：无侵入式集成到现有 structlog 配置

**日志级别**：WARNING、ERROR、CRITICAL（符合用户需求）

### 2. `backend/app/config/logging_config.py` (+55行)

新增文件Handler实现：
```python
def _setup_error_log_file():
    """设置错误日志文件（仅在启用时）"""
    # 创建日志目录
    log_path = Path(settings.ERROR_LOG_FILE_PATH)
    log_path.parent.mkdir(parents=True, exist_ok=True)
    
    # 创建 RotatingFileHandler
    error_handler = RotatingFileHandler(
        filename=log_path,
        maxBytes=settings.ERROR_LOG_FILE_MAX_SIZE,
        backupCount=0,  # 不保留备份
        encoding="utf-8"
    )
    error_handler.setLevel(logging.WARNING)  # WARNING 及以上
    
    # 可读性优先的格式
    formatter = logging.Formatter(
        fmt='%(asctime)s | %(levelname)-8s | %(name)s | %(message)s',
        datefmt='%Y-%m-%d %H:%M:%S'
    )
    error_handler.setFormatter(formatter)
    
    # 添加到 root logger
    logging.getLogger().addHandler(error_handler)
```

在 `setup_logging()` 中添加调用：
```python
# ===== 配置错误日志文件（仅在启用时）=====
if settings.ENABLE_ERROR_LOG_FILE:
    _setup_error_log_file()
```

## 使用方法

### 启用功能

在 `.env` 文件中添加：
```bash
ENABLE_ERROR_LOG_FILE=true
```

### 启动服务

```bash
cd backend
make dev
```

### 查看日志

```bash
# 实时查看
tail -f backend/logs/err.log

# 搜索错误
grep "ERROR" backend/logs/err.log

# 查看最近50行
tail -n 50 backend/logs/err.log
```

## 常见问题

### Q: 日志文件没有生成？
A: 检查 `.env` 中 `ENABLE_ERROR_LOG_FILE=true` 是否设置

### Q: 日志文件太大？
A: 会自动轮转，最大10MB后覆盖

### Q: 生产环境会启用吗？
A: 不会，默认禁用，需手动开启

### Q: 可以修改日志格式吗？
A: 可以，修改 `logging_config.py` 中的 Formatter
