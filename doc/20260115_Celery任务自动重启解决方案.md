# Celery Worker 重启后自动运行任务解决方案

**日期**: 2026-01-15  
**问题**: Worker 重启后，未完成的任务自动重新执行

---

## 🔍 问题根因

当前 Celery 配置使用了**任务持久化机制**：

```python
# backend/app/core/celery_app.py
task_acks_late=True,                    # 任务完成后才确认(ACK)
task_reject_on_worker_lost=True,        # Worker丢失时拒绝任务,重新入队
```

### 工作原理

```
1. Worker 接收任务 → 开始执行
2. Worker 崩溃/重启 → 任务未确认(ACK)
3. Redis 检测到任务未完成 → 重新入队
4. Worker 重启后 → 自动接收并重新执行
```

这是 Celery 的**可靠性保证机制**，确保任务不丢失。

---

## 🛑 解决方案（3种方法）

### 方案1: 清空队列（推荐）✅

**适用场景**: 需要彻底清理所有待处理和运行中的任务

```bash
cd backend

# 运行清理脚本
uv run python scripts/clear_celery_queue.py
```

**脚本功能**:
1. ✅ 使用 Celery API 清空队列
2. ✅ 直接清空 Redis 中的队列键
3. ✅ 终止所有正在运行的任务

**执行后效果**:
- 所有待处理任务被删除
- 所有运行中任务被撤销
- Worker 重启后不会自动执行任务

---

### 方案2: 使用 Celery 命令行工具

**适用场景**: 临时清理，无需编写脚本

```bash
# 1. 清空所有队列
celery -A app.core.celery_app purge

# 2. 查看当前队列状态
celery -A app.core.celery_app inspect active_queues

# 3. 查看正在运行的任务
celery -A app.core.celery_app inspect active

# 4. 撤销特定任务
celery -A app.core.celery_app control revoke <task_id> --terminate

# 5. 撤销所有任务
celery -A app.core.celery_app control revoke $(celery -A app.core.celery_app inspect active | grep -oP "'id': '\K[^']+") --terminate
```

---

### 方案3: 临时禁用任务持久化（不推荐）⚠️

**适用场景**: 测试环境，不关心任务丢失

#### 步骤1: 修改配置

编辑 `backend/app/core/celery_app.py`:

```python
celery_app.conf.update(
    # ... 其他配置 ...
    
    # ❌ 临时禁用任务持久化
    task_acks_late=False,              # 改为 False
    task_reject_on_worker_lost=False,  # 改为 False
    
    # ... 其他配置 ...
)
```

#### 步骤2: 重启 Worker

```bash
# 停止 Worker
pkill -f "celery worker"

# 清空队列
cd backend
uv run python scripts/clear_celery_queue.py

# 重新启动 Worker
make dev  # 或你的启动命令
```

#### ⚠️ 注意事项

- **任务会丢失**: Worker 崩溃时,正在执行的任务直接丢失
- **不适合生产**: 违背了可靠性保证原则
- **测试完恢复**: 记得改回原配置

## 🎯 推荐操作流程

### 日常开发场景

```bash
# 1. 停止 Celery Worker
pkill -f "celery worker"

# 2. 清空队列
cd backend
uv run python scripts/clear_celery_queue.py

# 3. 重启 Worker
make dev
```

### 紧急情况（Worker 无响应）

```bash
# 1. 强制杀死所有 Worker 进程
pkill -9 -f "celery worker"

# 2. 清空 Redis 中的所有 Celery 数据
redis-cli FLUSHDB  # ⚠️ 慎用,会清空整个数据库

# 3. 重启服务
make dev
```

## 🔍 验证清理结果

```bash
# 1. 检查 Redis 中的队列键
redis-cli KEYS "celery*"
# 应该返回空或很少的键

# 2. 检查 Celery Worker 状态
celery -A app.core.celery_app inspect active
# 应该显示没有正在运行的任务

# 3. 检查队列长度
celery -A app.core.celery_app inspect stats
# 查看 total 字段,应该为 0
```

## 📊 配置对比表

| 配置 | 默认值(生产) | 测试值(可选) | 影响 |
|------|-------------|-------------|------|
| `task_acks_late` | `True` | `False` | True=任务完成后确认,False=接收时确认 |
| `task_reject_on_worker_lost` | `True` | `False` | True=Worker崩溃时重新入队,False=任务丢失 |
| `worker_prefetch_multiplier` | `1` | `1` | 预取任务数,1=每次只拿1个 |

## 💡 最佳实践建议

### 开发环境

```bash
# 开发时经常需要重启,建议:
# 1. 每次重启前清空队列
cd backend && uv run python scripts/clear_celery_queue.py

# 2. 或者使用 Makefile 添加清理命令
make clean-celery  # 清空队列后重启
```

### 生产环境

```bash
# 生产环境保持默认配置（任务持久化）
# 如需维护,使用优雅重启:

# 1. 停止接收新任务
celery -A app.core.celery_app control shutdown

# 2. 等待当前任务完成（或设置超时）
sleep 60

# 3. 重启 Worker
celery -A app.core.celery_app worker --loglevel=info
```
