# Mock路线图测试功能开发完成

## 需求背景

用户希望在测试内容生成功能时，能够：
1. **路线图生成阶段**：使用真实的用户请求进行测试（验证意图分析、课程设计、验证等逻辑）
2. **内容生成阶段**：使用简化的Mock路线图数据（加快测试速度，便于验证内容生成逻辑）

## 实现方案

### 核心思路
在路线图生成工作流即将进入内容生成阶段时，动态替换数据库中的路线图`curriculum`字段为简化的Mock数据。

### 工作流时机
```
意图分析 → 课程设计 → 验证 → 审核批准 
                                 ↓
                        [🔧 Mock数据替换]
                                 ↓
                           内容生成 → 完成
```

## 代码改动

### 1. 新增Mock数据替换函数
```python
async def replace_roadmap_with_mock(roadmap_id: str):
    """用Mock数据替换路线图的curriculum字段"""
    async with async_session_maker() as session:
        roadmap_crud = get_roadmap_crud()
        roadmap = await roadmap_crud.get_by_roadmap_id(session, roadmap_id)
        
        # 替换curriculum字段
        roadmap.curriculum = MOCK_ROADMAP_FRAMEWORK
        roadmap.total_estimated_hours = MOCK_ROADMAP_FRAMEWORK["total_estimated_hours"]
        roadmap.recommended_completion_weeks = MOCK_ROADMAP_FRAMEWORK["recommended_completion_weeks"]
        
        await session.commit()
```

### 2. 增强轮询逻辑
在`poll_task_status`函数中添加检测逻辑：
```python
# 检测到即将进入或已进入content_generation阶段
if use_mock_roadmap and not mock_replaced:
    if current_step in ["human_review_approved", "content_generation"]:
        roadmap_id = task_data.get("roadmap_id")
        if roadmap_id:
            success = await replace_roadmap_with_mock(roadmap_id)
            if success:
                mock_replaced = True
```

### 3. 新增命令行参数
```bash
# --mock-roadmap: 启用Mock路线图模式
# --no-cleanup: 测试完成后不清理数据
```

## 使用方法

### 完整测试（真实路线图 + 真实内容）
```bash
cd backend
uv run python scripts/test_roadmap_generation.py
```

### Mock路线图测试（真实路线图生成 + Mock内容生成）
```bash
cd backend
uv run python scripts/test_roadmap_generation.py --mock-roadmap
```

### 保留测试数据
```bash
cd backend
uv run python scripts/test_roadmap_generation.py --no-cleanup
```

### Mock模式 + 保留数据
```bash
cd backend
```

## 优势与价值

### 1. 快速验证内容生成逻辑
- Mock数据仅3个概念，生成时间从10-30分钟缩短至1-2分钟
- 便于快速迭代和调试内容生成Agent

### 2. 保留完整流程验证
- 路线图生成阶段仍使用真实数据
- 验证意图分析、课程设计、验证等核心逻辑

### 3. 灵活可控
- 通过命令行参数控制是否启用Mock模式
- 支持保留测试数据供后续查看

### 4. 易于调试
- Mock数据结构简单清晰
- 概念数量少，便于定位问题

## 适用场景

### ✅ 适合使用Mock模式
- 测试内容生成Agent的逻辑
- 测试Tutorial/Quiz生成功能
- 调试内容生成相关的数据库操作
- 快速验证工作流的完整性

### ❌ 不适合使用Mock模式
- 测试真实场景下的性能表现
- 测试复杂路线图的内容生成质量
- 生产环境测试
- 完整的端到端验证
