## 一、重构详情

### 1.1 删除的冗余代码

#### ❌ 删除：过度复杂的 `safe_session()`

**旧实现**（80+ 行）：
- 多层异常捕获（5+ 个 try-except）
- `asyncio.shield()` 保护连接关闭
- 处理 `GeneratorExit`、`IllegalStateChangeError`
- 复杂的连接泄漏防护逻辑

**新实现**（废弃别名，3 行）：
```python
@asynccontextmanager
async def safe_session():
    logger.warning("⚠️ safe_session() 已废弃")
    async with async_session_maker() as session:
        yield session
```

#### ❌ 删除：过度复杂的 `safe_session_with_retry()`

**旧实现**（130+ 行）：
- 自定义重试逻辑（指数退避）
- 连接错误判断
- 复杂的错误处理

**新实现**（废弃别名，3 行）：
```python
@asynccontextmanager
async def safe_session_with_retry(max_retries=3, base_backoff=0.5):
    logger.warning("⚠️ safe_session_with_retry() 已废弃")
    async with async_session_maker() as session:
        yield session
```

**为什么不需要？**
- SQLAlchemy 连接池配置了 `pool_pre_ping=True`
- 连接池会自动重试失效的连接

#### ❌ 删除：事件循环感知的引擎缓存

**旧实现**（170+ 行）：
```python
_engine_cache: dict[int, AsyncEngine] = {}
_engine_lock = asyncio.Lock()

async def get_engine() -> AsyncEngine:
    loop_id = id(asyncio.get_event_loop())
    if loop_id not in _engine_cache:
        _engine_cache[loop_id] = _create_engine()
    return _engine_cache[loop_id]
```

**新实现**（单例模式，1 行）：
```python
engine: AsyncEngine = create_async_engine(...)
```

**为什么不需要？**
- Celery Worker 应该使用专门的 `celery_session.py`
- 不应该在通用 session.py 中处理 Celery 特殊需求

- 📅 建议 30 天内迁移完成
- 🗑️ 60 天后可删除

### 2.2 迁移路径

**最简单的迁移**：
```python

async with safe_session_with_retry() as session:
    ...

# 新代码（只需要改一行）
from app.db.session import async_session_maker
async with async_session_maker.begin() as session:
    ...  # ✅ 自动 commit/rollback
```

## 八、核心原则总结

### ✅ 遵循的原则

1. **KISS 原则**（Keep It Simple, Stupid）
   - 从 1029 行精简到 540 行
   - 依赖 SQLAlchemy 的健壮性

2. **YAGNI 原则**（You Aren't Gonna Need It）
   - 删除了 400+ 行"可能有用"的防御代码
   - 等问题真实出现再解决

3. **信任成熟的库**
   - SQLAlchemy 2.0 已经过数百万项目验证
   - 不重新发明轮子

4. **职责边界清晰**
   - session.py 只负责提供会话
   - 连接泄漏由调用方负责

### ❌ 避免的反模式

1. **过度防御性编程**
   - 删除了 `asyncio.shield()`
   - 删除了多层异常捕获

2. **症状治疗**
   - 不在底层库中修复业务代码的问题
   - 找到根本原因

3. **缺乏信任**
   - 不因为一次生产问题就失去对库的信任
   - 分析问题真正的原因
