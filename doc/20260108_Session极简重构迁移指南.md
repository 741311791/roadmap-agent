## 迁移方法

### 1. 迁移 `safe_session()` → `async_session_maker()`

```python
# ❌ 旧代码
from app.db.session import safe_session

async with safe_session() as session:
    result = await session.execute(query)
    # ⚠️ 需要手动 commit
    await session.commit()

# ✅ 新代码（推荐）
from app.db.session import async_session_maker

# 方法 A: 手动事务管理
async with async_session_maker() as session:
    result = await session.execute(query)
    await session.commit()  # 手动 commit

# 方法 B: 自动事务管理（推荐）
async with async_session_maker.begin() as session:
    result = await session.execute(query)
    # ✅ 自动 commit/rollback
```

### 2. 迁移 `safe_session_with_retry()` → `async_session_maker()`

```python
# ❌ 旧代码
from app.db.session import safe_session_with_retry

async with safe_session_with_retry(max_retries=3) as session:
    result = await session.execute(query)
    await session.commit()

# ✅ 新代码
from app.db.session import async_session_maker

async with async_session_maker.begin() as session:
    result = await session.execute(query)
    # ✅ SQLAlchemy 连接池会自动重试
    # ✅ 自动 commit/rollback
```

**为什么不需要重试？**
- SQLAlchemy 连接池配置了 `pool_pre_ping=True`（连接前健康检查）
- 连接池配置了 `pool_recycle=300`（定期回收连接）
- 连接池会自动重试失效的连接

### 3. 迁移 `AsyncSessionLocal()` → `async_session_maker()`

```python
# ❌ 旧代码
from app.db.session import AsyncSessionLocal

session = AsyncSessionLocal()
try:
    result = await session.execute(query)
    await session.commit()
finally:
    await session.close()

# ✅ 新代码
from app.db.session import async_session_maker

# 方法 A: 上下文管理器（推荐）
async with async_session_maker.begin() as session:
    result = await session.execute(query)
    # ✅ 自动 commit/close

# 方法 B: 手动管理（不推荐）
session = async_session_maker()
try:
    result = await session.execute(query)
    await session.commit()
finally:
    await session.close()
```

### 4. FastAPI 依赖注入（最佳实践）

```python
# ✅ 推荐：使用类型别名
from app.db.session import CurrentSession, CurrentSessionTransaction

# GET 请求（只读）
@router.get("/users/{user_id}")
async def get_user(
    user_id: int,
    session: CurrentSession,  # ✅ 自动注入只读会话
):
    result = await session.execute(select(User).where(User.id == user_id))
    return result.scalar_one_or_none()

# POST 请求（事务）
@router.post("/users")
async def create_user(
    user: UserCreate,
    session: CurrentSessionTransaction,  # ✅ 自动注入事务会话
):
    new_user = User(**user.dict())
    session.add(new_user)
    # ✅ 函数结束时自动 commit
    return new_user
```

## 常见问题

### Q1: 为什么废弃的函数还能用？

**A**: 为了保证向后兼容，避免一次性修改过多文件导致风险。废弃的函数会记录警告日志，提醒开发者迁移。

### Q2: 什么时候会完全删除废弃函数？

**A**: 建议在 30 天内完成迁移，60 天后可以删除废弃函数。

### Q3: 为什么不需要 `safe_session_with_retry()` 的重试机制？

**A**: 
1. SQLAlchemy 连接池配置了 `pool_pre_ping=True`，会在使用前检查连接有效性
2. 连接池会自动重试失效的连接
3. 如果业务逻辑需要重试，应该在业务层实现，而不是在 session 层

### Q4: 如何处理连接泄漏？

**A**: 
1. **不要**在 session.py 中加防御代码
2. **应该**在业务代码中正确使用上下文管理器
3. **应该**通过 Prometheus 监控连接池指标
4. **应该**找到泄漏的根本原因并修复

### Q5: Celery 任务如何使用 session？

**A**: Celery 任务应该使用专门的 `celery_session.py`：

```python
from app.db.celery_session import get_celery_session

@celery_app.task
async def my_task():
    async with get_celery_session() as session:
        ...  # 使用 session
```
