## 一、实施概述

### 设计原则

1. **精简有效**：不追求100%覆盖率，聚焦核心功能
2. **快速反馈**：测试套件可在6分钟内完成
3. **三层架构**：单元测试 → 集成测试 → E2E测试
4. **Mock外部依赖**：LLM、Tavily、S3等外部服务使用Mock

### 测试通过即代表

- ✅ 服务可以正常启动（健康检查）
- ✅ 数据库连接正常（CRUD操作）
- ✅ 认证授权机制正常（JWT、权限控制）
- ✅ 核心业务逻辑正常（路线图查询、概念管理）
- ✅ Schema验证正确（数据模型）

## 三、测试执行指南

```sql
CREATE DATABASE roadmap_test;
```

**运行完整测试**：

## 四、测试架构设计

### 测试金字塔

```
        ┌─────────────┐
        │  E2E Tests  │  ← 4个测试（健康检查）
        │   (Slow)    │
        ├─────────────┤
        │Integration  │  ← 16个测试（认证 + Service）
        │   Tests     │
        ├─────────────┤
        │ Unit Tests  │  ← 10个测试（Schema验证）
        │  (Fast)     │
        └─────────────┘
        
总计：30个核心测试用例
预期执行时间：< 6分钟（完整套件）
```

### Mock策略

```
┌──────────────────────────────────────────┐
│           Application Code                │
├──────────────────────────────────────────┤
│  ✅ Real: FastAPI, SQLAlchemy, Pydantic  │
│  ✅ Real: Database (Test DB)              │
│  ✅ Real: Redis (Test Instance)           │
├──────────────────────────────────────────┤
│  ❌ Mock: LiteLLM (OpenAI, Claude)        │
│  ❌ Mock: Tavily API                      │
│  ❌ Mock: S3/MinIO                        │
│  ❌ Mock: WebSocket Connections           │
└──────────────────────────────────────────┘
```

### 数据隔离策略

- **Session级别隔离**：每个测试使用独立的数据库会话
- **自动清理**：测试结束后自动删除测试数据
- **Fixture管理**：使用pytest fixtures管理测试数据生命周期

## 七、维护指南

### 新增功能时的测试要求

1. **新增API端点**：
   - 必须添加集成测试（`tests/integration/`）
   - 测试至少包含：成功场景、失败场景、权限验证

2. **修改数据模型**：
   - 必须更新单元测试（`tests/unit/test_schemas.py`）
   - 验证必填字段、类型验证、嵌套结构

3. **修改Service逻辑**：
   - 必须更新集成测试（`tests/integration/test_services.py`）
   - 包含正常流程和异常处理

### 测试失败时的处理流程

1. **查看详细错误信息**：
```bash
./scripts/run_tests.sh all  # -v 参数已包含
```

2. **单独运行失败的测试**：
```bash
uv run pytest tests/unit/test_schemas.py::test_name -v
```

3. **检查日志输出**：
```bash
uv run pytest tests/ -v --log-cli-level=DEBUG
```
