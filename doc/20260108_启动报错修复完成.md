## 一、问题概述

启动应用时遇到两类关键错误：
1. **前端 Hydration 错误** - 首页加载时服务器端和客户端渲染不一致
2. **后端 API 验证错误** - 封面图接口返回500错误（状态枚举值不匹配）

---

## 二、修复详情

### 2.1 前端 Hydration 错误修复

**文件**: `frontend-next/components/ui/waitlist-form.tsx`

**问题根源**:
```typescript
// ❌ 错误：初始值为 0，导致服务器端和客户端渲染不一致
const [width, setWidth] = useState(0);
```

服务器端渲染时 `width = 0` → 移动端布局  
客户端 hydration 时 `width = 0` → 立即变成真实宽度 → 桌面端布局  
**结果**: React Hydration Error

**解决方案**:
```typescript
// ✅ 修复：使用 undefined 作为初始值
const [width, setWidth] = useState<number | undefined>(undefined);

// 在客户端 hydration 完成前，默认使用桌面版布局
const isSmallScreen = width !== undefined && width <= SMALL_BREAKPOINT;
```

**影响范围**:
- ✅ 首页 (`/`)
- ✅ 所有使用 `WaitlistForm` 的页面

---

### 2.2 后端封面图 API 修复

**文件**: 
- `backend/app/services/cover_image_service.py`
- `backend/app/api/v1/endpoints/cover_image.py`

**问题根源**: 数据库模型和 API Schema 的状态枚举值不一致

| 层级 | 状态值 |
|------|--------|
| **数据库模型** (`RoadmapCoverImage`) | `pending`, `generating`, `success`, `failed` |
| **API Schema** (`CoverImageStatusResponse`) | `not_started`, `processing`, `completed`, `failed` |

**错误日志**:
```
pydantic_core._pydantic_core.ValidationError: 1 validation error for CoverImageStatusResponse
status
  Input should be 'not_started', 'processing', 'completed' or 'failed' 
  [type=literal_error, input_value='success', input_type=str]
```

**解决方案 - Step 1: 添加状态映射**

`cover_image_service.py`:
```python
# 映射数据库状态到API响应状态
status_mapping = {
    "pending": "not_started",
    "generating": "processing",
    "success": "completed",
    "failed": "failed",
}
api_status = status_mapping.get(cover_image.generation_status, "not_started")
```

**解决方案 - Step 2: 修复 Endpoint 访问方式**

`cover_image.py`:
```python
# ❌ 错误：将 Pydantic 对象当字典访问
cover_image_url=status_info["url"]

# ✅ 修复：使用对象属性访问
cover_image_url=status_info.url
```

**修复的接口**:
1. ✅ `GET /api/v1/roadmap/{roadmap_id}/cover-image` - 获取单个封面图
2. ✅ `POST /api/v1/cover-images/batch-get` - 批量获取封面图

## 七、额外修复：用户路线图接口

### 7.1 问题：RoadmapMetadata 缺少 topic 和 status 字段

**文件**: `backend/app/services/user_service.py`

**问题根源**:
```python
# ❌ 错误：RoadmapMetadata 没有这些属性
topic=roadmap.topic,
status=roadmap.status,
```

**数据模型关系**:
- `RoadmapMetadata`: 存储框架数据（framework_data）
- `RoadmapTask`: 存储任务状态（status, task_id, current_step）

**解决方案**:
```python
# ✅ 从 framework_data 中提取 topic
topic = roadmap.framework_data.get("topic") or roadmap.framework_data.get("title", "").lower()

# ✅ 批量查询关联的任务信息
task_result = await session.execute(
    select(RoadmapTask).where(RoadmapTask.roadmap_id.in_(roadmap_ids))
)
tasks = task_result.scalars().all()
task_dict = {task.roadmap_id: task for task in tasks}

# ✅ 从 task 获取 status 和其他信息
task = task_dict.get(roadmap.roadmap_id)
status = task.status if task else "completed"
```

## 十、Home页面封面图显示修复

### 10.1 问题：封面图不显示 + 401 错误

**现象**:
1. Home 页面封面图无法显示（数据库有数据）
2. 控制台出现 401 错误：`POST /api/v1/cover-images/batch-generate HTTP/1.1 401 Unauthorized`

**问题根源**:

**问题1：前后端状态值不匹配**
```typescript
// ❌ 前端检查的是 'success'
if (data.status === 'success' && data.cover_image_url) {
  return url;
}

// ✅ 但后端返回的是 'completed'
status: Literal["not_started", "processing", "completed", "failed"]
```

**问题2：自动生成封面图触发 401**
- Home 页面会自动触发缺失封面图的生成
- 但 `batch-generate` 接口需要认证
- 如果用户未登录或 token 失效，会返回 401

**解决方案**:

**修复 1：前端兼容两种状态值**

文件: `frontend-next/lib/cover-image.ts`

```typescript
// ✅ 修复：同时兼容 'completed'（新）和 'success'（旧）
if ((data.status === 'completed' || data.status === 'success') && data.cover_image_url) {
  const url = data.cover_image_url;
  coverImageCache.set(roadmapId, url);
  return url;
}

// 批量获取也同样修复
const url = (item.status === 'completed' || item.status === 'success') && item.cover_image_url 
  ? item.cover_image_url 
  : null;
```

**修复 2：401 错误静默处理**（已存在）

```typescript
// ✅ 代码中已经处理了 401 错误
if (response.status === 401) {
  console.warn('[batchGenerateCoverImages] Unauthorized - user not authenticated');
  return {
    triggered: 0,
    skipped: roadmapIds.length,
    roadmap_ids: [],
    message: 'Skipped: user not authenticated'
  };
}
```

- ✅ 401 错误被正确捕获，不影响用户体验
