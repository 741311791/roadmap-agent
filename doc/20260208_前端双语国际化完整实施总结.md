## 技术实现细节

### 1. 浏览器语言检测
```typescript
export function detectBrowserLocale(): Locale {
  if (typeof window === 'undefined') return defaultLocale;
  
  const browserLang = navigator.language.toLowerCase();
  if (browserLang.startsWith('zh')) return 'zh';
  return 'en';
}
```

### 2. 语言优先级
```
1. localStorage.getItem('locale')
   ↓ (不存在)
2. navigator.language检测
   ↓ (zh开头)
3. 'zh'，否则 'en'
```

### 3. 切换流程
```
用户点击切换按钮
   ↓
setLocale(newLocale)
   ↓
动态import翻译文件
   ↓
更新React状态
   ↓
localStorage + Cookie持久化
   ↓
UI即时更新（无需刷新）
```

### 4. 组件使用示例
```typescript
import { useTranslations } from 'next-intl';

export function MyComponent() {
  const t = useTranslations('sectionName');
  
  return (
    <div>
      <h1>{t('title')}</h1>
      <p>{t('description')}</p>
    </div>
  );
}
```

## 关键技术决策

### 为什么选择纯客户端方案？
1. **简化配置**：无需复杂的middleware和路由配置
2. **即时切换**：无需页面刷新，用户体验更好
3. **易于调试**：所有逻辑在客户端，便于开发和调试
4. **性能优秀**：按需加载，无服务端请求

### 为什么不使用URL路径（/en/、/zh/）？
1. **SEO非必需**：当前为应用型网站，不需要搜索引擎索引
2. **用户体验优先**：URL简洁，无需关心语言路径
3. **分享链接统一**：用户分享的链接根据接收者浏览器自动适配语言

## 已知限制

1. **服务端渲染**：当前方案为纯客户端，首屏会有短暂的语言初始化
2. **SEO**：搜索引擎无法索引不同语言版本
3. **邮件链接**：邮件中的链接无法预设语言

如未来需要SEO，可升级为：
- 使用URL路径方案（/en/、/zh/）
- 添加next-intl的middleware
- 配置hreflang标签
