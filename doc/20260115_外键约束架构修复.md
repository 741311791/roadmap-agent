# 外键约束架构修复完成

**修复时间**: 2026-01-15  
**问题类型**: 数据库外键约束导致的时序问题

## 🔍 问题描述

### 报错信息
```
sqlalchemy.dialects.postgresql.asyncpg.IntegrityError: 
insert or update on table "intent_analysis_metadata" violates foreign key constraint 
"intent_analysis_metadata_roadmap_id_fkey"

DETAIL: Key (roadmap_id)=(python-fullstack-engineer-ee94908a) 
is not present in table "roadmap_metadata".
```

### 根本原因

**时序矛盾**：
1. `roadmap_id` 由 `IntentAnalyzerAgent` 在 `intent_analysis` 阶段生成
2. `intent_analysis_metadata` 需要在此阶段保存，引用 `roadmap_id`
3. `roadmap_metadata` 表在后续的 `curriculum_design` 阶段才创建
4. 外键约束要求 `roadmap_metadata` 必须先存在 → **插入失败**

**工作流顺序**：
```
intent_analysis (生成 roadmap_id)
    ↓ 保存 intent_analysis_metadata ❌ 外键约束失败
    ↓
curriculum_design (创建 roadmap_metadata) ← 太晚了
```

## 💡 解决方案

### 方案选择

移除外键约束，由应用层保证数据一致性。

**原因**：
1. ✅ **业务流程正确**：`intent_analysis` → `curriculum_design` 顺序合理
2. ✅ **工作流保证一致性**：LangGraph 保证两个节点顺序执行
3. ✅ **简化数据库操作**：不需要提前创建空记录

**替代方案（已弃用）**：
- ❌ 在 `intent_analysis` 阶段提前创建空的 `roadmap_metadata`
  - 违反业务逻辑（此时还没有框架数据）
  - 需要两次写入（一次创建空记录，一次更新完整数据）

## 🛠️ 实施步骤

### 1. 修改 Model 定义

**文件**: `backend/app/models/database.py`

```python
# 修改前
roadmap_id: str = Field(
    foreign_key="roadmap_metadata.roadmap_id",  # ❌ 外键约束
    index=True,
    description="路线图唯一标识"
)

# 修改后
roadmap_id: str = Field(
    # ⚠️ 不使用外键约束，因为 intent_analysis 在 roadmap_metadata 创建之前执行
    # 应用层通过工作流保证数据一致性
    index=True,  # ✅ 保留索引
    description="路线图唯一标识"
)
```

### 2. 创建数据库迁移

**迁移脚本**: `backend/scripts/execute_migration.py`

```sql
ALTER TABLE intent_analysis_metadata 
DROP CONSTRAINT intent_analysis_metadata_roadmap_id_fkey;
```

### 3. 执行迁移

## 🔒 数据一致性保证

### 应用层保证机制

1. **LangGraph 工作流顺序**：
   - `intent_analysis` → `curriculum_design` 固定顺序
   - 节点间依赖由 Graph 拓扑结构保证

2. **事务原子性**：
   - 如果 `curriculum_design` 失败，整个任务失败
   - 不会留下孤立的 `intent_analysis_metadata` 记录

3. **重试机制**：
   - 重试时复用已有的 `roadmap_id`
   - 幂等性保证数据一致性

### 查询性能保持

- ✅ **保留索引**: `ix_intent_analysis_metadata_roadmap_id`
- ✅ **唯一约束**: `uix_intent_roadmap_id`
- ✅ **Join 性能**: 不受影响

## 📝 总结

### 关键点

1. **外键约束不适合所有场景**：
   - 当关联数据有时序依赖时，外键约束可能成为障碍
   - 应用层工作流可以更灵活地保证一致性

2. **架构设计原则**：
   - 数据库约束用于防止**无意**的数据错误
   - 业务逻辑顺序由**应用层**保证

3. **索引 vs 外键**：
   - 索引：提升查询性能 ✅ 保留
   - 外键：强制引用完整性 ❌ 移除（由应用层保证）
