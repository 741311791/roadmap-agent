## 一、问题背景

在代码审查中发现,部分 API 端点文件直接在文件内定义 Pydantic 模型(请求/响应 Schema),违反了后端架构设计规范:

> **规范要求**: API 目录下的代码的请求响应格式需要统一在 `backend/app/schemas` 目录下定义

### 违规文件清单 (共 6 个文件)

1. `admin/monitoring.py` - 5 个模型
2. `content/concept_status.py` - 2 个模型
3. `content/modification.py` - 1 个模型
4. `content/subgraph.py` - 2 个模型
5. `roadmaps/cover_image.py` - 5 个模型
6. `roadmaps/streaming.py` - 1 个模型

**总计**: 16 个模型需要迁移

## 二、整改方案

### 1. 创建新的 Schema 文件

#### `backend/app/schemas/monitoring.py` (新建)

统一管理 Celery 任务队列监控相关的 Schema:

- `CeleryTaskInfo` - Celery 任务信息
- `CeleryOverview` - 任务队列总览
- `CeleryTaskListResponse` - 任务列表响应
- `CeleryWorkerInfo` - Worker 信息
- `CeleryWorkerListResponse` - Worker 列表响应

### 2. 扩展现有 Schema 文件

#### `backend/app/schemas/content.py`

新增 Concept 状态和内容修改相关 Schema:

- `ConceptStatusResponse` - 单个 Concept 状态
- `RoadmapConceptsStatusResponse` - Roadmap 所有 Concept 状态
- `ModifyContentRequest` - 内容修改请求
- `GenerateSingleConceptRequest` - 单 Concept 生成请求
- `ContentGenerationTaskResponse` - 内容生成任务响应

#### `backend/app/schemas/cover_image.py`

新增封面图相关 Schema:

- `CoverImageResponse` - 封面图响应
- `GenerateCoverImageRequest` - 生成封面图请求
- `BatchGenerateRequest` - 批量生成请求
- `BatchGetCoverImagesRequest` - 批量获取请求
- `BatchCoverImageResponse` - 批量响应

#### `backend/app/schemas/roadmap.py`

新增流式生成相关 Schema:

- `ChatModificationRequest` - 聊天修改请求

## 六、后续规范要求

### 开发规范 (强制)

1. **禁止在端点文件中定义 Pydantic 模型**
2. **所有请求/响应 Schema 必须在 `schemas/` 目录下定义**
3. **新增 Schema 必须在 `schemas/__init__.py` 中导出**

### 文件组织规范

```
backend/app/schemas/
├── common.py          # 通用 Schema (分页、错误等)
├── roadmap.py         # 路线图相关
├── content.py         # 内容相关
├── admin.py           # 管理后台相关
├── monitoring.py      # 监控相关 (新增)
├── cover_image.py     # 封面图相关
└── __init__.py        # 统一导出
```

### 命名规范

| Schema 类型 | 命名规则 | 示例 |
|---|---|---|
| 请求模型 | `{Action}{Resource}Request` | `ModifyContentRequest` |
| 响应模型 | `{Resource}Response` | `ConceptStatusResponse` |
| 列表响应 | `{Resource}ListResponse` | `CeleryTaskListResponse` |
| 批量操作 | `Batch{Action}Request` | `BatchGenerateRequest` |
