# 内容生成 Celery 任务重构方案

**日期**：2026-01-31  
**问题**：当前 `content_generation_tasks.py` 直接循环调用 agent，缺少 LangGraph 的 Fan-Out/Fan-In 架构和断点续传能力  
**目标**：使用 LangGraph 子图重构，实现与主工作流一致的架构

---

## 1. 当前问题

### 当前实现（错误）❌

```python
# app/tasks/content_generation_tasks.py

@celery_app.task

    # 1. 获取 Concepts
    framework, concepts, user_preferences = asyncio.run(

    # 2. ❌ 使用 Celery Chord 手动编排 Fan-Out
```

**问题**：
1. ❌ 直接循环调用 agent，没有使用 LangGraph 的 Fan-Out/Fan-In
2. ❌ 没有 checkpointer，失败后无法断点续传（需要重新生成所有内容）
3. ❌ 没有独立的 thread_id，无法与主工作流隔离
4. ❌ 手动编排并发（Celery Chord），复杂且容易出错
5. ❌ 手动保存结果，代码重复

## 2. 可复用的组件

### 完整可用的子图 ✅

**位置**：`app/core/orchestrator/subgraphs/content_generation.py`

**架构**：
```
外层子图（编排多个 Concept）：
  START → outer_fan_out (外层 Fan-Out)
      ↓ (Send API 创建 N 个子图实例)
  single_concept_subgraph × N (并行执行)
      ↓ (自动 Reduce 汇总)
  final_aggregation (批量更新 Framework)
      ↓
  END

单 Concept 子图（编排单个 Concept 的内容生成）：
  START → inner_fan_out (内层 Fan-Out)
      ↓ (并发生成 3 个内容)
  ├─ generate_tutorial
  ├─ generate_resource
  └─ generate_quiz
      ↓ (自动 Reduce)
  save_metadata (保存元数据)
      ↓
  END
```

**核心函数**：
```python
# 1. 构建子图
def build_content_generation_subgraph(checkpointer=None):
    """构建内容生成子图（支持断点续传）"""
    builder = StateGraph(ContentGenState)
    builder.add_node("outer_fan_out", outer_fan_out)
    builder.add_node("single_concept_subgraph", single_concept_subgraph_wrapper)
    builder.add_node("final_aggregation", final_aggregation)
    # ...
    return builder.compile(checkpointer=checkpointer)  # ← 传入 checkpointer

# 2. 外层 Fan-Out
def outer_fan_out(state) -> Command:
    """为每个 Concept 创建子图实例"""
    sends = [
        Send("single_concept_subgraph", {
            "concept": concept,
            "roadmap_id": roadmap_id,
            # ...
        })
        for concept in state["concepts"]
    ]
    return Command(goto=sends)

# 3. 单 Concept 子图包装器
async def single_concept_subgraph_wrapper(state, config):
    """执行单 Concept 子图（内层 Fan-Out/Fan-In）"""
    subgraph = build_single_concept_subgraph()
    result = await subgraph.ainvoke(state, config)
    return {"concept_results": [result]}  # Reducer 自动累加

# 4. 最终汇总
async def final_aggregation(state, config):
    """批量更新 Framework 和 Task 状态"""
    handler = ContentHandler(state_manager=ctx.state_manager)
    await handler.update_framework_batch(...)
    await handler.update_task_final_status(...)
    return {"all_concepts_saved": True}
```

## 3. 重构实现

### 步骤1：创建子图执行函数

**新增函数**（在 `content_generation_tasks.py` 中）：

```python
async def _execute_content_generation_subgraph(
    task_id: str,
    roadmap_id: str,
    concepts: list[Concept],
    user_preferences: LearningPreferences,
) -> Dict[str, Any]:
    """
    执行内容生成子图（LangGraph 版本）
    
    架构：
    - 使用 build_content_generation_subgraph() 构建子图
    - 传入 child_checkpointer 支持断点续传
    - 使用独立的 thread_id: {task_id}:content
    - LangGraph 自动管理 Fan-Out/Fan-In
    
    Args:
        task_id: 任务 ID
        roadmap_id: 路线图 ID
        concepts: Concept 列表（已经过测试模式截断）
        user_preferences: 用户偏好
        
    Returns:
        执行结果
    """
    from app.core.orchestrator_factory import OrchestratorFactory
    from app.core.orchestrator.runtime_context import RuntimeContext
    from app.core.orchestrator.subgraphs.content_generation import build_content_generation_subgraph
    
    # 1. 获取 child_checkpointer（复用 OrchestratorFactory）
    child_checkpointer = OrchestratorFactory.get_child_checkpointer()
    
    # 2. 创建 RuntimeContext（复用现有依赖）
    context = RuntimeContext(
        agent_factory=OrchestratorFactory.get_agent_factory(),
        notification_service=notification_service,
        execution_logger=execution_logger,
        state_manager=OrchestratorFactory.get_state_manager(),
        child_checkpointer=child_checkpointer,
    )
    
    logger.info(
        "langgraph_subgraph_execution_starting",
        task_id=task_id,
        roadmap_id=roadmap_id,
        total_concepts=len(concepts),
        has_checkpointer=True,
        architecture="dual_checkpointer",
    )
    
    # 3. 构建子图（传入 checkpointer）
    subgraph = build_content_generation_subgraph(checkpointer=child_checkpointer)
    
    # 4. 准备子图输入状态
    sub_state = {
        "roadmap_id": roadmap_id,
        "concepts": concepts,
        "user_preferences": user_preferences,
        "task_id": task_id,
        "concept": None,  # 用于 Send API
        "concept_results": [],  # Reducer 自动累加
    }
    
    # 5. 调用子图（关键：使用独立的 thread_id）
    child_config = {
        "configurable": {
            "thread_id": f"{task_id}:content",  # ← 独立的 thread_id
            "runtime_context": context,
        }
    }
    
    # 6. 执行子图（LangGraph 自动断点续传）
    result = await subgraph.ainvoke(sub_state, child_config)
    
    # 7. 统计结果
    concept_results = result.get("concept_results", [])
    successful_count = len([
        r for r in concept_results
        if r.get("save_status", {}).get("metadata_saved", False)
    ])
    failed_count = len(concept_results) - successful_count
    
    logger.info(
        "langgraph_subgraph_execution_completed",
        task_id=task_id,
        roadmap_id=roadmap_id,
        total_concepts=len(concept_results),
        successful_count=successful_count,
        failed_count=failed_count,
    )
    
    return {
        "status": "completed" if failed_count == 0 else "partial_failure",
        "total_concepts": len(concept_results),
        "successful_count": successful_count,
        "failed_count": failed_count,
        "concept_results": concept_results,
    }
```

### 步骤2：简化协调任务

**修改 `generate_all_content_task`**：

```python
@celery_app.task(
    name="generate_all_content",
    bind=True,
    queue="content_generation",
)
def generate_all_content_task(
    self,
    roadmap_id: str,
    task_id: str,
    user_id: str,
) -> Dict[str, Any]:
    """
    生成所有内容的协调任务（LangGraph 子图版本）
    
    架构改进：
    - ✅ 使用 LangGraph 子图替代 Celery Chord
    - ✅ 支持 Fan-Out/Fan-In 并行架构
    - ✅ 支持断点续传（通过 checkpointer）
    - ✅ 使用独立的 thread_id（{task_id}:content）
    
    职责：
    1. 获取 Framework 和 Concepts（含测试模式截断）
    2. 调用 LangGraph 子图执行内容生成
    3. 子图内部自动 Fan-Out/Fan-In 和保存结果
    
    Args:
        roadmap_id: 路线图 ID
        task_id: 主任务 ID
        user_id: 用户 ID
        
    Returns:
        执行结果
    """
    logger.info(
        "content_generation_coordinator_started_langgraph",
        task_id=task_id,
        roadmap_id=roadmap_id,
        celery_task_id=self.request.id,
        architecture="langgraph_subgraph",
    )
    
    try:
        import asyncio
        
        # 1. 获取 Framework 和 Concepts（含测试模式截断）
        framework, concepts, user_preferences = asyncio.run(
            _get_framework_and_concepts(roadmap_id, user_id)
        )
        
        if not concepts:
            logger.warning(
                "no_concepts_to_generate",
                task_id=task_id,
                roadmap_id=roadmap_id,
            )
            return {
                "status": "completed",
                "total_concepts": 0,
                "message": "无内容需要生成",
            }
        
        # 2. 执行 LangGraph 子图（替代 Celery Chord）
        result = asyncio.run(
            _execute_content_generation_subgraph(
                task_id=task_id,
                roadmap_id=roadmap_id,
                concepts=concepts,
                user_preferences=user_preferences,
            )
        )
        
        logger.info(
            "content_generation_coordinator_completed_langgraph",
            task_id=task_id,
            roadmap_id=roadmap_id,
            result=result,
        )
        
        return result
        
    except Exception as e:
        logger.error(
            "content_generation_coordinator_failed",
            task_id=task_id,
            roadmap_id=roadmap_id,
            error=str(e),
            exc_info=True,
        )
        raise
```

## 4. 架构对比

### 旧架构（Celery Chord）❌

```
generate_all_content_task (Celery 主任务)
    ↓
Celery Chord (手动编排 Fan-Out)
    ↓
generate_concept_content_task × N (Celery 子任务)
    ├─ 直接调用 tutorial_agent.generate()
    ├─ 直接调用 resource_agent.generate()
    └─ 直接调用 quiz_agent.generate()
    ↓
finalize_content_generation (Callback)
    └─ 手动更新 Framework 和 Task 状态

问题：
- ❌ 没有 checkpointer，失败后必须重新生成所有内容
- ❌ 手动编排，代码复杂
- ❌ 手动保存，容易出错
```

### 新架构（LangGraph 子图）✅

```
generate_all_content_task (Celery 入口)
    ↓ (获取 Concepts，含测试模式截断)
_execute_content_generation_subgraph (调用 LangGraph 子图)
    ↓
LangGraph 子图（自动编排 Fan-Out/Fan-In）
    ├─ outer_fan_out (外层 Fan-Out)
    │   ↓ (Send API 创建 N 个子图实例)
    ├─ single_concept_subgraph × N (并行执行)
    │   ├─ inner_fan_out (内层 Fan-Out)
    │   ├─ Tutorial、Resource、Quiz 并发生成
    │   └─ save_metadata (自动保存)
    │   ↓ (自动 Reduce)
    └─ final_aggregation (批量更新 Framework)

优势：
- ✅ Checkpointer 记录进度，支持断点续传
- ✅ LangGraph 自动编排，代码简洁
- ✅ Handler 自动保存，无需手动编写
- ✅ 独立的 thread_id: {task_id}:content
- ✅ 与主工作流架构一致
```

## 5. 断点续传机制

### Thread ID 隔离

```
主工作流：{task_id}
    ├─ intent_analysis
    ├─ curriculum_design
    ├─ structure_validation
    └─ human_review → END

内容生成子图：{task_id}:content  ← 独立的 thread_id
    ├─ outer_fan_out
    ├─ single_concept_subgraph (concept_1) ✅ 已完成
    ├─ single_concept_subgraph (concept_2) ❌ 失败
    ├─ single_concept_subgraph (concept_3) ⏸️  待执行
    └─ final_aggregation
```

### 断点续传示例

```python
# 第一次执行（某些 Concept 失败）
result = await subgraph.ainvoke(
    state={...},
    config={"configurable": {"thread_id": f"{task_id}:content"}}
)
# 结果：concept_1 成功，concept_2 失败，concept_3 未执行

# 第二次执行（重试）

    state={...},  # 相同的输入
    config={"configurable": {"thread_id": f"{task_id}:content"}}  # 相同的 thread_id
)
# LangGraph 自动：
# - ✅ 跳过 concept_1（已完成，从 checkpoint 加载）
# - ✅ 重试 concept_2（失败，重新执行）
# - ✅ 执行 concept_3（未执行，首次执行）
```

```python
# app/core/orchestrator/nodes/human_review.py 或 app/services/shared/cache_service.py

async def _cache_content_generation_data(
    task_id: str,
    roadmap_id: str,
    state: RoadmapState,
) -> None:
    """
    缓存内容生成所需的数据到 Redis
    
    职责：
    1. 从 state 提取 framework 和 intent_analysis
    2. 预提取 Concepts（扁平化列表）
    3. 提取用户约束（full_analysis_data）
    4. 写入 Redis（TTL: 24小时）
    
    Args:
        task_id: 任务 ID
        roadmap_id: 路线图 ID
        state: 主工作流的完整状态
    """
    from app.db.redis_client import redis_client
    from app.models.domain import Concept
    
    # 1. 从 state 提取数据
    framework = state.get("roadmap_framework")
    intent_analysis = state.get("intent_analysis")
    user_request = state.get("user_request")
    
    if not framework:
        logger.error(
            "cache_content_gen_data_missing_framework",
            task_id=task_id,
            roadmap_id=roadmap_id,
        )
        raise ValueError("framework 不存在，无法缓存")
    
    # 2. 预提取 Concepts（扁平化列表）
    concepts = []
    for stage in framework.stages:
        for module in stage.modules:
            for concept in module.concepts:
                concepts.append(concept)
    
    # 3. 提取用户约束
    user_constraints = {}
    if intent_analysis and intent_analysis.full_analysis_data:
        user_constraints = intent_analysis.full_analysis_data
    
    # 4. 构建缓存数据
    cache_data = {
        "roadmap_id": roadmap_id,
        "task_id": task_id,
        "user_id": user_request.user_id if user_request else None,
        
        # 完整的 framework（包含 Pydantic 模型）
        "framework": framework.model_dump(),
        
        # 预提取的 Concepts（扁平化列表）
        "concepts": [c.model_dump() for c in concepts],
        
        # 用户约束（来自 IntentAnalysis）
        "user_constraints": user_constraints,
        
        # 元数据
        "cached_at": datetime.utcnow().isoformat(),
        "version": "v1",
    }
    
    # 5. 写入 Redis（TTL: 24小时）
    key = f"content_gen_cache:{task_id}"
    await redis_client.set_json(
        key=key,
        value=cache_data,
        ex=86400,  # 24小时过期
    )
    
    logger.info(
        "content_gen_data_cached",
        task_id=task_id,
        roadmap_id=roadmap_id,
        redis_key=key,
        total_concepts=len(concepts),
        cache_size_kb=len(str(cache_data)) / 1024,
        ttl_hours=24,
    )
```

### 8.4 缓存读取策略

#### 读取优先级

```python
async def _get_framework_and_concepts_optimized(
    roadmap_id: str,
    task_id: str,
    user_id: str,
) -> tuple[RoadmapFramework, list[Concept], dict]:
    """
    获取 Framework 和 Concepts（优化版 - 优先从 Redis 读取）
    
    读取策略：
    1. 优先从 Redis 读取（快速）
    2. 如果 Redis 不存在，从数据库读取（兜底）
    
    Returns:
        (framework, concepts, user_constraints)
    """
    from app.db.redis_client import redis_client
    from app.models.domain import RoadmapFramework, Concept
    
    # ============ 优先级1：从 Redis 读取 ============
    redis_key = f"content_gen_cache:{task_id}"
    cache_data = await redis_client.get_json(redis_key)
    
    if cache_data:
        logger.info(
            "content_gen_cache_hit",
            task_id=task_id,
            roadmap_id=roadmap_id,
            redis_key=redis_key,
            total_concepts=len(cache_data["concepts"]),
            cached_at=cache_data.get("cached_at"),
        )
        
        # 反序列化 Pydantic 模型
        framework = RoadmapFramework(**cache_data["framework"])
        concepts = [Concept(**c) for c in cache_data["concepts"]]
        user_constraints = cache_data["user_constraints"]
        
        # ✅ 测试模式截断（在缓存数据上应用）
        if settings.TEST_MODE_TRUNCATE_FRAMEWORK:
            framework, concepts = _apply_test_mode_truncation(
                framework, concepts, task_id
            )
        
        return framework, concepts, user_constraints
    
    # ============ 优先级2：从数据库读取（兜底） ============
    logger.warning(
        "content_gen_cache_miss_fallback_to_db",
        task_id=task_id,
        roadmap_id=roadmap_id,
        redis_key=redis_key,
    )
    
    # 使用原有的数据库查询逻辑
    async with get_celery_session() as session:
        # 查询 RoadmapMetadata
        roadmap_crud = get_roadmap_crud()
        roadmap_metadata = await roadmap_crud.get_by_roadmap_id(session, roadmap_id)
        
        if not roadmap_metadata:
            raise ValueError(f"路线图 {roadmap_id} 不存在")
        
        # 解析 Framework
        framework = RoadmapFramework(**roadmap_metadata.framework_data)
        
        # 提取 Concepts
        concepts = []
        for stage in framework.stages:
            for module in stage.modules:
                concepts.extend(module.concepts)
        
        # 获取用户约束
        intent_crud = get_intent_analysis_crud()
        intent = await intent_crud.get_by_roadmap_id(session, roadmap_id)
        user_constraints = intent.full_analysis_data if intent else {}
        
        # ✅ 测试模式截断
        if settings.TEST_MODE_TRUNCATE_FRAMEWORK:
            framework, concepts = _apply_test_mode_truncation(
                framework, concepts, task_id
            )
        
        return framework, concepts, user_constraints
```

#### 测试模式截断函数（复用）

```python
def _apply_test_mode_truncation(
    framework: RoadmapFramework,
    concepts: list[Concept],
    task_id: str,
) -> tuple[RoadmapFramework, list[Concept]]:
    """
    应用测试模式截断（统一的截断逻辑）
    
    只保留第一个 Stage 的第一个 Module 的所有 Concepts
    
    Args:
        framework: 原始框架
        concepts: 原始 Concepts 列表
        task_id: 任务 ID
        
    Returns:
        (截断后的 framework, 截断后的 concepts)
    """
    logger.warning(
        "test_mode_truncate_framework_enabled",
        task_id=task_id,
        original_stages=len(framework.stages),
        original_modules=sum(len(s.modules) for s in framework.stages),
        original_concepts=len(concepts),
    )
    
    # 深拷贝避免修改原始对象
    from copy import deepcopy
    framework = deepcopy(framework)
    
    # 只保留第一个 Stage 的第一个 Module
    if framework.stages:
        first_stage = framework.stages[0]
        if first_stage.modules:
            first_module = first_stage.modules[0]
            first_stage.modules = [first_module]
        framework.stages = [first_stage]
    
    # 重新提取 Concepts
    truncated_concepts = []
    for stage in framework.stages:
        for module in stage.modules:
            truncated_concepts.extend(module.concepts)
    
    logger.info(
        "test_mode_framework_truncated",
        task_id=task_id,
        truncated_stages=len(framework.stages),
        truncated_modules=sum(len(s.modules) for s in framework.stages),
        truncated_concepts=len(truncated_concepts),
    )
    
    return framework, truncated_concepts
```

### 8.5 缓存一致性和边缘情况

#### 场景1：缓存失效

**问题**：Redis 宕机或缓存过期

**方案**：Fallback 到数据库查询

```python
async def _get_framework_and_concepts_optimized(...):

        cache_data = await redis_client.get_json(key)

        logger.warning(
            "redis_cache_read_failed_fallback_to_db",
            task_id=task_id,
            error=str(e),
        )
    
    # Fallback: 从数据库读取
    return await _query_from_database(roadmap_id, user_id)
```

#### 场景2：Framework 在缓存后被编辑

**问题**：用户在 human_review 批准后、内容生成前，又手动编辑了 Framework

**影响**：
- 缓存的 Framework 可能已过时
- 内容生成使用的是旧版本 Framework

**方案**：
1. **短 TTL**：设置较短的过期时间（如 1 小时）
2. **版本检查**：缓存时记录 `framework_version`，读取时对比
3. **接受过时**：内容生成使用审核时的版本（符合预期）

**推荐方案3**：接受这个行为，因为：
- ✅ 用户审核的是特定版本的 Framework
- ✅ 内容生成应该基于审核时的版本
- ✅ 如果 Framework 被编辑，用户可以重新触发内容生成

#### 场景3：缓存写入失败

**问题**：Redis 写入失败，但 Celery 任务已触发

**方案**：Celery 任务会 Fallback 到数据库查询

```python
async def _cache_content_generation_data(...):
    try:
        await redis_client.set_json(key, data, ex=86400)
        logger.info("content_gen_data_cached", ...)
    except Exception as e:
        # ⚠️ 不抛出异常，只记录警告

        logger.warning(
            "content_gen_cache_write_failed_task_will_fallback",
            task_id=task_id,
            error=str(e),
        )
```

#### 场景4：测试模式截断的时机

**问题**：测试模式截断应该在缓存写入前还是读取后应用？

**方案对比**：

| 方案 | 截断时机 | 优点 | 缺点 |
|-----|---------|-----|-----|
| **A. 写入前截断** | 缓存时应用 | Redis 数据更小 | 缓存不可复用（无法关闭测试模式后复用） |
| **B. 读取后截断** | 读取时应用 | 缓存可复用 | Redis 存储完整数据 |

**推荐方案B**：读取后截断

```python
async def _get_framework_and_concepts_optimized(...):
    # 1. 从 Redis 读取完整数据
    cache_data = await redis_client.get_json(key)
    framework = RoadmapFramework(**cache_data["framework"])
    concepts = [Concept(**c) for c in cache_data["concepts"]]
    
    # 2. 应用测试模式截断（在读取后）
    if settings.TEST_MODE_TRUNCATE_FRAMEWORK:
        framework, concepts = _apply_test_mode_truncation(framework, concepts, task_id)
    
    return framework, concepts, user_constraints
```

**理由**：
- ✅ 缓存的是完整数据，可以在测试模式开关变化后复用
- ✅ 测试模式只影响读取，不影响缓存
- ✅ 更灵活（可以动态调整截断策略）
