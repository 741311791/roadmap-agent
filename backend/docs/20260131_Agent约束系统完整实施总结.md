## 二、技术架构

### 约束数据流

```
用户请求
  ↓
IntentAnalyzerAgent
  ↓ _generate_constraints()
约束文本字典 (12个)
  ↓
IntentAnalysisOutput.full_analysis_data
  ↓
数据库 IntentAnalysisMetadata
  ↓
RuntimeContext.get_user_constraints()
  ↓ 缓存命中
RuntimeContext._constraints_cache
  ↓
各 Agent._load_user_constraints()
  ↓ _filter_constraints()
过滤后的约束 (3-8个)
  ↓
BaseAgent._load_system_prompt(user_constraints=...)
  ↓ Jinja2 渲染
Prompt 包含用户画像约束
  ↓
LLM 生成个性化内容
```

### 约束系统三层架构

**Layer 1: 约束生成层**（IntentAnalyzerAgent）
- 从用户画像数据生成约束文本
- 12 个约束覆盖所有个性化维度
- 格式：`{"约束名称": "约束内容"}`

**Layer 2: 约束管理层**（BaseAgent + RuntimeContext）
- BaseAgent 提供约束过滤和加载接口
- RuntimeContext 提供约束缓存和共享机制
- 支持多种加载方式（内存/数据库/缓存）

**Layer 3: 约束应用层**（各 Agent + Prompt 模板）
- 各 Agent 定义约束需求
- Prompt 模板自动注入约束
- LLM 基于约束生成内容

## 四、使用指南

### 方式 1：在工作流节点中使用（推荐）

```python
async def my_node(state: RoadmapState, config: RunnableConfig) -> dict:
    ctx: RuntimeContext = config["configurable"]["runtime_context"]
    
    # 获取约束（带缓存）
    user_constraints = await ctx.get_user_constraints(
        roadmap_id=state["roadmap_id"],
        intent_analysis=state.get("intent_analysis")
    )
    
    # 创建 Agent
    agent = ctx.agent_factory.create_my_agent()
    
    # Agent 内部会自动使用约束
    result = await agent.execute(...)
    
    return {"result": result}
```

### 方式 2：在 Agent 内部使用

```python
class MyAgent(BaseAgent):
    def _get_required_constraints(self) -> list[str]:
        """定义需要的约束"""
        from app.models.domain import ConstraintNames
        return [
            ConstraintNames.LANGUAGE,
            ConstraintNames.USER_GOAL,
            ConstraintNames.USER_PROFILE,
            ConstraintNames.DIFFICULTY,  # 根据需要添加
        ]
    
    async def execute(self, input_data, roadmap_id: str = None):
        # 加载约束
        user_constraints = await self._load_user_constraints(
            roadmap_id=roadmap_id
        )
        
        # 加载 Prompt（自动注入约束）
        prompt = self._load_system_prompt(
            "my_agent.j2",
            user_constraints=user_constraints,
            # ... 其他模板变量
        )
        
        # 调用 LLM
        result = await self._call_llm(...)
        return result
```

## 十四、注意事项

### 1. Prompt 长度管理

**约束注入会增加 Prompt 长度**：
- 每个约束约 50-100 字符
- 12 个约束约 600-1200 字符（~150-300 tokens）
- 过滤后的约束（3-8 个）约 150-800 字符（~40-200 tokens）

**建议**：
- 监控 Prompt 总长度，确保不超过模型限制
- 如需优化，可实现约束优先级系统

### 2. 数据库迁移注意

**迁移前**：
- 备份数据库（重要！）
- 在开发环境先测试迁移

**迁移后**：
- 验证数据转换是否正确
- 检查是否有遗漏的记录

### 3. 向后兼容性

**已有保障**：
- 约束为空时，Jinja2 模板不渲染约束区域
- BaseAgent 的约束方法返回空字典时不影响正常运行
- 旧的 Agent 调用方式仍然有效
