# 内容生成Celery序列化错误修复

**日期**: 2026-02-08  
**问题**: Celery任务失败 - `Object of type Concept is not JSON serializable`  
**影响**: 内容生成任务无法完成，导致路线图内容缺失

---

## 一、问题现象

### 错误日志

```
kombu.exceptions.EncodeError: Object of type Concept is not JSON serializable
TypeError: Object of type Concept is not JSON serializable

Traceback:
  File "celery/backends/base.py", line 512, in encode
    _, _, payload = self._encode(data)
  File "celery/backends/base.py", line 516, in _encode
    return dumps(data, serializer=self.serializer)
```

### 关联错误

同时发现了3个相关问题：
1. **工具加载失败**: `'dict' object has no attribute 'schema'`
2. **JSON解析失败**: `JSONDecodeError: Expecting value: line 1 column 1 (char 0)`
3. **Celery序列化失败**: `Object of type Concept is not JSON serializable`

---

## 二、根本原因分析

### 问题1：工具加载失败

**文件**: `app/agents/tutorial_generator.py` 第108行

**原因**: 
- `langchain-mcp-adapters` 返回的工具，`args_schema` 可能已经是字典
- 代码假设它是 Pydantic 模型，直接调用 `.schema()` 导致失败

**影响**:
- Context7工具无法加载
- Agent在没有工具的情况下运行
- LLM可能返回非预期格式的内容

### 问题2：JSON解析失败

**文件**: `app/agents/tutorial_generator.py` 第501行

**原因**:
- LLM在ReAct模式下返回内容包含思考过程（`Thought: ...`）
- `_parse_output` 方法无法处理这种格式
- 去除代码块标记后变成空字符串

**表现**:
```python
content = "Thought: 这是我的思考过程..."  # LLM返回的内容
json_content = content.strip()  # 去除```后无法找到JSON
json.loads(json_content)  # 抛出 JSONDecodeError
```

### 问题3：Celery序列化失败

**文件**: `app/core/orchestrator/subgraphs/content_generation.py` 第154行

**原因**:
- 返回的 `concept_results` 包含完整的 `SingleConceptState`
- `SingleConceptState` 中包含 `concept: Concept` 字段
- `Concept` 是 Pydantic 模型，Celery 无法直接序列化

**代码问题**:
```python
# ❌ 错误：返回完整的 state（包含Concept对象）
return {
    "concept_results": [result],  # result 是完整的 SingleConceptState
}
```

---

## 三、修复方案

### 修复1：兼容多种工具schema格式

**文件**: `app/agents/tutorial_generator.py`  
**行号**: 102-113

```python
# 获取参数schema（兼容多种格式）
if hasattr(tool, 'args_schema') and tool.args_schema:
    # 如果是Pydantic模型，调用schema()
    if hasattr(tool.args_schema, 'schema'):
        parameters = tool.args_schema.schema()
    # 如果已经是字典，直接使用
    elif isinstance(tool.args_schema, dict):
        parameters = tool.args_schema
    else:
        parameters = {"type": "object", "properties": {}}
else:
    parameters = {"type": "object", "properties": {}}
```

**效果**:
- ✅ 支持 Pydantic 模型
- ✅ 支持字典格式
- ✅ 向后兼容

### 修复2：处理ReAct思考过程前缀

**文件**: `app/agents/tutorial_generator.py`  
**行号**: 500-530

```python
# 去除可能的ReAct思考过程前缀
json_content = content.strip()

# 如果内容以"Thought:"开头，提取JSON部分
if json_content.startswith("Thought:"):
    json_start = json_content.find("{")
    if json_start != -1:
        json_content = json_content[json_start:]
        logger.info(
            "tutorial_react_thought_stripped",
            concept_id=concept.concept_id,
            message="Removed ReAct thought prefix, extracted JSON"
        )
    else:
        raise ValueError("LLM returned ReAct thought but no JSON object found")

# 验证不为空
if not json_content:
    raise ValueError("JSON content is empty after preprocessing")
```

**效果**:
- ✅ 自动识别并去除 `Thought:` 前缀
- ✅ 提取实际的JSON内容
- ✅ 增加空值校验

### 修复3：只返回可序列化的字段

**文件**: `app/core/orchestrator/subgraphs/content_generation.py`  
**行号**: 153-158

```python
# ❌ 修复前：返回完整state（包含Concept对象）
return {
    "concept_results": [result],  # result包含Concept对象
}

# ✅ 修复后：只返回可序列化字段
serializable_result = {
    "concept_id": concept.concept_id,
    "save_status": result.get("save_status", {}),
    "concept_name": concept.name,  # 只保存名称，不保存完整对象
}

return {
    "concept_results": [serializable_result],
}
```

**效果**:
- ✅ Celery可以成功序列化
- ✅ 保留所有必要信息
- ✅ 减少内存占用

## 四、ReAct最佳实践优化

### 改进：优雅降级而非失败

**问题**: 当ReAct循环达到 `max_iterations` 时，原先会抛出异常导致任务失败

**改进方案**: 强制LLM基于已收集信息生成最终输出

**文件**: `app/agents/base.py`  
**行号**: 433-467

```python
# ❌ 改进前：直接失败
logger.error("react_max_iterations_reached")
raise ValueError(f"ReAct 循环达到最大迭代次数（{max_iterations}）...")

# ✅ 改进后：优雅降级
logger.warning(
    "react_max_iterations_reached_forcing_output",
    message="已达最大迭代次数，强制LLM基于已收集信息生成最终输出"
)

# 添加强制输出指令
conversation.append({
    "role": "system",
    "content": (
        "🚨 重要提示：你已达到最大工具调用次数限制。\n\n"
        "现在你**必须**基于目前已收集的所有信息，立即生成最终输出。\n"
        "不要再尝试调用任何工具，不要说'需要更多信息'。\n"
        "请综合利用你已经获取的文档内容和你的知识，完成教程生成任务。\n\n"
        "即使信息不够完美，也请生成一个质量尽可能高的教程。"
    )
})

# 强制文本输出（禁用工具）
final_response = await self._standard_call(
    messages=conversation,
    tools=None,
)

logger.info("react_forced_completion", message="已强制生成最终输出")
return final_response
```

**验证结果**:
- ✅ 设置 `max_iterations=3` 测试通过
- ✅ 达到上限后成功生成8075字符的教程
- ✅ 任务状态从 `failed` 改为 `success`
