## 🚨 Breaking Change 1: 统一响应格式

### 变更说明

所有API响应都包装在统一的格式中：`{code, msg, data}`

### 旧格式（直接返回数据）

```typescript
// GET /api/v1/roadmaps/{roadmap_id}/concepts/{concept_id}/tutorials
{
  "roadmap_id": "roadmap-123",
  "concept_id": "concept-456",
  "total_versions": 3,
  "tutorials": [...]
}
```

### 新格式（统一包装）

```typescript
// GET /api/v1/roadmaps/{roadmap_id}/concepts/{concept_id}/tutorials
{
  "code": 200,
  "msg": "Success",
  "data": {
    "roadmap_id": "roadmap-123",
    "concept_id": "concept-456",
    "total_versions": 3,
    "tutorials": [...]
  }
}
```

### 前端适配方案

#### 方案 1: 创建统一的API请求封装函数（推荐）

```typescript
// lib/api/client.ts

interface APIResponse<T> {
  code: number;
  msg: string;
  data: T;
}

export async function apiRequest<T>(
  url: string,
  options?: RequestInit
): Promise<T> {
  const response = await fetch(url, {
    ...options,
    headers: {
      'Content-Type': 'application/json',
      ...options?.headers,
    },
  });
  
  const result: APIResponse<T> = await response.json();
  
  // 检查业务状态码
  if (result.code !== 200) {
    throw new Error(result.msg);
  }
  
  return result.data;
}

// 使用示例
const tutorials = await apiRequest<TutorialVersionListResponse>(
  '/api/v1/roadmaps/xxx/concepts/yyy/tutorials'
);
console.log(tutorials.total_versions);  // 直接访问数据
```

#### 方案 2: 逐个修改API调用（不推荐）

```typescript
// 旧代码
const response = await fetch('/api/v1/roadmaps/xxx/concepts/yyy/tutorials');
const data = await response.json();
console.log(data.tutorials);

// 新代码
const response = await fetch('/api/v1/roadmaps/xxx/concepts/yyy/tutorials');
const result = await response.json();
if (result.code === 200) {
  console.log(result.data.tutorials);  // 需要访问 data 属性
} else {
  console.error(result.msg);
}
```

## 🚨 Breaking Change 2: 错误响应格式变化

### 变更说明

错误响应从简单的 `{detail}` 变为结构化的 `{error}` 对象。

### 旧格式（HTTPException）

```typescript
// 404错误
{
  "detail": "路线图不存在"
}

// 500错误
{
  "detail": "Internal server error"
}
```

### 新格式（结构化错误）

```typescript
{
  "error": {
    "code": "NOT_FOUND",
    "message": "路线图不存在",
    "details": null,
    "request_id": "req-abc-123",
    "timestamp": "2026-01-07T10:00:00Z",
    "debug_info": {  // 仅开发环境
      "exception_type": "NotFoundError",
      "traceback": "..."
    }
  }
}
```

### 前端适配方案

```typescript
// lib/api/error-handler.ts

interface APIError {
  code: string;
  message: string;
  details?: any;
  request_id?: string;
  timestamp: string;
  debug_info?: {
    exception_type: string;
    traceback: string;
  };
}

export class APIException extends Error {
  code: string;
  details?: any;
  request_id?: string;
  
  constructor(error: APIError) {
    super(error.message);
    this.code = error.code;
    this.details = error.details;
    this.request_id = error.request_id;
  }
}

export async function apiRequest<T>(
  url: string,
  options?: RequestInit
): Promise<T> {
  const response = await fetch(url, options);
  
  // 检查HTTP状态码
  if (!response.ok) {
    const errorData = await response.json();
    
    // 新格式：{error: {...}}
    if (errorData.error) {
      throw new APIException(errorData.error);
    }
    
    // 兼容旧格式（过渡期）
    if (errorData.detail) {
      throw new Error(errorData.detail);
    }
    
    throw new Error('Unknown error');
  }
  
  // 成功响应：{code, msg, data}
  const result = await response.json();
  return result.data;
}
```

## 🔐 Breaking Change 3: 权限验证加强

### 变更说明

部分端点添加了JWT身份验证，不再接受查询参数中的 `user_id`。

### 受影响的端点

#### 1. DELETE `/api/v1/roadmaps/{roadmap_id}`

**旧接口**:
```typescript
// 需要在查询参数中传递user_id（❌ 易被伪造）
DELETE /api/v1/roadmaps/roadmap-123?user_id=user-456
```

**新接口**:
```typescript
// 从JWT Token中自动提取user_id（✅ 安全）
DELETE /api/v1/roadmaps/roadmap-123
Headers: {
  "Authorization": "Bearer eyJhbGc..."
}
```

**前端适配**:
```typescript
// 旧代码
await fetch(`/api/v1/roadmaps/${roadmapId}?user_id=${userId}`, {
  method: 'DELETE',
});

// 新代码（移除user_id参数）
await fetch(`/api/v1/roadmaps/${roadmapId}`, {
  method: 'DELETE',
  headers: {
    'Authorization': `Bearer ${token}`,  // ✅ JWT自动提取user_id
  },
});
```

#### 2. POST `/api/v1/roadmaps/{roadmap_id}/restore`

**适配方案**: 同上，移除查询参数中的 `user_id`。

#### 3. DELETE `/api/v1/roadmaps/{roadmap_id}/permanent`

**适配方案**: 同上，移除查询参数中的 `user_id`。

## 🔧 前端通用适配代码

### 1. API客户端封装（推荐）

```typescript
// lib/api/client.ts

/**
 * 统一API响应格式
 */
interface APIResponse<T> {
  code: number;
  msg: string;
  data: T;
}

/**
 * 统一错误格式
 */
interface APIError {
  code: string;  // 错误码：NOT_FOUND, BAD_REQUEST等
  message: string;
  details?: any;
  request_id?: string;
  timestamp: string;
}

/**
 * API异常类
 */
export class APIException extends Error {
  code: string;
  details?: any;
  request_id?: string;
  
  constructor(error: APIError) {
    super(error.message);
    this.name = 'APIException';
    this.code = error.code;
    this.details = error.details;
    this.request_id = error.request_id;
  }
  
  isNotFound(): boolean {
    return this.code === 'NOT_FOUND';
  }
  
  isUnauthorized(): boolean {
    return this.code === 'UNAUTHORIZED';
  }
  
  isForbidden(): boolean {
    return this.code === 'FORBIDDEN';
  }
}

/**
 * 统一API请求函数
 */
export async function apiRequest<T>(
  url: string,
  options?: RequestInit
): Promise<T> {
  try {
    const response = await fetch(url, {
      ...options,
      headers: {
        'Content-Type': 'application/json',
        ...options?.headers,
      },
    });
    
    // 处理错误响应
    if (!response.ok) {
      const errorData = await response.json();
      
      // 新格式：{error: {...}}
      if (errorData.error) {
        throw new APIException(errorData.error);
      }
      
      // 兜底处理
      throw new Error(errorData.detail || 'Unknown error');
    }
    
    // 处理成功响应
    const result: APIResponse<T> = await response.json();
    
    // 验证业务状态码
    if (result.code !== 200) {
      throw new Error(result.msg);
    }
    
    return result.data;
    
  } catch (error) {
    if (error instanceof APIException) {
      throw error;
    }
    throw new Error(`API request failed: ${error.message}`);
  }
}

/**
 * GET 请求封装
 */
export async function get<T>(url: string, token?: string): Promise<T> {
  return apiRequest<T>(url, {
    method: 'GET',
    headers: token ? { 'Authorization': `Bearer ${token}` } : {},
  });
}

/**
 * POST 请求封装
 */
export async function post<T>(
  url: string,
  data?: any,
  token?: string
): Promise<T> {
  return apiRequest<T>(url, {
    method: 'POST',
    headers: token ? { 'Authorization': `Bearer ${token}` } : {},
    body: JSON.stringify(data),
  });
}

/**
 * PUT 请求封装
 */
export async function put<T>(
  url: string,
  data?: any,
  token?: string
): Promise<T> {
  return apiRequest<T>(url, {
    method: 'PUT',
    headers: token ? { 'Authorization': `Bearer ${token}` } : {},
    body: JSON.stringify(data),
  });
}

/**
 * DELETE 请求封装
 */
export async function del<T>(url: string, token?: string): Promise<T> {
  return apiRequest<T>(url, {
    method: 'DELETE',
    headers: token ? { 'Authorization': `Bearer ${token}` } : {},
  });
}
```

### 3. 使用示例

```typescript
// 旧代码
const fetchTutorials = async (roadmapId: string, conceptId: string) => {
  const response = await fetch(
    `/api/v1/roadmaps/${roadmapId}/concepts/${conceptId}/tutorials`
  );
  const data = await response.json();
  return data;  // 直接返回
};

// 新代码
import { get } from '@/lib/api/client';
import { TutorialVersionListResponse } from '@/types/api';

const fetchTutorials = async (
  roadmapId: string,
  conceptId: string
): Promise<TutorialVersionListResponse> => {
  return await get<TutorialVersionListResponse>(
    `/api/v1/roadmaps/${roadmapId}/concepts/${conceptId}/tutorials`
  );
};

// 使用
try {
  const tutorials = await fetchTutorials('roadmap-123', 'concept-456');
  console.log(tutorials.total_versions);  // 类型安全
  console.log(tutorials.tutorials[0].title);
} catch (error) {
  if (error instanceof APIException) {
    if (error.isNotFound()) {
      console.log('教程不存在');
    } else {
      console.error(`API错误: ${error.message} (${error.code})`);
    }
  }
}
```

## ⚠️ 风险提示

### 高风险项

1. **所有API调用都会失败**（如果前端未适配）
   - 缓解：使用统一的API客户端，一次修改全局生效
   
2. **权限验证失败**（management端点）
   - 缓解：确保JWT Token正确传递
   
3. **错误处理不完整**
   - 缓解：使用try-catch包装所有API调用

### 测试重点

- ✅ 所有成功响应都能正确提取 `data` 字段
- ✅ 所有错误响应都能正确解析 `error` 对象
- ✅ 管理员端点需要superuser权限
- ✅ 路线图管理端点需要JWT认证
- ✅ 删除操作验证用户权限（不能删除别人的路线图）
