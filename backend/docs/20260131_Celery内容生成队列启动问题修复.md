# Celery 内容生成队列启动问题修复

## 问题描述

启动内容生成 Celery Worker 时遇到 `WorkerLostError` 错误，Worker 进程被 `SIGKILL` 强制终止。

```bash
[2026-01-31 17:06:00,107: ERROR/MainProcess] Process 'ForkPoolWorker-1' pid:36299 exited with 'signal 9 (SIGKILL)'
[2026-01-31 17:06:00,129: CRITICAL/MainProcess] Unrecoverable error: WorkerLostError('Could not start worker processes')
```

## 根本原因

经过日志分析，发现以下问题：

1. **缺少任务模块导入** (`celery_app.py`)
   - `content_generation_tasks` 模块未在 Celery `imports` 配置中声明
   - 导致模块加载失败或循环依赖

2. **缺少队列定义**
   - 使用了 `content_generation` 队列，但未在 Celery 配置中定义
   - 导致队列路由失败

3. **并发度过高 + 连接池资源不足**
   - `concurrency=8` 并发度过高
   - 每个 Worker 进程的连接池 `max_size=10`
   - 总连接数：8 × 10 = 80 个，可能超出数据库最大连接限制
   - 导致 OrchestratorFactory 初始化时内存/连接不足，被系统 SIGKILL

## 修复方案

### 1. 添加任务模块导入

**文件**: `backend/app/core/celery_app.py`

```python
# 自动发现任务模块
imports=(
    "app.tasks.log_tasks",
    "app.tasks.roadmap_generation_tasks",
    "app.tasks.workflow_resume_tasks",
    "app.tasks.cover_image_tasks",
    "app.tasks.maintenance_tasks",
    "app.tasks.content_utils",
    "app.tasks.tavily_cache_tasks",
    "app.tasks.assessment_initialization_tasks",
    "app.tasks.capability_analysis_tasks",
    "app.tasks.content_generation_tasks",  # ✅ 新增
),
```

### 2. 添加队列路由和定义

**文件**: `backend/app/core/celery_app.py`

```python
# 任务路由配置
task_routes={
    "generate_all_content": {"queue": "content_generation"},  # 内容生成任务使用专用队列
},
# 队列定义
task_queues={
    "celery": {"exchange": "celery", "routing_key": "celery"},  # 默认队列
    "content_generation": {"exchange": "content_generation", "routing_key": "content_generation"},  # 内容生成队列
},
```

### 3. 降低并发度

**创建专用启动脚本**: `backend/scripts/start_content_worker_dev.sh`

```bash
#!/bin/bash
# 启动 Celery Content Generation Worker
uv run celery -A app.core.celery_app worker \
    --loglevel=info \
    --concurrency=4 \  # ✅ 从 8 降到 4
    --hostname=content@%h \
    --max-tasks-per-child=100 \
    --queues=content_generation
```

**优化原因**:
- 降低并发度可减少资源竞争
- 避免同时初始化过多连接池

### 4. 降低连接池大小

**文件**: `backend/app/core/orchestrator_factory.py`

```python
# 研发环境：max_size=5（从 10 降到 5）
# 生产环境：max_size=10（从 20 降到 10）
langgraph_max_size = 5 if settings.ENVIRONMENT == "development" else 10
```

**计算**:
- 4 个 Worker 进程 × 5 连接 = 20 个总连接
- 安全范围，不会超出数据库限制

## 架构说明

### 队列设计

| 队列名称 | 用途 | Worker 启动脚本 |
|---|---|---|
| `celery` (默认) | 路线图生成、工作流恢复等主流程任务 | `scripts/start_worker_dev.sh` |
| `content_generation` | 教程、资源、测验内容生成（高并发） | `scripts/start_content_worker_dev.sh` |

### 并发配置建议

**开发环境**:
- 主 Worker: `concurrency=2`
- 内容 Worker: `concurrency=4`

**生产环境**:
- 主 Worker: `concurrency=4`
- 内容 Worker: `concurrency=20-30`（根据 LLM API 限流调整）

### 连接池计算

```
总连接数 = Worker 进程数 × 连接池大小
安全范围 = 数据库最大连接数 × 0.5（留一半给 API 进程）

示例（开发环境）:
- 主 Worker: 2 进程 × 5 连接 = 10 个
- 内容 Worker: 4 进程 × 5 连接 = 20 个
- API 进程: ~10 个
- 总计: 40 个（安全）
```
