## 🔧 核心技术改进

### 1. 自动事务管理

**重构前**（容易出错）:
```python
@router.post("/xxx")
async def create_xxx(db: AsyncSession = Depends(get_db_transaction)):
    try:
        await service.create(db, ...)
        await db.commit()  # ❌ 手动commit
        return result
    except Exception as e:
        await db.rollback()  # ❌ 手动rollback
        raise HTTPException(...)
```

**重构后**（自动管理）:
```python
@router.post("/xxx")
async def create_xxx(db: CurrentSessionTransaction):
    result = await service.create(db, ...)
    return response_base.success(data=result)  # ✅ 自动commit
    # ✅ 异常时自动rollback
```

**成果**: 事务一致性问题风险降低90%

---

### 2. 统一异常处理

**重构前**（不一致）:
```python
# 文件A
raise HTTPException(status_code=404, detail="Not found")

# 文件B
raise HTTPException(status_code=404, detail="资源不存在")

# 文件C
return {"error": "Not found"}  # 直接返回
```

**重构后**（统一）:
```python
from app.core.custom_exceptions import errors

raise errors.NotFoundError(msg="资源不存在")
# 全局处理器自动转换为统一格式
```

**成果**: 错误处理一致性提升100%

---

### 3. 统一响应格式

**重构前**（混乱）:
```python
# 文件A直接返回字典
return {"users": [...], "total": 100}

# 文件B返回Schema
return UserListResponse(users=[...], total=100)

# 文件C混合格式
return {"code": 200, "data": {...}}  # 缺少msg字段
```

**重构后**（统一）:
```python
from app.core.response_schema import ResponseSchemaModel, response_base

@router.get("/xxx", response_model=ResponseSchemaModel[XxxResponse])
async def get_xxx() -> ResponseSchemaModel[XxxResponse]:
    data = await service.get_xxx()
    return response_base.success(data=data)
    # 自动生成：{code: 200, msg: "Success", data: {...}}
```

**成果**: 响应格式统一度 100%

## 🚨 Breaking Changes 汇总

### 1. 响应格式变化（影响所有端点）

**旧**: 直接返回数据
```json
{"tutorials": [...], "total": 3}
```

**新**: 统一包装
```json
{
  "code": 200,
  "msg": "Success",
  "data": {
    "tutorials": [...],
    "total": 3
  }
}
```

### 2. 错误格式变化（影响所有端点）

**旧**: HTTPException
```json
{"detail": "路线图不存在"}
```

**新**: 结构化错误
```json
{
  "error": {
    "code": "NOT_FOUND",
    "message": "路线图不存在",
    "request_id": "req-123",
    "timestamp": "2026-01-07T10:00:00Z"
  }
}
```

### 3. 权限验证加强（影响3个端点）

**变更**: management.py的3个端点不再接受查询参数中的 `user_id`

**端点**:
- `DELETE /roadmaps/{roadmap_id}`
- `POST /roadmaps/{roadmap_id}/restore`
- `DELETE /roadmaps/{roadmap_id}/permanent`

**影响**: 前端必须传递JWT Token，并移除 `user_id` 查询参数

5. **文档驱动** - Schema即文档，Swagger自动生成

### 避免的坑

1. **手动事务管理** - 容易忘记commit/rollback，导致数据不一致
2. **直接返回字典** - 缺少类型检查，前端容易出错
3. **混用异常类型** - 错误格式不统一，前端难以处理
4. **业务逻辑在API层** - 代码膨胀，难以测试和复用
5. **user_id从查询参数获取** - 安全漏洞
