# 路线图编辑流程简化重构

**日期**: 2026-02-02  
**类型**: 架构重构  
**影响范围**: EditPlanAnalyzerAgent, RoadmapEditorAgent

## 重构目标

将修改指令从细粒度的工程化指令简化为 Stage 级别的语义化指令，充分发挥 LLM 的语义理解能力，降低状态同步成本，提升修改效率。

## 核心改进

### 1. 简化修改指令（EditPlanAnalyzer）

**修改前**:
- 6 种修改类型 × 3 种目标类型 = 18 种组合
- EditIntent 需要精确定位到 stage/module/concept
- 复杂的工程化指令

**修改后**:
- 3 种动作类型：CREATE / UPDATE / REGENERATE
- 以 Stage 为最小原子单位
- 用自然语言描述修改意图

### 2. 分阶段并行执行（RoadmapEditor）

**修改前**:
- 一次性处理整个路线图
- 无并行处理能力
- preserved_elements 手动标注

**修改后**:
- 分 Stage 处理，支持并行执行
- 依赖关系管理（拓扑排序）
- modified_node_ids 自动生成

### 3. 新旧对比引擎（FrameworkDiff）

**新增功能**:
- 自动对比新旧路线图框架
- 识别修改、添加、删除的节点
- 生成 modified_node_ids 列表
- 生成修改总结

## 架构变化

```mermaid
graph TB
    UserFeedback[用户反馈] --> EditPlanAnalyzer[EditPlanAnalyzer]
    EditPlanAnalyzer -->|StageEditTask[]| RoadmapEditor[RoadmapEditor]
    
    subgraph RoadmapEditor_Process [RoadmapEditor 执行流程]
        RoadmapEditor --> StageProcessor[StageProcessor]
        StageProcessor -->|并行| Stage1[Stage 1 修改]
        StageProcessor -->|并行| Stage2[Stage 2 修改]
        StageProcessor -->|并行| StageN[Stage N 修改]
        Stage1 --> Merge[合并Framework]
        Stage2 --> Merge
        StageN --> Merge
        Merge --> Diff[FrameworkDiff]
        Diff --> GenerateIDs[生成modified_node_ids]
        GenerateIDs --> Summary[生成总结]
    end
    
    Summary --> Output[RoadmapEditOutput]
```

## 文件修改清单

### 1. 数据模型 (domain.py)

**新增**:
- `StageEditTask`: Stage 级别的修改任务
- `modified_node_ids`: 被修改的节点 ID 列表

**修改**:
- `EditPlan.tasks`: 从 `List[EditIntent]` 改为 `List[StageEditTask]`
- `EditPlan.execution_strategy`: 新增执行策略字段
- `RoadmapEditOutput.modified_node_ids`: 替代 `preserved_elements`

**删除**:
- `EditIntent`: 不再使用细粒度的修改意图

### 2. EditPlanAnalyzerAgent

**文件**: `backend/app/agents/edit_plan_analyzer.py`

**修改**:
- 更新类文档字符串，说明新职责
- 修改日志输出，使用 `tasks_count` 而非 `intents_count`

### 3. EditPlanAnalyzer Prompt

**文件**: `backend/prompts/edit_plan_analyzer.j2`

**完全重写**:
- 聚焦 3 种动作类型：CREATE / UPDATE / REGENERATE
- 以 Stage 为单位的修改指令
- 自然语言描述修改意图
- 支持任务依赖关系
- 6 个示例场景（明确修改、创建新 Stage、多 Stage 修改、删除 Stage、模糊请求、重建路线图）

### 4. StageProcessor（新增）

**文件**: `backend/app/agents/stage_processor.py`

**职责**:
- 分析任务依赖关系
- 并行执行无依赖的 Stage 修改任务
- 顺序执行有依赖的任务
- 合并修改后的 Stage 到完整的 RoadmapFramework

**核心方法**:
- `process_tasks()`: 处理所有任务
- `_process_parallel()`: 并行执行
- `_process_sequential()`: 顺序执行
- `_handle_create()`: 处理 CREATE 任务
- `_handle_update()`: 处理 UPDATE 任务
- `_handle_delete()`: 处理删除任务

### 5. FrameworkDiff（新增）

**文件**: `backend/app/agents/framework_diff.py`

**职责**:
- 比较新旧路线图框架
- 识别修改、添加、删除的节点
- 生成 modified_node_ids 列表
- 生成修改总结

**核心方法**:
- `compute_diff()`: 计算差异
- `_is_node_modified()`: 判断节点是否被修改
- `_generate_summary()`: 生成修改总结
- `get_detailed_changes()`: 获取详细变更信息

**便捷函数**:
- `compute_modified_node_ids()`: 快速计算 modified_node_ids
- `generate_change_summary()`: 快速生成修改总结

### 6. RoadmapEditorAgent

**文件**: `backend/app/agents/roadmap_editor.py`

**重大重构**:
- 不再直接调用 LLM 生成整个路线图
- 使用 StageProcessor 分 Stage 处理
- 使用 FrameworkDiff 进行新旧对比
- 自动生成 modified_node_ids

**新执行流程**:
1. 使用 StageProcessor 分 Stage 处理修改任务
2. 使用 FrameworkDiff 对比新旧框架
3. 自动生成 modified_node_ids
4. 生成修改总结

### 7. RoadmapEditor Prompt

**文件**: `backend/prompts/roadmap_editor.j2`

**状态**: 已废弃

**说明**: 由于采用了 StageProcessor 分阶段处理，此 Prompt 文件不再被使用。每个 Stage 的修改使用独立的 Prompt（在 StageProcessor 中动态构建）。

## 优势总结

### 1. 降低复杂度
- 从 18 种组合简化为 3 种动作
- Prompt 更简洁，LLM 理解负担更小

### 2. 提升性能
- 支持并行处理（无依赖的 Stage 同时修改）
- 减少状态同步开销

### 3. 充分利用 LLM 能力
- 让 LLM 做它擅长的：语义理解 + 内容生成
- 避免微操 JSON 节点的工程化指令

### 4. 自动化
- modified_node_ids 自动生成（无需手动标注）
- 修改总结自动生成

### 5. 可维护性
- 逻辑分层清晰（EditPlanAnalyzer → StageProcessor → FrameworkDiff）
- 每个模块职责单一

## 使用示例

### 用户反馈
"请把阶段2的内容改简单点，删掉高级主题"

### EditPlanAnalyzer 输出
```json
{
  "edit_plan": {
    "feedback_summary": "简化阶段2，删除高级主题",
    "tasks": [
      {
        "action": "UPDATE",
        "stage_id": "stage-2",
        "instruction": "简化 Stage 2 的内容：删除所有标记为 hard 难度的高级主题概念，将剩余概念的难度适当降低。",
        "dependencies": []
      }
    ],
    "execution_strategy": "parallel"
  }
}
```

### RoadmapEditor 执行流程
1. StageProcessor 处理 stage-2 的 UPDATE 任务
2. FrameworkDiff 对比新旧框架
3. 生成 modified_node_ids: ["stage-2", "c-2-1-3", "c-2-1-4", ...]
4. 生成修改总结: "删除 2 个概念、修改 1 个阶段"

### 最终输出
```json
{
  "framework": { ... },
  "modification_summary": "删除 2 个概念、修改 1 个阶段",
  "modified_node_ids": ["stage-2", "c-2-1-3", "c-2-1-4"]
}
```

## 兼容性说明

### 破坏性变更
- `EditIntent` 类已删除
- `EditPlan.intents` 改为 `EditPlan.tasks`
- `RoadmapEditOutput.preserved_elements` 改为 `modified_node_ids`

### 迁移建议
如果有代码依赖旧的数据结构，需要进行以下修改：
1. 将 `EditIntent` 替换为 `StageEditTask`
2. 将 `edit_plan.intents` 替换为 `edit_plan.tasks`
3. 将 `result.preserved_elements` 替换为 `result.modified_node_ids`

## 后续优化方向

1. **智能依赖分析**: 自动识别 Stage 之间的依赖关系
2. **增量修改**: 只重新生成被修改的部分，而非整个 Stage
3. **回滚机制**: 如果修改失败，自动回滚到旧版本
4. **修改预览**: 在执行前预览修改效果
5. **批量修改**: 支持一次性修改多个路线图

## 总结

本次重构通过简化修改指令、支持并行处理、自动化对比总结，大幅降低了路线图编辑的复杂度和成本，同时提升了性能和可维护性。核心思想是**以 Stage 为单位 + 充分利用 LLM 的语义理解能力**，避免过度工程化。
