## 六、快速参考

### 约束系统架构

```
IntentAnalyzerAgent
  ↓ 生成 12 个约束
full_analysis_data (约束文本字典)
  ↓ 保存到数据库
IntentAnalysisMetadata
  ↓ 缓存到 RuntimeContext
RuntimeContext._constraints_cache
  ↓ 各 Agent 加载和过滤
过滤后的约束 (3-11 个)
  ↓ 注入到 Prompt
LLM 生成个性化内容
```

**CurriculumArchitectAgent（8 个约束）**：

### 关键代码片段

**生成约束**：
```python
# IntentAnalyzerAgent
result.full_analysis_data = self._generate_constraints(result)
```

**加载约束**：

## 七、常见问题

### Q1: 如何添加新的约束类型？

**步骤**：
1. 在 `ConstraintNames` 中添加常量
2. 在 `IntentAnalyzerAgent._generate_constraints()` 中添加生成逻辑
3. 在需要的 Agent 的 `_get_required_constraints()` 中添加约束名称

### Q2: 如何调试约束是否正确注入？

**方法**：
1. 检查日志中的 `constraints_generated` 事件
2. 在 Agent 的 `_load_system_prompt()` 后打印 prompt
3. 使用测试脚本验证约束过滤逻辑

### Q3: 缓存何时失效？

**答案**：
- RuntimeContext 的缓存在工作流执行期间有效
- 每次新的工作流执行会创建新的 RuntimeContext
- 缓存不跨工作流持久化（这是设计如此，避免过期数据）

### Q4: 如果约束加载失败怎么办？

**降级策略**：
- `_load_user_constraints()` 返回空字典
- Prompt 模板的 `{% if user_constraints %}` 不会渲染约束部分
- Agent 仍然可以正常工作，只是缺少个性化约束

## 十一、故障排除

### 问题 1：约束未生成

**症状**：`full_analysis_data` 为空

**排查**：
1. 检查 IntentAnalyzerAgent 是否正常执行
2. 检查日志中是否有 `constraints_generated` 事件
3. 验证 `_generate_constraints()` 方法是否被调用

**解决**：
- 确保 IntentAnalyzerAgent.execute() 正常返回
- 检查是否有异常被吞掉

### 问题 2：约束未注入到 Prompt

**症状**：生成的内容未遵守约束

**排查**：
1. 检查 Agent 是否调用了 `_load_user_constraints()`
2. 检查 `_load_system_prompt()` 是否传入了 `user_constraints`
3. 打印 prompt 内容，查看是否包含约束

**解决**：
- 确保 Agent 的 execute 方法中加载了约束
- 确保 Prompt 模板有约束注入区域

### 问题 3：缓存未命中

**症状**：日志中没有 `cache_hit` 事件

**排查**：
1. 检查是否使用了 RuntimeContext.get_user_constraints()
2. 检查 roadmap_id 是否一致
3. 检查是否在不同的 RuntimeContext 实例中

**解决**：
- 在工作流节点中使用 ctx.get_user_constraints()
- 确保同一工作流使用同一个 RuntimeContext 实例
