# Agent 用户画像约束注入重构

## 一、重构概述

本次重构将用户画像数据（IntentAnalysisMetadata）转换为约束文本，并动态注入到所有 Agent 的系统提示词中，实现个性化的用户画像驱动生成。

**核心改动**：
- IntentAnalyzerAgent 生成约束文本（扁平键值对格式）
- BaseAgent 提供统一的约束管理和注入机制
- 不同 Agent 根据职责获取不同的约束子集
- 所有 Prompt 模板支持用户画像约束注入

### 3. BaseAgent 约束注入机制

**文件**: `backend/app/agents/base.py`

**新增方法**：

1. `_get_required_constraints()`: 获取当前 Agent 需要的约束类型（子类可覆盖）
2. `_filter_constraints()`: 过滤出当前 Agent 需要的约束
3. `_load_user_constraints()`: 加载用户约束（支持两种方式）
   - 方式1：直接传入 intent_analysis
   - 方式2：通过 roadmap_id 查询数据库

**改动点**：
- 修改 `_load_system_prompt()` 方法，支持 `user_constraints` 参数
- 自动将 `user_constraints` 注入到 Jinja2 模板变量中

## 十一、技术细节

### 约束加载优先级

```python
async def _load_user_constraints(
    self,
    roadmap_id: str | None = None,
    intent_analysis: IntentAnalysisOutput | None = None
) -> UserConstraints:
    # 优先级1：直接传入的 intent_analysis（最快）
    if intent_analysis and intent_analysis.full_analysis_data:
        return self._filter_constraints(intent_analysis.full_analysis_data)
    
    # 优先级2：通过 roadmap_id 查询数据库（备选）
    if roadmap_id:
        # 从数据库查询...
        
    # 优先级3：返回空字典（默认）
    return {}
```

### 约束过滤逻辑

```python
def _filter_constraints(self, all_constraints: UserConstraints) -> UserConstraints:
    required = self._get_required_constraints()  # 获取当前 Agent 需要的约束
    return {
        name: content
        for name, content in all_constraints.items()
        if name in required  # 只保留需要的约束
    }
```

### Prompt 注入逻辑

```python
def _load_system_prompt(
    self,
    template_name: str,
    user_constraints: UserConstraints | None = None,
    **kwargs
) -> str:
    if user_constraints is None:
        user_constraints = {}
    
    # 自动注入到模板变量
    kwargs["user_constraints"] = user_constraints
    
    return self.prompt_loader.render(template_name, **kwargs)
```
