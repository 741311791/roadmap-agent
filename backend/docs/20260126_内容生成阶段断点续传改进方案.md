# 内容生成阶段断点续传改进方案

## 📋 问题描述

当前架构下，内容生成阶段（Content Generation）的断点续传能力有限：

1. **子图没有独立的 checkpointer**，中间状态不会自动保存
2. **子图执行中断时**，所有进度会丢失，需要从头开始
3. **Worker 重启时**，正在执行的任务无法恢复

## 🎯 改进目标

1. **细粒度 Checkpoint**：每个 Concept 生成完成后立即保存状态
2. **增量重试**：失败时只重试未完成的 Concept
3. **Worker 安全**：Worker 重启后可以从中断点恢复
4. **进度追踪**：用户可以实时查看内容生成进度

## 💡 解决方案

### ⚠️ **LangGraph 1.x 官方机制说明**

根据 [LangGraph 官方文档](https://langchain-ai.github.io/langgraph/how-tos/subgraph/#add-persistence)：

1. **✅ Checkpointer 自动传播**：  
   > "You only need to provide the checkpointer when compiling the parent graph. LangGraph will automatically propagate the checkpointer to the child subgraphs."

2. **⚠️ 子图状态访问限制**：  
   > "Subgraph state can only be viewed **when the subgraph is interrupted**. Once you resume the graph, you won't be able to access the subgraph state."

**结论**：
- ✅ 当前实现是正确的（子图没有独立配置 checkpointer）
- ❌ 但子图状态只有在 `interrupt()` 暂停时才能恢复
- ❌ 内容生成子图没有使用 `interrupt()`，因此**无法从中间恢复**

### 方案 1：子图中添加 Interrupt 点（推荐）

在每个 Concept 生成完成后添加 interrupt 点，允许细粒度恢复。

#### 1.1 修改外层子图添加条件 interrupt

```python
# app/core/orchestrator/subgraphs/content_generation.py

from langgraph.types import interrupt
from app.config.settings import settings

async def outer_fan_out(state: ContentGenState) -> Command:
    """外层 Fan-Out：为每个 Concept 创建子图实例"""
    concepts = state["concepts"]
    task_id = state["task_id"]
    
    logger.info(
        "outer_fan_out_started",
        task_id=task_id,
        concept_count=len(concepts),
    )
    
    # 为每个 Concept 创建一个 Send 任务
    sends = [
        Send(
            "single_concept_subgraph",
            {
                "concept": concept,
                "roadmap_id": state["roadmap_id"],
                "user_preferences": state["user_preferences"],
                "task_id": task_id,
                # 初始化 Reducer 字段
                "tutorial": None,
                "resource": None,
                "quiz": None,
                "errors": [],
                "save_status": {},
            }
        )
        for concept in concepts
    ]
    
    return Command(goto=sends)


async def final_aggregation(state: ContentGenState) -> dict:
    """
    最终汇总节点
    
    ✅ 新增：在每批 Concept 完成后，添加可选的 interrupt 点
    """
    concept_results = state["concept_results"]
    task_id = state["task_id"]
    
    successful_count = len([
        r for r in concept_results
        if r.get("save_status", {}).get("metadata_saved", False)
    ])
    failed_count = len(concept_results) - successful_count
    
    logger.info(
        "content_generation_aggregation_completed",
        task_id=task_id,
        total_concepts=len(concept_results),
        successful_count=successful_count,
        failed_count=failed_count,
    )
    
    # ✅ 可选：添加 interrupt 点用于断点续传
    # 只在开发/测试模式启用，生产环境禁用
    if settings.ENABLE_CONTENT_GENERATION_CHECKPOINTS:
        interrupt(f"Batch completed: {successful_count}/{len(concept_results)} successful")
    
    return {
        "concept_results": concept_results,
    }
```

async def content_generation_node(state: RoadmapState, config: RunnableConfig) -> dict:

        "concept_results": [],

### 方案 3：混合方案（推荐 ⭐）

结合方案 1 和方案 2：

1. **使用 LangGraph Interrupt** 在关键点暂停（可选，仅开发/测试）

### ⚠️ **重要发现：LangGraph 子图 Checkpoint 限制**

根据官方文档，子图的 checkpointer **会自动从父图继承**，但有重要限制：

1. **子图状态只在 interrupt 时可访问**
2. **子图正常执行完成后，无法单独恢复其中间状态**
3. **Interrupt 会影响性能，不适合生产环境频繁使用**

**因此**：
- ❌ 方案 1（纯 Interrupt）**不适合生产环境**（性能影响大）
- ✅ 方案 2（数据库状态）**最适合生产环境**（性能好、可靠）
- ✅ 方案 3（混合）**最佳实践**（开发用 Interrupt 调试，生产用数据库）
