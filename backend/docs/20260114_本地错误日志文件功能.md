# 本地错误日志文件功能

## 功能概述

为本地开发环境新增错误日志文件收集功能，自动将 **WARNING** 及以上级别的日志写入 `logs/err.log` 文件。

**核心特点**：
- ✅ **仅本地启用**：通过配置开关控制，不影响生产环境
- ✅ **架构改动最小**：基于现有 structlog 架构，仅修改 2 个配置文件
- ✅ **可读性优先**：纯文本格式，便于快速查看和搜索
- ✅ **自动轮转**：单文件最大 10MB，超过自动覆盖（不保留备份）
- ✅ **多级别收集**：包含 WARNING、ERROR、CRITICAL 级别

---

## 快速开始

### 1. 启用错误日志文件

在 **本地环境** 的 `.env` 文件中添加：

```bash
# 启用错误日志文件（仅本地开发）
ENABLE_ERROR_LOG_FILE=true
```

### 2. 启动服务

```bash
cd backend
make dev
```

### 3. 查看错误日志

```bash
# 查看最新日志
tail -f backend/logs/err.log

# 搜索特定错误
grep "ERROR" backend/logs/err.log

# 查看最近 50 行
tail -n 50 backend/logs/err.log
```

## 配置详解

### 环境变量配置

在 `.env` 文件中配置以下变量：

```bash
# ==================== 错误日志文件配置 ====================

# 是否启用错误日志文件（默认: false）
ENABLE_ERROR_LOG_FILE=true

# 日志文件路径（默认: logs/err.log）
ERROR_LOG_FILE_PATH=logs/err.log

# 单文件最大大小（字节，默认: 10MB）
ERROR_LOG_FILE_MAX_SIZE=10485760
```

### 配置项说明

| 配置项 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| `ENABLE_ERROR_LOG_FILE` | bool | `false` | 是否启用错误日志文件 |
| `ERROR_LOG_FILE_PATH` | str | `logs/err.log` | 日志文件存储路径 |
| `ERROR_LOG_FILE_MAX_SIZE` | int | `10485760` | 单文件最大大小（10MB） |

## 日志格式

### 输出格式

```
YYYY-MM-DD HH:MM:SS | LEVEL    | logger_name | message
```

### 示例

```log
2026-01-14 15:30:45 | WARNING  | app.agents.base | LLM调用超时，正在重试...
2026-01-14 15:31:02 | ERROR    | app.core.orchestrator.executor | 路线图生成失败
2026-01-14 15:31:02 | CRITICAL | app.db.session | 数据库连接池耗尽
```

### 字段说明

- **时间戳**：精确到秒，格式 `YYYY-MM-DD HH:MM:SS`
- **级别**：WARNING | ERROR | CRITICAL（左对齐，固定 8 字符宽度）
- **Logger名称**：日志来源（如 `app.agents.base`）
- **消息**：日志内容（支持多行，异常堆栈会被格式化）

---

## 日志级别说明

### 收集范围

| 级别 | 是否收集 | 说明 |
|---|---|---|
| **DEBUG** | ❌ 否 | 调试信息，不写入文件 |
| **INFO** | ❌ 否 | 一般信息，不写入文件 |
| **WARNING** | ✅ 是 | 警告信息（可能导致问题） |
| **ERROR** | ✅ 是 | 错误（功能失败但程序继续） |
| **CRITICAL** | ✅ 是 | 严重错误（可能导致程序崩溃） |

### 典型场景

```python
import structlog

logger = structlog.get_logger(__name__)

# ❌ 不会写入文件
logger.debug("调试信息")
logger.info("一般信息")

# ✅ 会写入 err.log
logger.warning("LLM调用超时，正在重试...")
logger.error("路线图生成失败", roadmap_id="rdmp_123")
logger.critical("数据库连接池耗尽")

# ✅ 异常也会写入
try:
    result = await agent.execute(input_data)
except Exception as e:
    logger.error("Agent执行失败", exc_info=True)
```

## 文件管理

### 日志轮转

- **单文件最大**：10MB（可配置）
- **备份数量**：0（不保留备份，满了直接覆盖）
- **轮转策略**：当 `err.log` 达到 10MB 时，自动清空并重新开始写入

### 手动清理

```bash
# 删除日志文件
rm backend/logs/err.log

# 清空日志文件（保留文件）
> backend/logs/err.log
```

### Git 管理

日志文件已自动忽略（`.gitignore`），不会被提交到版本控制。

## 架构设计

### 改动文件

```
backend/
├── app/
│   └── config/
│       ├── settings.py        # ✅ 新增配置项（3项）
│       └── logging_config.py  # ✅ 新增文件Handler实现
└── .gitignore                 # ✅ 新增 logs/ 忽略规则
```

### 实现原理

1. **配置驱动**：通过 `ENABLE_ERROR_LOG_FILE` 环境变量控制
2. **标准库集成**：使用 Python 标准库的 `logging.handlers.RotatingFileHandler`
3. **无侵入**：不影响现有的 structlog 配置和控制台输出
4. **自动创建**：首次启动时自动创建 `logs/` 目录

### 执行流程

```
应用启动
    ↓
读取 settings.ENABLE_ERROR_LOG_FILE
    ↓
[如果为 true]
    ↓
创建 logs/ 目录（如果不存在）
    ↓
创建 RotatingFileHandler（WARNING 级别）
    ↓
添加到 root logger
    ↓
[日志产生]
    ↓
控制台输出（所有级别）
    +
文件写入（仅 WARNING 及以上）
```

## 常见问题

### Q1: 为什么日志文件没有生成？

**可能原因**：
1. 未启用功能：检查 `.env` 中 `ENABLE_ERROR_LOG_FILE=true`
2. 未产生错误：只有 WARNING 及以上级别才会写入
3. 权限问题：检查是否有 `logs/` 目录的写入权限

**解决方案**：
```bash
# 检查配置
cat .env | grep ENABLE_ERROR_LOG_FILE

# 手动测试（生成一个错误日志）
python -c "import structlog; logger = structlog.get_logger(); logger.error('测试错误日志')"

# 检查文件
ls -lh backend/logs/
```

---

### Q2: 日志文件太大怎么办？

**调整配置**：
```bash
# 减小单文件大小（5MB）
ERROR_LOG_FILE_MAX_SIZE=5242880
```

**手动清理**：
```bash
# 清空日志文件
> backend/logs/err.log
```

---

### Q3: 生产环境会自动禁用吗？

**是的**！只要不在生产环境的 `.env` 中设置 `ENABLE_ERROR_LOG_FILE=true`，功能就不会启用。

默认值为 `false`，确保生产环境不会意外启用。

---

### Q4: 为什么不保留备份文件？

**设计考虑**：
- 本地开发环境磁盘空间有限
- 错误日志主要用于实时调试，历史日志价值较低
- 如需保留历史日志，可以在达到 10MB 前手动备份

**手动备份**：
```bash
# 备份当前日志
cp backend/logs/err.log backend/logs/err.log.backup-$(date +%Y%m%d)
```

---

### Q5: 可以修改日志格式吗？

**可以**！修改 `backend/app/config/logging_config.py` 中的 `_setup_error_log_file` 函数：

```python
# 当前格式
formatter = logging.Formatter(
    fmt='%(asctime)s | %(levelname)-8s | %(name)s | %(message)s',
    datefmt='%Y-%m-%d %H:%M:%S'
)

# 修改为更简洁的格式
formatter = logging.Formatter(
    fmt='[%(levelname)s] %(message)s'
)

# 修改为更详细的格式（包含文件名和行号）
formatter = logging.Formatter(
    fmt='%(asctime)s | %(levelname)-8s | %(name)s:%(lineno)d | %(message)s',
    datefmt='%Y-%m-%d %H:%M:%S'
)
```

## 与现有日志系统的关系

### 控制台日志（Console）

- **不受影响**：所有级别的日志仍会输出到控制台
- **独立工作**：文件日志和控制台日志并行工作

### Structlog配置

- **完全兼容**：基于标准库 `logging` 实现，与 structlog 无缝集成
- **上下文保留**：structlog 的上下文信息会自动包含在文件日志中

### 其他日志工具

- **Celery日志**：Worker 的错误也会写入文件
- **FastAPI日志**：请求处理错误会写入文件
- **第三方库日志**：SQLAlchemy、httpx 等库的错误也会收集
