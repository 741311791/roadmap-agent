## 一、架构问题诊断

### 1.1 原有设计的根本性错误

❌ **错误的"三层重试粒度"概念**：
- 任务级、阶段级、概念级 ← 这个分类是错误的
- 混淆了不同的使用场景
- 不符合LangGraph的checkpoint机制

❌ **概念级重试放错位置**：
- 概念内容重新生成不属于Retry功能
- 应该属于Concept编辑服务
- 当前实现绕过了checkpoint机制

❌ **子图恢复机制缺失**：
- 没有检查子图中断状态
- 没有使用 `get_state(config, subgraphs=True)`
- 子图节点失败无法正确恢复

---

## 二、正确的架构理解

### 2.1 三种独立场景

基于LangGraph官方文档和实际需求，应该是：

#### 1️⃣ 断点续传（Resume from Checkpoint）

**定义**: 从最后的checkpoint自动恢复执行

**适用场景**:
- Worker进程崩溃/重启
- 临时网络故障
- API限流错误
- **主图节点失败**（单点失败）
- **子图节点失败**（可能是多个并发节点）

**关键理解：并发失败处理**:
```python
# 子图并发执行（使用Send API）
# 如果Concept A, B, C同时失败：
# - LangGraph会保存整个图的状态（包含所有失败信息）
# - checkpoint记录的是"图的快照"，不是"单个节点"
# - 恢复时会自动处理所有失败的并发节点

# 示例：3个Concept的tutorial生成都失败了
failed_states = {
    "concept_A_tutorial": "failed",
    "concept_B_tutorial": "failed", 
    "concept_C_tutorial": "failed",
}
# checkpoint保存了整个图的状态，恢复时会重试所有失败节点
```

**实现机制**:
```python
# 断点续传（主图/子图通用）
config = {"configurable": {"thread_id": task_id}}

# 1. 检查当前状态（获取失败信息）
state = await graph.aget_state(config, subgraphs=True)  # ✅ 异步调用

# 2. 分析失败情况
if state.tasks:  # 有子图在中断/失败
    subgraph_state = state.tasks[0].state
    failed_nodes = subgraph_state.next  # 获取需要重试的节点列表
    
    logger.info(
        "subgraph_failures_detected",
        task_id=task_id,
        failed_count=len(failed_nodes) if failed_nodes else 0,
        failed_nodes=failed_nodes,
    )

# 3. 恢复执行（LangGraph会自动重试所有失败节点）
await graph.ainvoke(None, config)  # ✅ 自动处理并发失败
```

**特点**:
- ✅ 自动选择checkpoint（最后一个）
- ✅ 支持主图和子图
- ✅ **自动处理并发失败**（无需手动选择）
- ✅ 最快速的恢复方式
- ✅ 返回新的celery_task_id

**重要**：断点续传不需要手动选择checkpoint，LangGraph会：
1. 从最后的checkpoint加载完整状态
2. 识别所有需要重试的节点（包括并发失败）
3. 自动重新执行所有失败节点

---

#### 2️⃣ 时间旅行（Time Travel）

**定义**: 回溯到历史的特定主图节点重新执行

**适用场景**:
- 用户需求变更（想从Intent重新开始）
- 探索不同的执行路径
- 调试特定阶段问题
- **仅主图节点**（主图是顺序执行的）

**关键理解：主图vs子图**:
```python
# 主图节点（顺序执行）
START -> Intent -> Curriculum -> Validation -> Review -> Content -> END
#        ↑        ↑             ↑              ↑         ↑
#        可以时间旅行回到任意主图节点

# 子图节点（并发执行 - 不支持时间旅行）
Content (主图节点) 
  └─> fan_out -> [TutorialA, TutorialB, TutorialC]  # 并发
      └─> 不支持时间旅行到单个TutorialA
      └─> 只能从Content主图节点重新开始
```

**实现机制**:
```python
# 时间旅行：回到主图的历史节点
# 主图是顺序的，所以找到第一个匹配即可

checkpoint_id = None
iteration_count = 0
max_depth = 50  # 限制查询深度（防止无限遍历）

async for state in graph.aget_state_history(config):  # ✅ 异步调用
    iteration_count += 1
    current_step = state.values.get("current_step", "")
    
    # 主图节点匹配
    if current_step == target_node:
        checkpoint_id = state.config["configurable"]["checkpoint_id"]
        logger.info(
            "main_graph_checkpoint_found",
            task_id=task_id,
            target_node=target_node,
            iterations=iteration_count,
            checkpoint_id=checkpoint_id[:8],
        )
        break  # ✅ 主图是顺序的，找到第一个即可
    
    # 防止无限遍历
    if iteration_count >= max_depth:
        logger.warning(
            "checkpoint_search_depth_exceeded",
            task_id=task_id,
            max_depth=max_depth,
        )
        break

if not checkpoint_id:
    raise ValueError(
        f"未找到目标节点 {target_node} 的checkpoint "
        f"(已查询{iteration_count}个checkpoint)"
    )

# 从该checkpoint恢复（异步）
config = {
    "configurable": {
        "thread_id": task_id,
        "checkpoint_id": checkpoint_id  # ← 关键
    }
}
await graph.ainvoke(None, config)  # ✅ 异步调用
```

**特点**:
- ✅ 手动选择checkpoint
- ✅ 主图是顺序执行，流式查找有效（找到第一个即可）
- ⚠️ 仅支持主图节点（子图并发执行，不支持时间旅行）
- ✅ 可探索替代路径
- ✅ 返回新的celery_task_id

**限制**:
- 子图节点不支持时间旅行（官方文档未提供方案）
- 只能回到主图的历史节点
- **并发子图节点失败 → 使用断点续传（自动处理所有并发失败）**

#### 3️⃣ 内容重新生成（Content Regeneration）

**定义**: 重新生成单个Concept的教程/资源/测验

**适用场景**:
- 单个教程质量不满意
- 想要不同风格的资源推荐
- 测验难度调整

**实现机制**:
```python
# 直接调用Content Agent（绕过checkpoint）
result = await content_service.regenerate_content(
    roadmap_id=roadmap_id,
    concept_id=concept_id,
    content_type="tutorial",  # or "resources", "quiz"
    user_feedback="需要更详细的代码示例"
)
```

**特点**:
- ❌ 不使用checkpoint机制
- ✅ 最细粒度的修改
- ✅ 不影响其他内容
- ❌ 不返回celery_task_id（直接执行）

**归属**:
- 属于Concept编辑服务，不属于Retry功能
- API路径：`/api/v1/content/{roadmap_id}/concepts/{concept_id}/regenerate`

### 2.2 子图Checkpoint机制（关键理解）

根据[官方文档](https://docs.langchain.com/oss/python/langgraph/use-subgraphs)：

#### ✅ 子图完全支持checkpoint

```python
# 子图注册方式（方式B - 推荐）
subgraph_compiled = subgraph_builder.compile()
builder.add_node("content_generation", subgraph_compiled)

# 这样注册后，子图的每个节点都会有独立checkpoint
```

#### ✅ 查看子图中断状态

```python
# 默认只能看到父图状态（异步）
parent_state = await graph.aget_state(config)  # ✅ 异步调用

# 使用subgraphs=True查看子图状态（异步）
all_states = await graph.aget_state(config, subgraphs=True)  # ✅ 异步调用

# 检查是否有子图在中断
if all_states.tasks:
    subgraph_state = all_states.tasks[0].state
    print(subgraph_state.next)  # 子图的下一步节点
```

#### ✅ 恢复子图执行

```python
# 向父图发送resume，会自动路由到子图（异步）
await graph.ainvoke(Command(resume=data), config)  # ✅ 异步调用
```

#### ⚠️ 子图时间旅行不支持

官方文档未提供子图时间旅行的方案，暂时只支持断点续传。

### 3.1 新的Schema设计

```python
# backend/app/schemas/retry.py

class RetryMode(str, Enum):
    """重试模式枚举"""
    RESUME = "resume"  # 断点续传
    TIME_TRAVEL = "time_travel"  # 时间旅行


class MainGraphNode(str, Enum):
    """主图节点枚举（用于时间旅行）"""
    INTENT = "intent_analysis"
    CURRICULUM = "curriculum_design"
    VALIDATION = "structure_validation"
    REVIEW = "human_review"
    CONTENT = "content_generation"


class RetryRequest(BaseModel):
    """统一的重试请求"""
    mode: RetryMode = RetryMode.RESUME
    target_node: Optional[MainGraphNode] = None  # 仅time_travel需要
    reason: Optional[str] = None


class RetryResponse(BaseModel):
    """重试响应"""
    success: bool
    message: str
    task_id: str
    celery_task_id: str  # 新的Celery任务ID
    mode: RetryMode
    resume_from: Optional[str] = None  # checkpoint_id或节点名
    is_subgraph: bool = False  # 是否在子图中断
```

### 3.2 RetryService重构

```python
# backend/app/services/workflows/generation/retry_service.py

class RetryService:
    
    async def retry_task(
        self,
        task_id: str,
        request: RetryRequest,
        user_id: str,
    ) -> RetryResponse:
        """执行任务重试"""
        
        # 验证任务和权限
        task = await self._validate_task(task_id, user_id)
        
        # 根据模式分发
        if request.mode == RetryMode.RESUME:
            return await self._resume_from_checkpoint(task_id, task)
        elif request.mode == RetryMode.TIME_TRAVEL:
            return await self._time_travel_to_node(task_id, task, request)
    
    async def _resume_from_checkpoint(self, task_id, task):
        """断点续传（支持主图和子图）"""
        
        factory = OrchestratorFactory()
        await factory.initialize()
        
        executor = factory.create_workflow_executor()
        config = {"configurable": {"thread_id": task_id}}
        
        # ===== 关键：检查是否有子图在中断（异步调用）=====
        state = await executor.graph.aget_state(config, subgraphs=True)  # ✅ 异步
        
        is_subgraph = bool(state.tasks)  # 有子图在中断
        
        if is_subgraph:
            logger.info(
                "subgraph_interrupted_detected",
                task_id=task_id,
                subgraph_next=state.tasks[0].state.next,

            success=True,

            celery_task_id=celery_task.id,
```

### 6.2 子图恢复

```python
# 向父图发送Command，会自动路由到子图（异步）
await graph.ainvoke(Command(resume=data), config)  # ✅ 异步
```

### 6.3 时间旅行限制

- ✅ 主图节点：完全支持
- ❌ 子图节点：官方文档未提供方案

### 6.4 并发失败与时间旅行的区别

| 场景 | 图类型 | 执行方式 | 处理方式 | 是否需要遍历所有 |
|------|--------|---------|---------|----------------|
| 断点续传 | 主图/子图 | 顺序/并发 | LangGraph自动处理所有失败 | ❌ 不需要（自动） |
| 时间旅行 | **仅主图** | **顺序** | 手动选择checkpoint | ❌ 不需要（顺序，找到第一个） |
| 子图并发失败 | 子图 | 并发 | 使用断点续传 | ❌ 不需要（checkpoint包含完整状态） |

**关键理解**：

1. **断点续传不需要遍历**：
   ```python
   # LangGraph会从最后的checkpoint加载完整状态
   # 包括所有并发失败的节点信息
   await graph.ainvoke(None, config)  # 自动处理
   ```

2. **时间旅行仅用于主图**（主图是顺序的）：
   ```python
   # 主图节点顺序执行：Intent -> Curriculum -> Content
   # 找到第一个匹配的主图节点checkpoint即可
   async for state in graph.aget_state_history(config):
       if state.values.get("current_step") == target_node:
           break  # 主图是顺序的，第一个即正确
   ```

3. **子图并发失败不使用时间旅行**：
   ```python
   # 如果3个Concept的tutorial都失败
   # → 使用断点续传（Resume）
   # → LangGraph会重试所有3个失败的tutorial
   # ❌ 不使用时间旅行（无法选择"回到哪个Concept"）
   ```

### 6.5 性能优化：流式查找checkpoint

**适用场景**：仅时间旅行（主图节点查找）

```python
# ✅ 高效：流式查找主图节点（顺序执行，找到第一个）
checkpoint_id = None
iteration_count = 0

async for state in graph.aget_state_history(config):
    iteration_count += 1
    
    if state.values.get("current_step") == target_node:
        checkpoint_id = state.config["configurable"]["checkpoint_id"]
        logger.info("found_at_iteration", count=iteration_count)
        break  # 主图是顺序的，找到第一个即可
    
    if iteration_count >= 50:  # 防护：最多查50个
        break
```

**性能收益**：
- 目标在最近5个checkpoint内：遍历5次（vs 100次）
- **20x性能提升**（仅适用于时间旅行）
