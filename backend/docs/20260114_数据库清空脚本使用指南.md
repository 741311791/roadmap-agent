# 数据库清空脚本使用指南

## 概述

`clear_all_tables.py` 是一个用于清空数据库所有表数据的工具脚本，主要用于开发/测试环境的数据重置。

## 功能特性

### 1. 清空范围

**业务表（23张）**：
- users（用户表）
- roadmap_tasks（路线图任务表）
- roadmap_metadata（路线图元数据）
- concept_metadata（概念元数据）
- tutorial_metadata（教程元数据）
- intent_analysis_metadata（意图分析元数据）
- resource_recommendation_metadata（资源推荐元数据）
- quiz_metadata（测验元数据）
- tech_stack_assessments（技术栈评估）
- user_profiles（用户配置）
- execution_logs（执行日志）
- concept_progress（概念进度）
- quiz_attempts（测验尝试）
- structure_validation_records（结构验证记录）
- roadmap_edit_records（路线图编辑记录）
- human_review_feedbacks（人工审核反馈）
- edit_plan_records（编辑计划记录）
- chat_sessions（聊天会话）
- chat_messages（聊天消息）
- learning_notes（学习笔记）
- waitlist_emails（等待列表邮箱）
- roadmap_cover_images（路线图封面图）
- tavily_api_keys（Tavily API密钥）

**Checkpoint表（3张）**：
- checkpoints（LangGraph检查点）
- checkpoint_blobs（检查点二进制数据）
- checkpoint_writes（检查点写入记录）

### 2. 安全特性

- ✅ **环境保护**：禁止在生产环境执行
- ✅ **二次确认**：要求用户输入 'YES' 确认
- ✅ **外键处理**：使用 `TRUNCATE CASCADE` 自动处理外键约束
- ✅ **事务保证**：所有操作在同一事务中执行
- ✅ **详细日志**：记录每个表的清空状态

## 使用场景

### ✅ 适用场景

1. **开发环境重置**：清空测试数据，重新开始
2. **测试数据清理**：测试完成后清空数据
3. **Schema迁移后**：清空旧数据，重新生成
4. **本地开发调试**：快速重置数据库状态

### ❌ 不适用场景

1. **生产环境**：脚本会自动拒绝执行
2. **部分数据清理**：此脚本会清空所有表
3. **数据备份**：不提供备份功能，需手动备份

## 安全注意事项

### 1. 环境隔离

```python
# 脚本内置环境检查
if settings.ENVIRONMENT == "production":
    logger.error("禁止在生产环境执行")
    sys.exit(1)
```

### 2. 数据备份

在执行清空前，建议备份重要数据：

```bash
# PostgreSQL 备份
pg_dump -h localhost -U postgres -d roadmap_db > backup_$(date +%Y%m%d_%H%M%S).sql

# 恢复数据
psql -h localhost -U postgres -d roadmap_db < backup_20260114_120000.sql
```

### 3. 确认提示

脚本要求用户输入 `YES`（大写）确认，任何其他输入都会取消操作。

## 技术实现

### TRUNCATE CASCADE

使用 PostgreSQL 的 `TRUNCATE CASCADE` 命令：

```sql
TRUNCATE TABLE table_name RESTART IDENTITY CASCADE
```

**特性**：
- 自动处理外键约束
- 重置自增序列（RESTART IDENTITY）
- 比 DELETE 更快（不触发触发器）
- 立即释放磁盘空间

### 事务保证

所有表的清空操作在同一事务中执行，确保原子性：

```python
async with async_session_maker.begin() as session:
    for table in tables_to_clear:
        await truncate_table(session, table)
    await session.commit()
```

## 故障排查

### 问题1：权限不足

**错误**：`ERROR: permission denied for table xxx`

**解决**：确保数据库用户有 TRUNCATE 权限

```sql
GRANT TRUNCATE ON ALL TABLES IN SCHEMA public TO your_user;
```

### 问题2：外键约束

**错误**：`ERROR: cannot truncate a table referenced in a foreign key constraint`

**解决**：脚本已使用 CASCADE 自动处理，如果仍有问题，检查是否有循环引用

### 问题3：表不存在

**日志**：`table_truncate_failed: table xxx does not exist`

**原因**：表尚未创建或已被删除

**解决**：正常情况，脚本会跳过不存在的表

## 扩展说明

### 添加新表

如果添加了新的业务表，需要更新脚本中的 `BUSINESS_TABLES` 列表：

```python
BUSINESS_TABLES = [
    "users",
    "roadmap_tasks",
    # ... 现有表 ...
    "your_new_table",  # 添加新表
]
```

### 仅清空业务表

如果想保留 checkpoint 数据，修改 `include_checkpoints` 参数：

```python
result = await clear_all_tables(
    include_checkpoints=False,  # 不清空checkpoint表
    dry_run=False
)
```

### 演习模式

测试脚本而不实际删除数据：

```python
result = await clear_all_tables(
    include_checkpoints=True,
    dry_run=True  # 演习模式
)
```
