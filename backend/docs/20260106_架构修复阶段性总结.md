## ⏳ 待修复（5个违规点）

### 5. retry.py (4处违规)

**当前状态**: 688行，多处直接调用RoadmapRepository

**违规代码示例**:
```python
# 第89行
repo = RoadmapRepository(db)

# 第203行  
repo = RoadmapRepository(db)

# 第272行
task_repo = TaskRepository(db)

# 第387行
roadmap_repo = RoadmapRepository(db)
```

**问题分析**:
- API层包含大量业务逻辑（批量重试逻辑、任务状态管理等）
- 现有 `retry_service.py` 是后台函数，不是标准Service类
- 需要重构为标准Service + 简化API层

**修复计划**:
```python
# 新的 RetryService 结构
class RetryService:
    def __init__(self):
        self.roadmap_crud = RoadmapCRUD(RoadmapMetadata)
        self.task_crud = TaskCRUD(RoadmapTask)
        self.concept_crud = ConceptCRUD(ConceptMetadata)
    
    async def batch_retry_concepts(self, session, roadmap_id, concepts, preferences):
        """批量重试概念内容"""
        
    async def regenerate_concept_content(self, session, roadmap_id, concept_id, preferences):
        """重新生成概念内容"""
        
    async def retry_by_task_id(self, session, task_id, content_types):
        """基于任务ID重试"""
```

**预计工时**: 2小时

## 🔍 经验教训

### 为什么出现系统性违规？

1. **缺少强制检查**: 没有Pre-commit Hook检测架构违规
2. **快速开发优先**: 忽略了架构规范
3. **规范学习不足**: 对分层架构理解不深
4. **早期代码示例误导**: 旧代码就有违规，后续照抄

### 预防措施

1. **Pre-commit Hook**: 
```bash
# .git/hooks/pre-commit
if grep -r "Repository(" app/api/ --include="*.py"; then
    echo "❌ API层禁止直接调用Repository"
    exit 1
fi
```

2. **CI/CD检查**: 添加架构合规性检查步骤

3. **Code Review**: 所有PR必须验证分层架构

4. **团队培训**: 统一学习 `FastAPI_Enterprise_Architecture_Guide.md`
