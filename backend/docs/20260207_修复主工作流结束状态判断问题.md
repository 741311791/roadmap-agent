# 修复主工作流结束状态判断问题

**日期**: 2026-02-07  
**问题**: 主工作流结束后TaskStatus被错误地标记为`partial_failure`  
**影响范围**: 后端 - 工作流状态管理、任务状态更新  
**修复方案**: 完善状态判断逻辑，识别主工作流正常结束场景

---

## 一、问题描述

### 1.1 背景

项目采用**双工作流架构**：
- **主工作流**：意图分析 → 课程设计 → 验证 → (人工审核) → 框架生成完成
- **内容生成工作流**：独立的Celery Worker，主工作流完成后异步触发

### 1.2 问题现象

运行测试脚本`uv run python scripts/test_roadmap_generation.py`（环境变量`SKIP_HUMAN_REVIEW=true`）时：

1. **问题1**: 主工作流在`structure_validation`结束后，TaskStatus被标记为`partial_failure`
2. **问题2**: 逻辑混乱，主工作流结束 ≠ 整体任务完成

### 1.3 根本原因

**状态判断逻辑不完善**
```python
# 旧逻辑（workflow_execution_service.py）
if current_step == "human_review":
    status = TaskStatus.HUMAN_REVIEW
elif current_step == "completed":
    status = TaskStatus.COMPLETED
else:
    # ❌ 其他情况都被视为partial_failure
    status = TaskStatus.PARTIAL_FAILURE
```

当`SKIP_HUMAN_REVIEW=true`且工作流正常结束时，`current_step`仍是`structure_validation`，被错误地判断为`partial_failure`。

---

## 二、解决方案

### 2.1 完善状态判断逻辑（workflow_execution_service.py）

#### 修改前
```python
if current_step == "human_review":
    status = TaskStatus.HUMAN_REVIEW
elif current_step == "completed":
    status = TaskStatus.COMPLETED
else:
    status = TaskStatus.PARTIAL_FAILURE  # ❌ 主工作流正常结束也被视为失败
```

#### 修改后
```python
if current_step == "human_review":
    # 工作流暂停在人工审核
    status = TaskStatus.HUMAN_REVIEW
elif current_step == "structure_validation" and roadmap_id:
    # ✅ 主工作流在验证阶段正常结束
    # 场景1: 验证通过且SKIP_HUMAN_REVIEW=true
    # 场景2: 验证失败但达到最大重试次数且SKIP_HUMAN_REVIEW=true
    # 路线图框架已生成，保持PROCESSING等待内容生成
    status = TaskStatus.PROCESSING
    success = True
elif current_step == "completed":
    # 整体任务完成（框架 + 内容生成都完成）
    status = TaskStatus.COMPLETED
else:
    # 真正的异常中断
    status = TaskStatus.PARTIAL_FAILURE
```

## 六、核心设计原则

### 6.1 双工作流架构

```
┌─────────────────────────────────────────────────────┐
│           主工作流（框架生成）                          │
│  Intent → Curriculum → Validation → Review → END    │
│                                              ↓       │
│                                    current_step =    │
│                                    framework_completed│
└─────────────────────────────────────────────────────┘
                        ↓ 触发
┌─────────────────────────────────────────────────────┐
│         内容生成工作流（独立Celery Worker）              │
│    Tutorial Generation → Resource Generation         │
│             → Quiz Generation → END                  │
│                                  ↓                   │
│                        TaskStatus = COMPLETED        │
└─────────────────────────────────────────────────────┘
```

### 6.2 TaskStatus的含义

| TaskStatus | 含义 | 触发时机 |
|-----------|------|---------|
| `pending` | 任务排队中 | 任务创建时 |
| `processing` | 任务执行中 | 任务开始执行 / 主工作流完成 |
| `human_review` | 等待人工审核 | 工作流暂停在human_review节点 |
| `completed` | 整体任务完成 | 主工作流 + 内容生成 都完成 |
| `failed` | 任务失败 | 发生不可恢复的错误 |
| `partial_failure` | 部分失败 | 工作流异常中断（非正常结束） |

**关键点**:
- **主工作流完成 → TaskStatus = PROCESSING**（不是COMPLETED）
- **内容生成完成 → TaskStatus = COMPLETED**
- **partial_failure** 仅用于真正的异常情况（不是正常结束路径）

## 八、总结

本次修复通过完善状态判断逻辑，正确识别主工作流正常结束的场景，解决了TaskStatus被错误标记为`partial_failure`的问题。

**核心改进**:
1. ✅ 识别`current_step="structure_validation" + roadmap_id存在`为主工作流正常结束
2. ✅ 主工作流结束时，TaskStatus保持为`PROCESSING`（等待内容生成）
3. ✅ 只有内容生成完成后，TaskStatus才更新为`COMPLETED`
4. ✅ `partial_failure`仅用于真正的异常中断（如工作流崩溃）

**设计原则**:
- **充分利用LangGraph内置的END节点**，无需额外添加结束节点
- **通过current_step + roadmap_id判断**主工作流是否正常完成
- **保持状态枚举简洁**，不增加额外的current_step值

这个方案更简洁，充分利用了LangGraph的原生机制，同时正确反映了双工作流架构的设计意图。
