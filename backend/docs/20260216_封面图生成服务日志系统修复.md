# 封面图生成服务日志系统修复

## 问题背景

在执行封面图生成测试脚本时发现两个错误：

1. **Logger 类型错误**
   - 错误信息：`Logger._log() got an unexpected keyword argument 'roadmap_id'`
   - 根本原因：使用了标准库的 `logging` 而不是 `structlog`

2. **测试脚本属性错误**
   - 错误信息：`'RoadmapCoverImage' object has no attribute 'id'`
   - 根本原因：访问了不存在的属性（该模型使用 `roadmap_id` 作为主键）

## 问题分析

### 问题1：Logger 类型不匹配

**原代码**:
```python
import logging
logger = logging.getLogger(__name__)

# 使用结构化参数调用（标准 logging 不支持）
logger.info(
    "cover_image_already_exists_skip_generation",
    roadmap_id=roadmap_id,
    url=cover_image.cover_image_url,
)
```

**问题**:
- 标准库的 `logging.Logger` 不支持关键字参数传递
- 只支持字符串格式化的日志消息
- 导致运行时 TypeError

### 问题2：数据库模型理解错误

**模型定义**:
```python
class RoadmapCoverImage(SQLModel, table=True):
    roadmap_id: str = Field(
        primary_key=True,  # ✅ roadmap_id 是主键
        description="路线图ID（主键）"
    )
    # ❌ 没有 id 字段
```

**测试脚本错误**:
```python
print(f"ID: {cover_image.id}")  # ❌ 访问不存在的属性
```

## 解决方案

### 修复1：统一使用 structlog

**文件**: `backend/app/services/roadmaps/cover_image_service.py`

#### 修改导入
```python
# ❌ 修改前
import logging
logger = logging.getLogger(__name__)

# ✅ 修改后
import structlog
logger = structlog.get_logger()
```

#### 修改日志调用格式

**修改前（f-string 格式）**:
```python
logger.info(f"开始生成封面图: roadmap_id={roadmap_id}, prompt={prompt}")
logger.error(f"路线图不存在: roadmap_id={roadmap_id}")
logger.error(f"封面图生成失败: roadmap_id={roadmap_id}, {error_msg}")
```

**修改后（结构化日志格式）**:
```python
logger.info("cover_image_generation_started", roadmap_id=roadmap_id, prompt=prompt)
logger.error("roadmap_not_found", roadmap_id=roadmap_id)
logger.error("cover_image_generation_failed", roadmap_id=roadmap_id, error=error_msg)
```

#### 完整修改列表

| 原日志消息 | 新事件名称 | 参数 |
|---|---|---|
| `开始生成封面图` | `cover_image_generation_started` | `roadmap_id`, `prompt` |
| `路线图不存在` | `roadmap_not_found` | `roadmap_id` |
| `封面图生成成功` | `cover_image_generation_success` | `roadmap_id`, `url` |
| `封面图生成失败` | `cover_image_generation_failed` | `roadmap_id`, `error` |
| `封面图生成失败: 请求超时` | `cover_image_generation_timeout` | `roadmap_id`, `error` |
| `封面图生成失败: HTTP 错误` | `cover_image_generation_http_error` | `roadmap_id`, `error` |
| `封面图生成失败: 未知错误` | `cover_image_generation_unknown_error` | `roadmap_id`, `error` |

## 技术规范说明

### Structlog vs Logging

**标准 logging**:
```python
import logging
logger = logging.getLogger(__name__)

# 只支持字符串格式化
logger.info("User %s logged in", username)
logger.info(f"User {username} logged in")  # f-string
```

**Structlog**:
```python
import structlog
logger = structlog.get_logger()

# 支持结构化参数（推荐）
logger.info("user_logged_in", username=username, ip=request.ip)

# 也支持 f-string（但不推荐）
logger.info(f"User {username} logged in")
```

### Structlog 优势

1. **结构化日志**
   - 自动转换为 JSON 格式
   - 易于日志聚合系统解析

2. **上下文绑定**
   ```python
   log = logger.bind(request_id=req_id, user_id=user_id)
   log.info("operation_started")  # 自动包含 request_id 和 user_id
   ```

3. **类型安全**
   - 参数以关键字形式传递
   - 避免字符串拼接错误

4. **性能优化**
   - 延迟格式化
   - 条件日志输出

### 日志命名规范

**事件名称**（推荐格式）:
- 使用 `snake_case`
- 动词_名词_结果：`cover_image_generation_started`
- 清晰描述事件类型

**参数名称**:
- 使用 `snake_case`
- 保持一致性：`roadmap_id`（不是 `id` 或 `RoadmapId`）

## 最佳实践总结

### 1. 日志系统选择
- ✅ **推荐**：在项目中统一使用 `structlog`
- ❌ **避免**：混用 `logging` 和 `structlog`

### 2. 日志调用格式
```python
# ✅ 推荐（结构化参数）
logger.info("event_name", param1=value1, param2=value2)

# ⚠️ 可用但不推荐（f-string）
logger.info(f"Event: {value1}, {value2}")

# ❌ 避免（字符串拼接）
logger.info("Event: " + str(value1))
```

### 3. 异常日志
```python
# ✅ 推荐（包含异常堆栈）
try:
    ...
except Exception as e:
    logger.exception("error_event", error=str(e), context=...)

# ❌ 避免（丢失堆栈信息）
except Exception as e:
    logger.error(f"Error: {e}")
```

### 4. 数据库模型访问
```python
# ✅ 推荐（检查属性是否存在）
if hasattr(model, 'id'):
    print(model.id)

# ✅ 推荐（使用已知的主键）
print(model.roadmap_id)  # 明确知道这是主键

# ❌ 避免（盲目访问可能不存在的属性）
print(model.id)  # 如果不确定，会导致 AttributeError
```
