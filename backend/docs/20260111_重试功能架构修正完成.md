## 一、问题发现

### 1.1 用户反馈

用户指出：

> 重试服务分为两种：
> 1. **断点续传**：根据现有的checkpoint日志继续执行
> 2. **时间旅行**：可以自定义回溯到之前任何一个节点继续执行

### 1.2 初版实现的问题

**❌ 错误的阶段级重试实现**：

```python
# 错误：直接修改当前状态，而不是回到历史checkpoint
async def _retry_from_stage(self, ...):
    config = {"configurable": {"thread_id": task_id}}
    
    # 问题1: 没有使用get_state_history()获取历史
    # 问题2: 直接修改当前状态，而不是回到过去
    await executor.graph.aupdate_state(config, values=reset_values)
    
    # 问题3: 没有传递checkpoint_id
    await resume_from_checkpoint.delay(task_id)  # 缺少checkpoint_id
```

**根本问题**：
- 混淆了"修改当前状态"和"回到历史状态"
- 没有使用 `get_state_history()` 查找历史checkpoint
- 不符合LangGraph的时间旅行最佳实践

## 二、官方最佳实践（参考资料）

### 2.1 官方文档

根据[LangGraph官方文档](https://docs.langchain.com/oss/python/langgraph/use-time-travel)：

**时间旅行的正确流程**：

1. **获取历史checkpoint列表**：
   ```python
   states = list(graph.get_state_history(config))
   ```

2. **选择特定checkpoint**：
   ```python
   selected_state = states[1]  # 倒序，选择第二个
   ```

3. **（可选）修改状态**：
   ```python
   new_config = graph.update_state(
       selected_state.config,  # ← 包含checkpoint_id
       values={"topic": "chickens"}
   )
   ```

4. **从该checkpoint恢复**：
   ```python
   graph.invoke(None, new_config)
   ```

### 2.2 断点续传 vs 时间旅行

| 特性 | 断点续传 | 时间旅行 |
|-----|---------|---------|
| checkpoint选择 | 自动（最后一个） | 手动（指定checkpoint_id） |
| `get_state_history()` | ❌ 不需要 | ✅ 必需 |
| checkpoint_id参数 | ❌ 不传递 | ✅ 必须传递 |
| 配置示例 | `{"thread_id": "..."}` | `{"thread_id": "...", "checkpoint_id": "..."}` |

## 三、修正方案

### 3.1 修正后的阶段级重试实现

**✅ 正确实现**（符合LangGraph最佳实践）：

```python
async def _retry_from_stage(self, task_id, stage, ...):
    """从特定阶段重新开始（时间旅行模式）"""
    
    # ===== 步骤1: 获取历史checkpoint列表 =====
    states = []
    async for state in executor.graph.aget_state_history(config):
        states.append(state)
    
    logger.info(
        "checkpoint_history_fetched",
        task_id=task_id,
        total_checkpoints=len(states),
    )
    
    # ===== 步骤2: 找到目标阶段的checkpoint =====
    target_checkpoint = None
    for state in states:
        if state.values.get("current_step") == stage:
            target_checkpoint = state
            break
    
    if not target_checkpoint:
        raise ValueError(f"未找到阶段 {stage} 的checkpoint")
    
    checkpoint_id = target_checkpoint.config["configurable"]["checkpoint_id"]
    
    logger.info(
        "resuming_from_checkpoint",
        task_id=task_id,
        checkpoint_id=checkpoint_id,
        target_stage=stage,
    )
    
    # ===== 步骤3: 从该checkpoint恢复（时间旅行） =====
    celery_task = resume_from_checkpoint.delay(
        task_id,
        checkpoint_id=checkpoint_id  # ✅ 关键：传递checkpoint_id
    )
```

### 3.2 Celery任务增强

**更新 `resume_from_checkpoint` 任务以支持checkpoint_id**：

```python
@celery_app.task(...)
def resume_from_checkpoint(
    self,
    task_id: str,
    checkpoint_id: Optional[str] = None,  # ✅ 新增参数
) -> dict:
    """
    支持两种模式：
    1. 断点续传（checkpoint_id=None）：从最后checkpoint恢复
    2. 时间旅行（checkpoint_id指定）：从特定checkpoint恢复
    """
    result = run_async(
        _resume_workflow_from_checkpoint(
            task_id=task_id,
            celery_task_id=self.request.id,
            checkpoint_id=checkpoint_id,  # ✅ 传递checkpoint_id
        )
    )
```

**异步执行函数**：

```python
async def _resume_workflow_from_checkpoint(
    task_id: str,
    celery_task_id: str,
    checkpoint_id: Optional[str] = None,  # ✅ 新增参数
) -> dict:
    """从checkpoint恢复工作流"""
    
    config = {"configurable": {"thread_id": task_id}}
    
    # 如果提供了checkpoint_id，添加到config（时间旅行模式）
    if checkpoint_id:
        config["configurable"]["checkpoint_id"] = checkpoint_id  # ✅ 关键
        logger.info("time_travel_mode_enabled", checkpoint_id=checkpoint_id)
    
    # 从checkpoint恢复
    final_state = await executor.graph.ainvoke(None, config=config)
```

## 八、性能影响

### 8.1 时间复杂度

| 操作 | 修正前 | 修正后 | 说明 |
|-----|-------|-------|------|
| 任务级重试 | O(1) | O(1) | 无变化 |
| 阶段级重试 | O(1) | O(n) | n=checkpoint数量，通常<10 |

**分析**：
- 阶段级重试需要遍历checkpoint历史，但数量很少（通常<10个）
- 性能影响可忽略不计
- 正确性优先于性能

### 8.2 空间复杂度

- 修正前：O(1) - 仅保存当前状态
- 修正后：O(n) - 需要加载历史checkpoint列表
- 影响：可忽略（checkpoint元数据很小）
