## 一、异步API规范

### 1.1 强制使用异步API

我们的架构是**全异步**的（FastAPI + async/await + asyncpg），所有LangGraph调用必须使用异步版本：

| ❌ 同步API（禁止） | ✅ 异步API（强制） | 说明 |
|------------------|------------------|------|
| `graph.invoke()` | `await graph.ainvoke()` | 执行图 |
| `graph.stream()` | `async for chunk in graph.astream()` | 流式执行 |
| `graph.get_state()` | `await graph.aget_state()` | 获取状态 |
| `graph.get_state_history()` | `async for state in graph.aget_state_history()` | 获取历史 |
| `graph.update_state()` | `await graph.aupdate_state()` | 更新状态 |

### 1.2 为什么必须全异步？

```python
# ❌ 错误：同步调用会阻塞事件循环
@router.post("/retry/{task_id}")
async def retry_task(...):
    # 这会阻塞整个FastAPI进程！
    result = graph.invoke(None, config)  # 同步调用
    return result

# ✅ 正确：异步调用不阻塞
@router.post("/retry/{task_id}")
async def retry_task(...):
    # FastAPI可以处理其他请求
    result = await graph.ainvoke(None, config)  # 异步调用
    return result
```

**影响**：
- 同步调用会阻塞整个事件循环
- 其他请求无法处理（吞吐量骤降）
- 数据库连接池耗尽

## 二、性能优化：流式查找checkpoint

### 2.1 问题：两次遍历的低效方式

```python
# ❌ 低效实现（两次遍历）
async def _time_travel_to_node(self, task_id, target_node):
    # 第一次遍历：收集所有历史（可能有几十上百个）
    states = []
    async for state in graph.aget_state_history(config):
        states.append(state)  # O(n)
    
    logger.info(f"获取了 {len(states)} 个checkpoint")
    
    # 第二次遍历：查找目标
    for state in states:  # O(n)
        if state.values.get("current_step") == target_node:
            checkpoint_id = state.config["configurable"]["checkpoint_id"]
            break
```

**问题分析**：
- 时间复杂度：O(2n)
- 空间复杂度：O(n) - 需要存储所有checkpoint
- 数据库压力：一次性加载所有历史记录
- 内存占用：checkpoint数据可能很大

### 2.2 优化：流式查找，找到即停止

```python
# ✅ 高效实现（流式查找）
async def _time_travel_to_node(self, task_id, target_node):
    checkpoint_id = None
    iteration_count = 0
    
    # 流式遍历：找到即停止
    async for state in graph.aget_state_history(config):
        iteration_count += 1
        
        if state.values.get("current_step") == target_node:
            checkpoint_id = state.config["configurable"]["checkpoint_id"]
            logger.info(
                "checkpoint_found",
                task_id=task_id,
                iterations=iteration_count,  # 通常只需3-5次
            )
            break  # ✅ 立即停止，不再继续
    
    if not checkpoint_id:
        logger.warning(
            "checkpoint_not_found",
            task_id=task_id,
            target_node=target_node,
            total_iterations=iteration_count,
        )
        raise ValueError(f"未找到目标节点 {target_node} 的checkpoint")
```

**优化效果**：
- 时间复杂度：O(k)，k为找到目标前遍历的checkpoint数量
- 空间复杂度：O(1) - 不需要存储历史
- 实际性能：如果目标在最近3个checkpoint内，仅需3次迭代

### 2.3 性能对比

| 场景 | 低效方式 | 高效方式 | 提升 |
|------|---------|---------|------|
| checkpoint总数=50，目标在第3个 | 遍历50+3=53次 | 遍历3次 | **17.6x** |
| checkpoint总数=100，目标在第5个 | 遍历100+5=105次 | 遍历5次 | **21x** |
| checkpoint总数=20，目标在第2个 | 遍历20+2=22次 | 遍历2次 | **11x** |

**结论**：流式查找在绝大多数场景下提供10-20倍的性能提升。

## 三、进一步优化方案

### 3.1 限制历史查询深度

```python
# 如果确信目标在最近的N个checkpoint内
max_depth = 20  # 只查询最近20个

checkpoint_id = None
iteration_count = 0

async for state in graph.aget_state_history(config):
    iteration_count += 1
    
    if state.values.get("current_step") == target_node:
        checkpoint_id = state.config["configurable"]["checkpoint_id"]
        break
    
    if iteration_count >= max_depth:
        logger.warning(
            "checkpoint_search_depth_exceeded",
            task_id=task_id,
            max_depth=max_depth,
        )
        break  # 防止无限遍历
```

### 3.2 多条件查找（提前退出）

```python
# 支持多个目标节点，找到任意一个即可
target_nodes = ["intent_analysis", "intent"]  # 节点名称可能有别名

async for state in graph.aget_state_history(config):
    current_step = state.values.get("current_step", "")
    
    if current_step in target_nodes:  # ✅ 找到任意匹配即退出
        checkpoint_id = state.config["configurable"]["checkpoint_id"]
        logger.info(
            "checkpoint_found",
            matched_node=current_step,
            target_nodes=target_nodes,
        )
        break
```

### 3.3 缓存checkpoint映射（可选）

```python
# 对于频繁查询的任务，缓存checkpoint信息到Redis
async def _get_checkpoint_id_with_cache(
    self,
    task_id: str,
    target_node: str,
) -> str:
    # 1. 尝试从Redis获取缓存
    cache_key = f"checkpoint:{task_id}:{target_node}"
    cached_id = await redis_client.get(cache_key)
    
    if cached_id:
        logger.info("checkpoint_cache_hit", task_id=task_id)
        return cached_id
    
    # 2. 缓存未命中，流式查找
    checkpoint_id = None
    async for state in graph.aget_state_history(config):
        if state.values.get("current_step") == target_node:
            checkpoint_id = state.config["configurable"]["checkpoint_id"]
            
            # 3. 缓存结果（TTL=1小时）
            await redis_client.setex(cache_key, 3600, checkpoint_id)
            logger.info("checkpoint_cached", task_id=task_id)
            break
    
    return checkpoint_id
```

1. **设置超时**：
   ```python

       logger.error("checkpoint_search_timeout", task_id=task_id)

   ```

2. **Prometheus指标**：
