# Handler输入验证失败根源修复

## 问题表象

所有Handler在执行时都报"输入验证失败"错误：

```
validation_errors=[
    {'type': 'missing', 'loc': ('intent_analysis',), 'msg': 'Field required'},
    {'type': 'string_type', 'loc': ('roadmap_id',), 'msg': 'Input should be a valid string', 'input': None},
    {'type': 'missing', 'loc': ('user_id',), 'msg': 'Field required'}
]
```

Handler期望的输入：
```python
{
    "intent_analysis": IntentAnalysisOutput,
    "roadmap_id": str,
    "user_id": str
}
```

实际收到的数据：
```python
{
    "parsed_goal": "6个月内系统掌握...",
    "key_technologies": ["Python", "HTML", ...],
    ...
}
```

这些字段（`parsed_goal`, `key_technologies`等）是`IntentAnalysisOutput`的**内部字段**！

## 深入分析问题根源

### 第一步：Node确实返回了完整的字典

检查`intent_analysis_node.py`：
```python
return {
    "intent_analysis": result,  # IntentAnalysisOutput对象
    "roadmap_id": result.roadmap_id,
    "user_id": user_request.user_id,
    "execution_history": ["需求分析完成"],
}
```

### 第二步：event.data.output不可靠

我们使用的是`astream_events()`监听节点生命周期：
```python
async for event in self.graph.astream_events(...):
    node_output = event.get("data", {}).get("output", {})
```

**关键问题**：`event.data.output`可能不是Node返回的完整字典！

根据LangGraph文档和实际行为：
- `astream_events()`主要用于监听Langchain内部事件（LLM调用、Tool调用）
- 它的`event.data.output`可能是：
  - State中某个字段的值（而不是Node返回的完整字典）
  - 经过序列化/处理的数据片段
  - 不保证包含Node的完整返回值

### 第三步：为什么Handler收到的是IntentAnalysisOutput的字段？

**推测**：`event.data.output`返回的可能是State中`intent_analysis`字段的值：

1. Node返回：`{"intent_analysis": result, "roadmap_id": xxx, "user_id": yyy}`
2. LangGraph将这些字段merge到State中
3. `event.data.output`可能只返回了State中某个字段（比如`intent_analysis`）
4. `_deep_convert_to_dict()`将`IntentAnalysisOutput`对象转换成字典
5. Handler收到的就是`{parsed_goal, key_technologies, ...}`

## 正确的解决方案

### 需求分析

你的需求是：
1. ✅ 需要在节点**启动前**发送通知、更新数据库
2. ✅ 需要在节点**结束后**获取完整数据、调用Handler

### 解决方案：继续使用astream_events()，但改用aget_state()获取数据

**核心策略**：
- 保持使用`astream_events()`监听`on_chain_start`和`on_chain_end`
- 在`on_chain_start`时发送通知
- 在`on_chain_end`时**不使用`event.data.output`**
- 改用**`aget_state(config).values`**获取完整的State

### 代码实现

```python
async for event in self.graph.astream_events(...):
    if event_type == "on_chain_start":
        # ✅ 节点启动：发送通知、更新数据库
        await self.coordinator.on_node_start(task_id, node_name, ...)
    
    elif event_type == "on_chain_end":
        # ❌ 不使用 event.data.output（不完整）
        # node_output = event.get("data", {}).get("output", {})
        
        # ✅ 通过 aget_state() 获取完整State
        state_snapshot = await self.graph.aget_state(config)
        complete_state = state_snapshot.values  # 这是完整的State！
        
        # ✅ 使用完整State作为Handler输入
        handler_input = _deep_convert_to_dict(complete_state)
        await handler_registry.handle(node_name, handler_input, ...)
```

## 为什么之前能运行，现在不行？

可能的原因（待验证）：
1. LangGraph版本升级改变了`event.data.output`的行为
2. 最近修改了Node的返回值结构
3. Pydantic版本升级导致序列化行为变化
4. State定义的某些改动影响了数据流

## 优势

1. **保持了节点启动前的事件监听**：满足你的需求
2. **获取了完整的State数据**：从checkpoint读取，保证完整性
3. **不依赖event.data.output的不确定性**：使用更可靠的aget_state() API
4. **容易调试**：添加了详细的对比日志
5. **向后兼容**：继续使用astream_events()，只改变数据获取方式
