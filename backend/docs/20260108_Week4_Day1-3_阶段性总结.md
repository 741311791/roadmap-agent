## 🔍 发现的核心挑战

### 挑战1: RepositoryFactory模式

**问题**: 3个文件使用 `RepositoryFactory`，而不是直接导入Repository

**影响文件**:
1. **roadmap_service.py** - 核心服务，使用RepositoryFactory
2. **retry_service.py** - 重试服务，使用RoadmapRepository
3. **celery_session.py** - Celery专用，创建所有Repository实例

**示例**:
```python
# roadmap_service.py
class RoadmapService:
    def __init__(self, repo_factory: RepositoryFactory, ...):
        self.repo_factory = repo_factory
    
    async def some_method(...):
        async with self.repo_factory.create_session() as session:
            repo = self.repo_factory.create_roadmap_repo(session)
            result = await repo.some_operation()
```

**迁移策略**:
```python
# ✅ 迁移后
class RoadmapService:
    def __init__(self):
        self.roadmap_crud = RoadmapCRUD(RoadmapMetadata)
        self.task_crud = TaskCRUD(RoadmapTask)
    
    async def some_method(session: AsyncSession, ...):
        result = await self.roadmap_crud.some_operation(session, ...)
```

**工作量**: 约3小时（需要重构服务接口）

### 挑战2: CeleryRepositoryFactory

**问题**: celery_session.py 包含9个Repository导入和实例化逻辑

**影响文件**:
- celery_session.py（核心，~300行）
- content_generation_tasks.py
- concept_generator.py
- content_retry_tasks.py

**复杂度**: 
- 涉及Celery任务的Session管理
- 需要保证Fork进程安全
- 影响所有Celery任务

**迁移策略**:
```python
# app/db/celery_session.py

class CeleryRepositoryFactory:
    """Celery专用Repository工厂"""
    
    # ❌ 旧代码
    def create_roadmap_repo(self, session):
        from app.db.repositories.roadmap_repo import RoadmapRepository
        return RoadmapRepository(session)
    
    # ✅ 新代码
    def get_roadmap_crud(self):
        from app.crud.crud_roadmap import get_roadmap_crud
        return get_roadmap_crud()
```

**工作量**: 约2小时
