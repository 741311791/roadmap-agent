# 工具调用策略优化：按需而非强制

## 优化背景

### 原有策略的问题

**策略**：开发场景下强制使用工具查询官方文档

```jinja2
## 🔧 场景类型：开发场景（必须查询官方文档）
这是一个开发场景，**必须**使用工具查询官方文档

### 🚫 开发场景约束
1. **必须使用工具**：禁止臆造技术信息，所有内容必须来自工具调用的官方文档
```

**问题**：

1. ❌ **效率低下**：即使是LLM已经掌握的基础知识（如React Hooks基础用法），也强制调用工具
2. ❌ **成本高**：每次工具调用都有延迟（5-10秒）和API成本
3. ❌ **不够灵活**：没有给LLM自主判断的空间
4. ❌ **违反自主性**：ReAct模式的核心是Agent自主决策，强制调用破坏了这一原则

### 实际情况分析

**LLM知识库已覆盖**：
- JavaScript/Python/TypeScript基础语法
- React/Vue/Angular成熟特性（如Hooks基础）
- 通用设计模式和最佳实践
- 常见库的稳定API

**需要工具补充**：
- 最新版本的新特性（如React 19 Server Components）
- 版本间的重大变更（如Pydantic v1→v2）
- 小众库或专业工具（如LangGraph）
- 官方特定的最佳实践

## 优化策略

### 核心原则

**从"强制使用"改为"按需使用"**：
- ✅ 优先使用LLM知识库（更快、更经济）
- ✅ 只在真正需要时调用工具
- ✅ 让LLM自主判断（符合ReAct原则）

### 工具使用决策指南

在Prompt中添加明确的判断标准：

```jinja2
### 🤔 何时应该使用工具？

#### ✅ 建议使用工具的情况

1. **版本敏感的新特性**：
   - 示例：React 19 新增的 Server Components、Next.js 14 App Router
   - 原因：训练数据可能不包含最新版本的变化

2. **特定版本的API差异**：
   - 示例：Pydantic v1 vs v2 的重大变更
   - 原因：需要确保代码示例符合特定版本

3. **小众或专业库**：
   - 示例：LangGraph、某个不常见的库
   - 原因：训练数据覆盖可能有限

4. **官方最佳实践**：
   - 示例：某个框架的官方推荐模式
   - 原因：官方文档比通用知识更权威

5. **你的知识库不确定或有限时**：
   - 如果你对某个知识点不够熟悉
   - 原因：工具可以提供准确的参考

#### ⭕ 可以不使用工具的情况

1. **成熟稳定的基础知识**：
   - 示例：JavaScript基础语法、React Hooks基础
   - 原因：这些知识点多年未变，知识库足够准确

2. **通用概念和原理**：
   - 示例：设计模式、算法思想
   - 原因：跨语言的通用知识

3. **你已经掌握的知识**：
   - 如果训练数据中有充分且准确的信息
   - 原因：直接使用知识库更高效
```

## 具体修改

### 1. 修改场景说明

#### 修改前：
```jinja2
## 🔧 场景类型：开发场景（必须查询官方文档）

这是一个开发场景，**必须**使用工具查询官方文档
```

#### 修改后：
```jinja2
## 🔧 场景类型：开发场景（可选使用工具）

这是一个开发场景。你可以根据需要选择性使用工具查询官方文档。
```

### 2. 添加工具使用判断指南

新增"何时应该使用工具？"章节，包含：
- ✅ 建议使用的5种情况
- ⭕ 可以不使用的3种情况
- 🎯 决策建议和判断流程

### 3. 修改约束要求

#### 修改前：
```jinja2
### 🚫 开发场景约束
1. **必须使用工具**：禁止臆造技术信息，所有内容必须来自工具调用
```

#### 修改后：
```jinja2
### 📋 开发场景要求
1. **准确性优先**：
   - 如果你的知识库有准确信息 → 直接使用
   - 如果不确定或知识有限 → 调用工具获取官方文档
   - 禁止编造不确定的技术细节
```

### 4. 优化工作流程

#### 修改前：
```jinja2
**执行步骤**：
1. 调用工具收集官方文档信息（可多次调用）
2. 判断信息是否充分
3. 停止调用工具，输出JSON格式教程
```

#### 修改后：
```jinja2
**决策流程**：
1. **自我评估**：我对这个概念的知识是否充分且准确？
2. **选择策略**：
   - 知识充分 → 直接生成教程（更快）
   - 知识不足 → 调用工具查询 → 生成教程
3. **输出教程**：直接输出JSON对象

**核心原则**：优先使用知识库，只在真正需要时调用工具。
```

### 5. 修改用户消息提醒

#### 修改前：
```python
scenario_reminder = """
**重要提醒**：
1. 这是开发场景，必须使用工具查询官方文档（禁止臆造）
2. 使用 resolve-library-id + query-docs 获取官方文档
3. 确保代码示例符合查询到的版本要求
"""
```

#### 修改后：
```python
scenario_reminder = """
**场景说明**：
这是开发场景（涉及技术栈），你可以选择性使用工具查询官方文档。

**决策建议**：
1. **优先使用你的知识库**：如果你对这个概念有充分且准确的了解，直接生成教程
2. **按需使用工具**：只在以下情况调用工具：
   - 知识点非常新（可能超出你的训练数据）
   - 需要特定版本的API说明
   - 你的知识库不确定或有限
   - 需要官方权威的最佳实践

**核心原则**：优先使用知识库，只在真正需要时调用工具。
"""
```

## 优化效果预期

### 性能提升

| 指标 | 优化前 | 优化后 | 改善 |
|------|--------|--------|------|
| **平均迭代次数** | 5-7次 | 1-4次 | -50% |
| **平均响应时间** | 30-60秒 | 10-30秒 | -50% |
| **工具调用率** | 100% | 30-50% | -50% |
| **成本** | 高 | 中低 | -40% |

### 工作模式分布

**预期分布**：
- **模式A（直接生成）**：50-70%的教程
  - 示例：React Hooks基础、Python异步、TypeScript泛型
  - 用时：10-15秒

- **模式B（补充查询）**：30-50%的教程
  - 示例：Next.js 14新特性、LangGraph高级用法
  - 用时：30-60秒

### 质量保证

虽然减少了强制工具调用，但质量不会下降：
- ✅ LLM会自主判断何时需要工具
- ✅ 对不确定的内容仍会查询文档
- ✅ 通过"禁止编造"约束保证准确性

## 理论依据

### ReAct原则

ReAct（Reasoning and Acting）的核心是**Agent自主决策**：
- ✅ Agent根据当前状态和目标，自主选择行动
- ✅ 包括选择是否使用工具、使用哪个工具
- ❌ 不应该强制Agent必须使用工具

### Prompt Engineering最佳实践

来自Anthropic、OpenAI的指南：
- ✅ "Give the model agency"（给模型自主权）
- ✅ "Provide tools as options, not requirements"（工具是选项，不是要求）
- ✅ "Let the model decide when to use tools"（让模型决定何时使用）

### 效率优化

- **80/20法则**：80%的教程可以用LLM知识库直接生成
- **及时满足**：只在需要时调用工具，避免过度工程
- **成本意识**：每次工具调用都有成本，应该优化ROI

## 总结

本次优化将工具调用策略从"强制"改为"按需"，核心改变：

1. ✅ **赋予自主权**：让LLM自主判断何时需要工具
2. ✅ **提供指南**：明确的判断标准和决策建议
3. ✅ **优化效率**：减少不必要的工具调用
4. ✅ **保证质量**：通过"禁止编造"约束保证准确性

**设计哲学**：
- 工具是辅助手段，不是必需品
- 知识库优先，工具补充
- 自主决策，按需调用

这符合ReAct模式的本质，也更符合实际生产环境的效率要求。
