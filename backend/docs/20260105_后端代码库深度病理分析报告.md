## 📊 风险评级矩阵

| 模块 | 风险描述 | 等级 | 后果推演 |
|------|---------|------|---------|
| **Celery 异步池** | 使用 `celery-pool-asyncio` 而非推荐的 `celery-aio-pool` | ⚠️警告 | `celery-pool-asyncio` 维护不活跃，可能导致异步任务执行不稳定，Worker 内存泄漏 |
| **序列化性能** | 未使用 `msgspec`，依赖 `json`/`pydantic` | ⚠️警告 | 大文本教程序列化时性能损失 5-10 倍，高并发下成为瓶颈 |
| **中间件顺序** | `RequestIDMiddleware` 在 `CORSMiddleware` 之前注册 | ⚠️警告 | CORS 预检请求可能被错误处理，跨域请求 TraceID 可能丢失 |
| **WebSocket 鉴权** | WebSocket 端点无 Token 验证 | 🔥高危 | 任意用户可订阅任意 task_id 的进度，存在信息泄露风险 |
| **JWT 黑名单** | 无 Redis 黑名单机制（强制登出） | ⚠️警告 | 无法立即撤销已签发的 Token，用户账号被盗后风险窗口为 Token 有效期（24小时） |
| **Session 读写分离** | 未严格区分 `CurrentSession` (读) 和 `CurrentSessionTransaction` (写) | ⚠️警告 | 读操作可能意外触发事务提交，事务边界不清晰 |
| **内存状态缓存** | `StateManager.live_step` 使用内存 dict | ⚠️警告 | 多实例部署时状态不同步，无法水平扩展 |
| **API 层业务逻辑** | `generation.py` 包含 `_execute_roadmap_generation_task` 等业务逻辑 | ℹ️建议 | 违反分层原则，API 层职责不纯，测试困难 |
| **Service 层返回 ORM** | 部分 Service 方法直接返回 ORM Model | ℹ️建议 | 违反分层原则，API 层与数据库模型耦合 |
| **统一会话管理** | 部分代码直接使用 `AsyncSessionLocal()` 而非 DI | ⚠️警告 | 事务边界不统一，连接泄漏风险 |
| **Redis AOF 未验证** | Redis 配置中未明确 AOF 持久化 | ⚠️警告 | 使用云服务（Upstash）时需确认持久化配置，否则 Celery 任务可能丢失 |
| **LangGraph 连接池隔离** | Checkpointer 使用独立连接池，与主 DB 连接池分离 | ℹ️建议 | 总连接数计算需包含两个池，可能超出数据库连接限制 |
| **N+1 查询风险** | 路线图加载时未使用 `selectinload` | ⚠️警告 | 获取完整路线图时可能产生 N+1 查询，影响性能 |
| **全局异常处理** | `generic_exception_handler` 捕获所有异常 | ✅良好 | 已实现，错误信息正确脱敏 |
| **连接池监控** | 已实现 Prometheus 指标和慢查询追踪 | ✅良好 | 可观测性良好 |
| **事件循环感知** | 已实现 engine 缓存和 Worker 进程初始化钩子 | ✅良好 | 正确处理了 Celery prefork 模式的连接隔离 |

#### 1.1 🔐 WebSocket Token 鉴权 [P0-Critical]

**问题**：当前 WebSocket 端点 `/ws/{task_id}` 无任何鉴权，任意用户可订阅任意任务进度。

**修复方案**：

```python
# app/api/v1/websocket.py

from app.core.auth.deps import get_optional_user_ws
from jose import jwt, JWTError

@router.websocket("/ws/{task_id}")
async def websocket_endpoint(
    websocket: WebSocket,
    task_id: str,
    token: str = Query(None, description="JWT Token"),
):
    """
    WebSocket 端点：订阅任务进度更新
    
    鉴权方式：通过 Query 参数传递 JWT Token
    """
    # 验证 Token
    user_id = None
    if token:
        try:
            payload = jwt.decode(
                token, 
                settings.JWT_SECRET_KEY, 
                algorithms=[settings.JWT_ALGORITHM]
            )
            user_id = payload.get("sub")
        except JWTError:
            await websocket.close(code=4001)
            return
    
    # 验证用户有权访问该任务
    if user_id:
        async with repo_factory.create_session() as session:
            task_repo = repo_factory.create_task_repo(session)
            task = await task_repo.get_by_task_id(task_id)
            if task and task.user_id != user_id:
                await websocket.close(code=4003)  # Forbidden
                return
    
    await manager.connect(websocket, task_id)
    # ... 后续逻辑
```

#### 1.4 🔒 JWT 黑名单机制 [P0-Medium]

**问题**：无法立即撤销已签发的 Token。

**修复方案**：

```python
# app/core/auth/jwt_blacklist.py
from app.db.redis_client import redis_client

JWT_BLACKLIST_PREFIX = "jwt:blacklist:"

async def add_to_blacklist(jti: str, expires_in: int):
    """
    将 Token 加入黑名单
    
    Args:
        jti: JWT ID
        expires_in: Token 剩余有效期（秒）
    """
    await redis_client.connect()
    await redis_client._client.setex(
        f"{JWT_BLACKLIST_PREFIX}{jti}",
        expires_in,
        "1"
    )

async def is_blacklisted(jti: str) -> bool:
    """检查 Token 是否在黑名单中"""
    await redis_client.connect()
    return await redis_client._client.exists(f"{JWT_BLACKLIST_PREFIX}{jti}") > 0
```

```python
# app/core/auth/deps.py
from app.core.auth.jwt_blacklist import is_blacklisted

        raise HTTPException(status_code=401, detail="Token has been revoked")
```

#### 2.1 📐 Session 读写分离 [P1-High]

**问题**：未区分读写 Session，事务边界不清晰。

**修复方案**：

```python
# app/db/session.py

from typing import Annotated
from fastapi import Depends

# 读操作 Session（不自动提交）
async def get_db_readonly() -> AsyncGenerator[AsyncSession, None]:
    """只读操作使用"""
    async with safe_session() as session:
        yield session
        # 不 commit，让调用方决定

# 写操作 Session（自动提交/回滚）
@asynccontextmanager
async def get_db_transaction() -> AsyncGenerator[AsyncSession, None]:
    """写操作使用（自动事务管理）"""
    async with safe_session() as session:
        try:
            yield session
            await session.commit()
        except Exception:
            await session.rollback()
            raise

# 类型别名（用于依赖注入）
CurrentSession = Annotated[AsyncSession, Depends(get_db_readonly)]
CurrentSessionTransaction = Annotated[AsyncSession, Depends(get_db_transaction)]
```

```python
# 使用示例
@router.get("/users/{user_id}")
async def get_user(user_id: str, db: CurrentSession):
    """读操作使用 CurrentSession"""
    return await user_repo.get_by_id(db, user_id)

@router.post("/users")
async def create_user(user: CreateUserSchema, db: CurrentSessionTransaction):
    """写操作使用 CurrentSessionTransaction"""
    return await user_service.create(db=db, obj=user)
```

```python
# 1. 将业务逻辑从 API 层移到 Service 层
# app/services/roadmap_service.py

class RoadmapService:
    """路线图服务（重构版）"""
    
    async def create_generation_task(
        self,
        user_request: UserRequest,
    ) -> CreateTaskResponse:
        """
        创建路线图生成任务
        
        Returns:
            CreateTaskResponse Schema（非 ORM Model）
        """
        task_id = str(uuid.uuid4())
        
        async with self.repo_factory.create_session() as session:
            task_repo = self.repo_factory.create_task_repo(session)
            await task_repo.create_task(
                task_id=task_id,
                user_id=user_request.user_id,
                user_request=user_request.model_dump(mode='json'),
            )
            await session.commit()
        
        # 分发 Celery 任务
        celery_task = generate_roadmap.delay(
            task_id=task_id,
            user_request=user_request.preferences.learning_goal,
            user_id=user_request.user_id,
            learning_preferences=user_request.preferences.model_dump(mode='json'),
        )
        
        # 返回 Schema，而非 ORM Model
        return CreateTaskResponse(
            task_id=task_id,
            status="pending",
            celery_task_id=celery_task.id,
        )
```

#### 2.3 📊 StateManager 迁移到 Redis [P1-Medium]

**问题**：`StateManager.live_step` 使用内存 dict，无法水平扩展。

**修复方案**：

```python
# app/core/orchestrator/state_manager.py

class StateManager:
    """状态管理器（Redis 版本）"""
    
    LIVE_STEP_PREFIX = "workflow:live_step:"
    LIVE_STEP_TTL = 3600  # 1 小时
    
    async def set_live_step(self, task_id: str, step: str):
        """设置任务当前步骤（Redis）"""
        await redis_client.connect()
        await redis_client._client.setex(
            f"{self.LIVE_STEP_PREFIX}{task_id}",
            self.LIVE_STEP_TTL,
            step,
        )
    
    async def get_live_step(self, task_id: str) -> str | None:
        """获取任务当前步骤"""
        await redis_client.connect()
        return await redis_client._client.get(f"{self.LIVE_STEP_PREFIX}{task_id}")
    
    async def clear_live_step(self, task_id: str):
        """清除任务步骤缓存"""
        await redis_client.connect()
        await redis_client._client.delete(f"{self.LIVE_STEP_PREFIX}{task_id}")
```

#### 3.1 🚀 引入 msgspec 高性能序列化 [P2-High]

**问题**：大文本教程序列化时，`json`/`pydantic` 性能不足。

**修复方案**：


```python
# app/utils/serializers.py
import msgspec
from typing import Any

encoder = msgspec.json.Encoder()
decoder = msgspec.json.Decoder()

def fast_dumps(obj: Any) -> bytes:
    """高性能 JSON 序列化"""
    return encoder.encode(obj)

def fast_loads(data: bytes | str) -> Any:
    """高性能 JSON 反序列化"""
    if isinstance(data, str):
        data = data.encode()
    return decoder.decode(data)
```

```python
# app/services/notification_service.py
from app.utils.serializers import fast_dumps

async def _publish(self, task_id: str, event: dict):

    # 使用 msgspec 序列化（比 json.dumps 快 10 倍）
    await redis_client._client.publish(
        self._get_channel(task_id),
        fast_dumps(event),
```

#### 3.2 🔍 N+1 查询优化 [P2-Medium]

**问题**：加载路线图框架时可能产生 N+1 查询。

**修复方案**：

```python
# app/db/repositories/roadmap_meta_repo.py
from sqlalchemy.orm import selectinload

class RoadmapMetadataRepository(BaseRepository[RoadmapMetadata]):
    
    async def get_with_concepts(self, roadmap_id: str) -> RoadmapMetadata | None:
        """
        获取路线图及其所有概念元数据（避免 N+1）
        """
        result = await self.session.execute(
            select(RoadmapMetadata)
            .options(selectinload(RoadmapMetadata.concept_metas))
            .where(RoadmapMetadata.roadmap_id == roadmap_id)
        )
        return result.scalar_one_or_none()
```

#### 3.3 📈 连接池配置优化 [P2-Medium]

**问题**：总连接数计算需包含主 DB 池和 LangGraph Checkpointer 池。

**修复方案**：

```python
# app/config/settings.py

class Settings(BaseSettings):
    # 主数据库连接池（每进程）
    DB_POOL_SIZE: int = Field(4, description="主数据库连接池大小")
    DB_MAX_OVERFLOW: int = Field(3, description="主数据库最大溢出")
    
    # LangGraph Checkpointer 连接池（全局共享）
    LANGGRAPH_POOL_MIN: int = Field(2, description="LangGraph 最小连接数")
    LANGGRAPH_POOL_MAX: int = Field(10, description="LangGraph 最大连接数")
    
    @property
    def estimated_total_connections(self) -> int:
        """
        估算总连接数
        
        公式：主池 × 进程数 + LangGraph 池
        """
        # 假设 4 个 uvicorn worker + 3 个 Celery worker
        api_workers = 4
        celery_workers = 3
        total_workers = api_workers + celery_workers
        
        main_pool = (self.DB_POOL_SIZE + self.DB_MAX_OVERFLOW) * total_workers
        langgraph_pool = self.LANGGRAPH_POOL_MAX
        
        return main_pool + langgraph_pool
```

```python
# app/tasks/roadmap_generation_tasks.py

@celery_app.task(
    name="roadmap_generation.generate_roadmap",
    bind=True,
    max_retries=3,  # 最多重试 3 次

    reject_on_worker_lost=True,
    time_limit=1800,
    soft_time_limit=1680,
)
def generate_roadmap(self, task_id: str, ...):

        return run_async(_execute_roadmap_workflow(...))

        # 记录重试信息
        logger.warning(
            "task_retry",
            task_id=task_id,
            retry_count=self.request.retries,
            error=str(e),
        )
        raise  # 让 Celery 处理重试
```
