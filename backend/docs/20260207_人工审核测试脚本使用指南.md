# 人工审核测试脚本使用指南

## 概述

`test_human_review.py` 是一个用于测试路线图人工审核功能的自动化脚本。

## 功能特性

1. ✅ **查找待审核任务** - 自动查询用户的待审核任务列表
2. ✅ **创建新任务** - 创建启用人工审核的路线图生成任务
3. ✅ **等待审核状态** - 自动轮询任务状态，等待进入 `human_review_pending`
4. ✅ **提交审核决策** - 批准或拒绝路线图，支持自定义反馈
5. ✅ **交互式/自动化模式** - 支持手动选择或自动化测试

## 使用方法

### 1. 交互式审核现有任务

```bash
cd backend
uv run python scripts/test_human_review.py
```

**流程：**
- 自动登录测试用户
- 查找所有待审核任务
- 手动选择要审核的任务
- 手动选择批准/拒绝
- 提交审核决策

### 2. 创建新任务并审核

```bash
cd backend
uv run python scripts/test_human_review.py --create-new
```

**流程：**
- 创建新的路线图生成任务（`skip_human_review=False`）
- 等待任务完成验证阶段
- 等待任务进入 `human_review_pending` 状态
- 手动选择批准/拒绝
- 提交审核决策

### 3. 自动批准模式

```bash
cd backend
uv run python scripts/test_human_review.py --create-new --auto-approve
```

**适用场景：**
- 自动化测试
- CI/CD 流水线
- 快速验证工作流

### 4. 自动拒绝模式（带反馈）

```bash
cd backend
uv run python scripts/test_human_review.py --create-new --auto-reject --feedback "请增加更多实战项目"
```

**适用场景：**
- 测试修改流程
- 验证编辑计划分析功能
- 测试工作流循环

## 命令行参数

| 参数 | 说明 | 示例 |
|-----|------|-----|
| `--create-new` | 创建新任务（而不是查找现有任务） | `--create-new` |
| `--auto-approve` | 自动批准（无需人工确认） | `--auto-approve` |
| `--auto-reject` | 自动拒绝（无需人工确认） | `--auto-reject` |
| `--feedback` | 拒绝时的反馈意见 | `--feedback "需要修改"` |

## API 端点说明

脚本使用以下 API 端点：

| 功能 | 方法 | 端点 | 说明 |
|-----|------|------|-----|
| 登录 | POST | `/api/v1/auth/jwt/login` | FastAPI Users 认证端点（form data） |
| 获取用户信息 | GET | `/api/v1/users/me` | 获取当前登录用户详情（FastAPI Users） |
| 获取当前用户任务 | GET | `/api/v1/tasks/my` | 查询当前用户的所有任务（从 JWT 自动提取 user_id） |
| 创建路线图任务 | POST | `/api/v1/tasks/generate` | 提交路线图生成请求 |
| 查询任务状态 | GET | `/api/v1/tasks/{task_id}/status` | 获取任务当前状态 |
| 提交审核决策 | POST | `/api/v1/tasks/{task_id}/approve` | 批准或拒绝路线图 |

## 注意事项

1. **环境变量**
   - 确保 `.env` 中 `SKIP_HUMAN_REVIEW` 未设置或设置为 `false`
   - 如果设置为 `true`，工作流会跳过人工审核

2. **任务状态**
   - 只有状态为 `human_review_pending` 的任务可以审核
   - 已完成或失败的任务无法审核

3. **超时设置**
   - 默认等待 5 分钟（100 次 × 3 秒）
   - 可以修改脚本中的 `MAX_POLL_ATTEMPTS` 和 `POLL_INTERVAL`

4. **并发测试**
   - 可以同时运行多个脚本实例
   - 每个实例可以审核不同的任务

## 故障排查

### 1. 登录失败

```
❌ 登录失败: {"detail":"Invalid credentials"}
```

**解决方案：**
- 检查测试用户是否存在
- 检查密码是否正确
- 检查后端服务是否运行

### 2. 任务未进入审核状态

```
❌ 任务未能进入审核状态
```

**可能原因：**
- `SKIP_HUMAN_REVIEW=true` 启用了跳过审核
- 任务在验证阶段失败
- 工作流配置错误

**解决方案：**
- 检查 `.env` 配置
- 查看任务日志：`GET /api/v1/tasks/{task_id}/logs`
- 检查 Celery worker 日志

### 3. 提交审核失败

```
❌ 提交审核失败
```

**可能原因：**
- 任务状态不是 `human_review_pending`
- 网络连接问题
- 后端服务异常

**解决方案：**
- 检查任务状态：`GET /api/v1/tasks/{task_id}/status`
- 检查后端日志
- 检查 Celery worker 是否运行

## 扩展功能

### 批量审核

如果需要批量审核多个任务，可以修改脚本：

```python
# 批量批准所有待审核任务
tasks = await get_user_tasks(client, token, user_id)
pending_tasks = [t for t in tasks if t["status"] == "human_review_pending"]

for task in pending_tasks:
    await submit_approval(client, token, task["task_id"], approved=True)
```

### 自定义审核逻辑

可以根据路线图内容自动决定批准或拒绝：

```python
# 获取路线图详情
roadmap = await get_roadmap_detail(client, token, roadmap_id)

# 根据规则自动审核
if roadmap["total_hours"] > 100:
    approved = False
    feedback = "学习时长过长，请简化"
else:
    approved = True
    feedback = None
```
