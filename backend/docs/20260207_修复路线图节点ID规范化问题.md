# 路线图节点ID规范化问题修复

**日期**: 2026-02-07  
**问题**: roadmap_edit阶段编辑后生成的framework中节点编码不规范，存在xxx-new的ID标识  
**影响范围**: 后端 - RoadmapEditorAgent、CurriculumArchitectAgent  

---

## 一、问题描述

在路线图编辑（roadmap_edit）阶段，LLM生成的框架中可能包含非标准的节点ID，例如：
- `c-3-1-new` - 带有`-new`后缀的Concept ID
- `m-4-1-new` - 带有`-new`后缀的Module ID  
- `s-1-old` - 带有其他非标准后缀的Stage ID

这些非标准ID会导致：
1. **数据库查询问题** - 依赖关系引用无效
2. **前端展示混乱** - ID不规范影响UI渲染
3. **数据一致性问题** - 同一节点可能有多个不同的ID表示

---

## 二、根本原因

LLM在生成修改后的路线图时，会为新增或修改的节点生成带有特殊后缀的ID（如`-new`、`-old`），用于标识节点的变化状态。但这些临时ID没有在输出前被规范化。

**问题位置**:
- `backend/app/agents/roadmap_editor.py` - RoadmapEditorAgent
- `backend/app/agents/curriculum_architect.py` - CurriculumArchitectAgent

---

## 三、解决方案

### 3.1 新增ID规范化工具

创建了 `backend/app/agents/framework_normalizer.py`，提供统一的ID规范化功能。

**规范化规则**:
```
Stage ID:   s-{stage_order}                    例: s-1, s-2
Module ID:  m-{stage_order}-{module_index}     例: m-1-1, m-1-2
Concept ID: c-{stage_order}-{module_index}-{concept_index}  例: c-1-1-1, c-1-1-2
```

**核心功能**:
1. 遍历所有Stage、Module、Concept，按规则重新编号
2. 构建旧ID到新ID的映射表
3. 更新所有Concept的prerequisites引用（将旧ID替换为新ID）
4. 保留其他所有字段不变

### 3.2 集成到Agent工作流

**修改1: RoadmapEditorAgent** (`backend/app/agents/roadmap_editor.py`)
```python
# 在LLM生成framework之后，立即进行ID规范化
updated_framework = await self._call_llm(...)

# ✅ ID规范化：移除LLM生成的非标准ID（如xxx-new）
logger.info("roadmap_edit_normalizing_ids")
updated_framework = normalize_framework_ids(updated_framework)
```

**修改2: CurriculumArchitectAgent** (`backend/app/agents/curriculum_architect.py`)
```python
# 在依赖关系检查之后，进行ID规范化
full_framework, fixes = self._check_and_fix_dependencies(full_framework)

# ✅ ID规范化：确保所有Stage、Module、Concept的ID符合规范
logger.info("curriculum_design_normalizing_ids", roadmap_id=roadmap_id)
full_framework = normalize_framework_ids(full_framework)
```
