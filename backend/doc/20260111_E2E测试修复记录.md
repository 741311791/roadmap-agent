### ✅ 问题1：登录时数据库会话错误

**错误信息**:
```
database_error: "Can't operate on closed transaction inside context manager."
```

**根本原因**:
- FastAPI Users 的 `get_user_db` 使用了事务会话 (`get_db_transaction`)
- 登录操作只需要读取用户数据，不需要事务
- 事务会话在上下文结束时自动关闭，导致后续访问失败

**修复方案**:
- 修改文件：`backend/app/core/auth/backend.py`
- 将 `get_user_db` 从使用 `get_db_transaction` 改为 `get_db_readonly`
- 登录操作使用只读会话，避免事务管理问题

**代码变更**:
```python
# 修改前
from app.db.session import get_db_transaction
async def get_user_db(session: AsyncSession = Depends(get_db_transaction)):
    yield SQLAlchemyUserDatabase(session, User)

# 修改后
from app.db.session import get_db_readonly
async def get_user_db(session: AsyncSession = Depends(get_db_readonly)):
    yield SQLAlchemyUserDatabase(session, User)
```

### ✅ 问题2：`ensure_unique_roadmap_id` 参数错误

**错误信息**:
```
ensure_unique_roadmap_id() takes 2 positional arguments but 3 were given
```

**根本原因**:
- `workflow_brain.py` 调用时传递了 3 个参数：`(roadmap_id, roadmap_crud, session)`
- `base.py` 中的函数定义只接收 2 个参数：`(roadmap_id, repo)`
- `RoadmapCRUD.roadmap_id_exists()` 方法需要 `session` 参数

**修复方案**:
- 修改文件：`backend/app/core/orchestrator/base.py`
- 添加 `session` 参数到函数签名
- 更新所有调用 `repo.roadmap_id_exists()` 的地方传递 `session`

**代码变更**:
```python
# 修改前
async def ensure_unique_roadmap_id(roadmap_id: str, repo) -> str:
    if not await repo.roadmap_id_exists(roadmap_id):
        return roadmap_id
    # ...
    if not await repo.roadmap_id_exists(new_roadmap_id):
        return new_roadmap_id

# 修改后
async def ensure_unique_roadmap_id(roadmap_id: str, repo, session) -> str:
    if not await repo.roadmap_id_exists(session, roadmap_id):
        return roadmap_id
    # ...
    if not await repo.roadmap_id_exists(session, new_roadmap_id):
        return new_roadmap_id
```

### ✅ 问题4：Celery Worker 事件循环关闭

**错误信息**:
```
RuntimeError: Event loop is closed
```

**根本原因**:
- Celery 使用 `--pool=prefork` 模式
- 子进程通过 fork 继承父进程状态
- 父进程的事件循环在 fork 后已经关闭
- 子进程尝试使用关闭的事件循环导致错误

**修复方案**:
- 修改文件：`backend/app/core/celery_app.py`
- 在 `worker_process_init` 信号中创建新的事件循环
- 关闭继承的旧循环，设置新循环为当前循环

**代码变更**:
```python
@worker_process_init.connect
def on_worker_process_init(**kwargs):
    import asyncio
    
    # 第一步：为子进程创建新的事件循环
    try:
        # 尝试关闭旧的事件循环
        try:
            loop = asyncio.get_event_loop()
            if loop.is_closed():
                logger.debug("celery_old_event_loop_closed")
            else:
                loop.close()
        except RuntimeError:
            pass
        
        # 创建新的事件循环
        new_loop = asyncio.new_event_loop()
        asyncio.set_event_loop(new_loop)
        logger.info("celery_event_loop_created", loop_id=id(new_loop))
    except Exception as loop_error:
        logger.error("celery_event_loop_creation_error", error=str(loop_error))
    
    # 第二步：重置数据库引擎缓存
    from app.db.session import reset_engine_cache
    reset_engine_cache()
    # ...
```

## 🔍 关键技术点

### 1. FastAPI Users 数据库会话管理

- 登录操作应使用只读会话
- 注册等写操作使用事务会话
- 避免在会话关闭后访问对象

### 2. Celery Prefork 模式的异步编程陷阱

- Fork 后子进程继承父进程状态
- 需要为每个子进程创建独立的事件循环
- 需要重置数据库连接池

### 3. CRUD 方法的完整性

- CRUD 类需要实现所有被调用的方法
- 注意 Pydantic 模型到 SQLModel 的转换
- 使用 `TYPE_CHECKING` 避免循环导入

### 4. SQLAlchemy 会话参数传递

- Repository 方法需要显式传递 `session` 参数
- 不要假设方法会自动获取会话
- 保持参数顺序一致性
