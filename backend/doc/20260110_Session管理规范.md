# Session 管理规范（强制执行）

## 核心原则

### 原则1：双Session隔离
- **FastAPI进程**：只使用 `async_session_maker`（连接池）
- **Celery Worker**：只使用 `get_celery_session()`（NullPool）
- **严禁跨进程混用**

### 原则2：所有权明确
- 谁创建Session，谁负责关闭
- Service层不应自己创建Session
- 优先使用依赖注入

### 原则3：事务边界清晰
- FastAPI：通过 `CurrentSession` 或 `CurrentSessionTransaction` 注入
- Celery：在任务函数顶层使用 `async with get_celery_session()`

## 使用模式

### FastAPI API层（推荐）

```python
from app.api.v1.deps import CurrentSession, CurrentSessionTransaction

# 只读操作
@router.get("/roadmaps/{id}")
async def get_roadmap(id: str, session: CurrentSession):
    return await crud.get(session, id)

# 写操作
@router.post("/roadmaps")
async def create_roadmap(data: RoadmapCreate, session: CurrentSessionTransaction):
    return await crud.create(session, data)
```

### Celery任务层（推荐）

```python
from app.db.celery_session import get_celery_session

@celery_app.task
def my_task(roadmap_id: str):
    async def _run():
        async with get_celery_session() as session:
            result = await crud.get(session, roadmap_id)
            # session 自动 commit/rollback/close
            return result
    
    return asyncio.run(_run())
```

### Service层（推荐）

```python
# 方式1：方法参数注入
class RoadmapService:
    async def get_roadmap(self, session: AsyncSession, roadmap_id: str):
        return await crud.get(session, roadmap_id)

# 方式2：构造函数注入
class RoadmapService:
    def __init__(self, session: AsyncSession):
        self.session = session
    
    async def get_roadmap(self, roadmap_id: str):
        return await crud.get(self.session, roadmap_id)
```

## 禁止模式

### 禁止1：Service自己创建Session

```python
# ❌ 错误
class RoadmapService:
    async def get_roadmap(self, roadmap_id: str):
        async with async_session_maker.begin() as session:  # ❌
            return await crud.get(session, roadmap_id)
```

### 禁止2：FastAPI使用Celery Session

```python
# ❌ 错误
@router.get("/roadmaps/{id}")
async def get_roadmap(id: str):
    async with get_celery_session() as session:  # ❌ NullPool性能差
        return await crud.get(session, id)
```

### 禁止3：Celery使用FastAPI Session

```python
# ❌ 错误
@celery_app.task
def my_task():
    async def _run():
        async with async_session_maker.begin() as session:  # ❌ 连接池跨进程
            return await crud.get(session, id)
    return asyncio.run(_run())
```

## 常见场景处理

### 场景1：FastAPI启动时初始化数据

**问题**：在 `lifespan` 函数中应该使用哪个Session？

**答案**：使用 `async_session_maker`，因为这是在FastAPI主进程中执行。

```python
@asynccontextmanager
async def lifespan(app: FastAPI):
    # ✅ 正确
    async with async_session_maker.begin() as session:
        await initialize_data(session)
    
    yield
```

### 场景2：同时被FastAPI和Celery调用的Service

**问题**：Service方法可能被API和Celery任务调用，应该怎么设计？

**答案**：通过参数注入Session，由调用方决定使用哪种Session。

```python
# Service层（不创建Session）
class RoadmapService:
    async def get_roadmap(self, session: AsyncSession, roadmap_id: str):
        return await crud.get(session, roadmap_id)

# FastAPI层调用
@router.get("/roadmaps/{id}")
async def get_roadmap(id: str, session: CurrentSession, service: RoadmapService = Depends()):
    return await service.get_roadmap(session, id)

# Celery层调用
@celery_app.task
def my_task(roadmap_id: str):
    async def _run():
        async with get_celery_session() as session:
            service = RoadmapService()
            return await service.get_roadmap(session, roadmap_id)
    return asyncio.run(_run())
```

### 场景3：长时间运行的Celery任务中的多次数据库操作

**问题**：任务需要多次查询/更新数据库，是否应该复用Session？

**答案**：看事务边界需求：
- 如果需要原子性（要么全成功要么全失败）：使用同一个Session
- 如果是独立操作：使用多个Session

```python
# 原子性场景（推荐）
@celery_app.task
def atomic_task():
    async def _run():
        async with get_celery_session() as session:
            # 多个操作在同一事务中
            await crud.create(session, data1)
            await crud.update(session, data2)
            # 自动commit
    return asyncio.run(_run())

# 独立操作场景
@celery_app.task
def independent_task():
    async def _run():
        # 操作1
        async with get_celery_session() as session:
            await crud.create(session, data1)
        
        # 操作2（独立事务）
        async with get_celery_session() as session:
            await crud.update(session, data2)
    return asyncio.run(_run())
```

## 连接池配置说明

### FastAPI进程（async_session_maker）

```python
# backend/app/db/session.py
engine = create_async_engine(
    settings.DATABASE_URL,
    pool_size=3,  # 基础连接数
    max_overflow=2,  # 最大溢出数
    pool_pre_ping=True,  # 连接健康检查
    pool_recycle=300,  # 5分钟回收连接
)
```

**计算公式**：
- 每进程最大连接数 = `pool_size` + `max_overflow` = 5
- FastAPI 4个进程 = 4 × 5 = 20个连接（峰值）

### Celery Worker（get_celery_session）

```python
# backend/app/db/celery_session.py
engine = create_async_engine(
    settings.DATABASE_URL,
    poolclass=NullPool,  # 无连接池，每次创建新连接
)
```

**特点**：
- 不复用连接，避免Fork进程问题
- 按需创建，用完即销毁
- 通过 `--concurrency` 参数限制并发数

## 故障排查

### 问题1：NameError: name 'repo' is not defined

**原因**：代码中使用了已删除的 `RepositoryFactory`。

**解决**：使用对应的CRUD，例如：
```python
# ❌ 错误
await repo.get_roadmap_metadata(roadmap_id)

# ✅ 正确
from app.crud.crud_roadmap import get_roadmap_crud
roadmap_crud = get_roadmap_crud()
await roadmap_crud.get_by_roadmap_id(session, roadmap_id)
```

### 问题2：Task failed: NullPool cannot checkin a connection

**原因**：FastAPI进程错误使用了 `get_celery_session()`。

**解决**：改用 `async_session_maker`。

### 问题3：连接池耗尽 (TimeoutError)

**原因**：连接未正确释放或并发数过高。

**排查步骤**：
1. 检查 `/health/db` 端点查看连接池状态
2. 查看Prometheus指标 `db_pool_connections_in_use`
3. 检查代码中是否有未关闭的Session
4. 考虑增加 `pool_size` 或减少并发数
