# 步进器分支识别问题完整分析与修复

## 问题描述

前端任务详情页中，当 Current Step 为 `roadmap_edit` 时，步进器未能正确识别当前所在的分支（验证失败分支 或 人工审核分支），导致显示错误。

## 根因分析

### 设计规范

根据 `backend/app/models/constants.py` 中的 WorkflowStep 枚举定义：

```python
class WorkflowStep(str, Enum):
    # 共享编辑节点（由edit_source区分来源：validation_failed或human_review）
    EDIT_PLAN_ANALYSIS = "edit_plan_analysis"  # 编辑计划分析（共享）
    ROADMAP_EDIT = "roadmap_edit"              # 路线图修正（共享）
```

**关键设计点**：
- ✅ 只有 `edit_plan_analysis` 和 `roadmap_edit` 两个**共享节点**
- ✅ 通过 `edit_source` 字段区分来源（`validation_failed` 或 `human_review`）
- ❌ **不存在** `validation_edit_plan_analysis` 这个步骤名

### 工作流路径

```
验证失败分支：
  structure_validation [失败]
    → edit_plan_analysis (edit_source=validation_failed)
    → roadmap_edit (edit_source=validation_failed)
    → structure_validation

人工审核分支：
  human_review [拒绝]
    → edit_plan_analysis (edit_source=human_review)
    → roadmap_edit (edit_source=human_review)
    → human_review
```

### 问题根源

**后端遗留文件**：
代码库中存在两个**已废弃且不符合设计规范**的文件：

1. `backend/app/core/orchestrator/nodes/validation_edit_plan_analysis.py`   - 使用步骤名：`"validation_edit_plan_analysis"` (Line 86, 103)
   - 这个步骤名**不在** WorkflowStep 枚举中

2. `backend/app/core/orchestrator/handlers/validation_edit_plan_handler.py`
   - get_node_name 返回：`"validation_edit_plan_analysis"` (Line 24)
   - 这个 Handler **未被注册**到 HandlerRegistry

**影响**：
- 虽然当前工作流已经不使用这些文件
- 但如果数据库中存在使用旧步骤名的历史日志
- 前端的日志过滤逻辑会遗漏这些日志，导致无法提取 `edit_source`
- 步进器无法判断分支，回退到默认的 'analysis' 节点（错误显示）

### 验证点

**后端当前实现（正确）**：

1. ✅ WorkflowBuilder 只注册了共享节点：
   ```python
   workflow.add_node("edit_plan_analysis", self.edit_plan_node)
   workflow.add_node("roadmap_edit", self.editor_node)
   ```

2. ✅ HandlerRegistry 只注册了共享 Handler：
   ```python
   handler_registry.register("edit_plan_analysis", EditPlanHandler(state_manager))
   handler_registry.register("roadmap_edit", EditorHandler(state_manager))
   ```

3. ✅ 状态设置正确：
   - `structure_validation_node` (Line 100): 验证失败时设置 `edit_source="validation_failed"`
   - `human_review_node` (Line 273): 拒绝时设置 `edit_source="human_review"`

4. ✅ 日志记录正确：
   - `edit_plan_analysis_node` (Line 106): `details={"edit_source": edit_source}`
   - `roadmap_edit_node` (Line 120): `details={"edit_source": edit_source}`

**前端实现（正确）**：

前端的日志过滤逻辑**完全符合设计规范**：

```typescript
// frontend-next/app/(app)/tasks/[taskId]/page.tsx
const latestEditSource = allLogs
  .filter(log => 
    (log.step === 'roadmap_edit' || log.step === 'edit_plan_analysis') && 
    log.details && 'edit_source' in log.details
  )
  .sort((a, b) => new Date(b.created_at).getTime() - new Date(a.created_at).getTime())
  [0]?.details?.edit_source || null;
```

### 1. 删除遗留文件（已完成）


**文件状态**：✅ 已删除

### 2. 检查数据库历史日志

运行检查脚本，查看数据库中是否存在使用旧步骤名的日志：

```bash
cd backend
python scripts/check_old_step_logs.py
```

如果发现使用旧步骤名的日志，可以考虑更新（⚠️ 谨慎操作，建议先备份）：

```sql
-- 查询使用旧步骤名的日志
SELECT COUNT(*) 
FROM execution_logs 
WHERE step = 'validation_edit_plan_analysis';

-- 更新为正确的步骤名和edit_source（谨慎操作！）
UPDATE execution_logs 
SET step = 'edit_plan_analysis',
    details = jsonb_set(
      COALESCE(details, '{}'), 
      '{edit_source}', 
      '"validation_failed"'
    )
WHERE step = 'validation_edit_plan_analysis';
```

### 3. 添加防御性日志（可选）

在前端添加调试日志，当无法提取 edit_source 时记录警告：

```typescript
if (!latestEditSource &&

```

### 1. 创建新任务

创建一个会触发验证失败的路线图任务：

2. 等待任务进入 `edit_plan_analysis` 步骤
3. 观察步进器显示是否正确

### 2. 检查数据库日志

```sql
-- 查看最新的 edit_plan_analysis 日志
SELECT task_id, step, details->>'edit_source' as edit_source, created_at
FROM execution_logs
WHERE step = 'edit_plan_analysis'
ORDER BY created_at DESC
LIMIT 5;

-- 查看最新的 roadmap_edit 日志
SELECT task_id, step, details->>'edit_source' as edit_source, created_at
FROM execution_logs
WHERE step = 'roadmap_edit'
ORDER BY created_at DESC
LIMIT 5;
```

确认：
- ✅ step 是 `edit_plan_analysis` 或 `roadmap_edit`
- ✅ details.edit_source 是 `validation_failed` 或 `human_review`

### 3. 检查前端显示

在浏览器控制台查看：

确认步进器：

2. 点击 "Change" 按钮并提交反馈
3. 观察步进器是否正确显示审核分支

确认：
- ✅ 审核分支：上方显示 Plan → Edit 节点高亮
