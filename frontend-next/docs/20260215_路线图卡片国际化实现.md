## 技术细节

### 国际化实现方式

使用 `next-intl` 库的 `useTranslations` hook：

```typescript
const t = useTranslations();
// 使用方式
t('roadmapCard.delete')
// 带参数的翻译
t('roadmapCard.timeDaysAgo', { days: 5 })
```

### 时间格式化逻辑

保持原有的时间差计算逻辑，只替换输出文本：
- 0天：今天/Today
- 1天：昨天/Yesterday
- <7天：X天前/X days ago
- <30天：X周前/X weeks ago
- ≥30天：X个月前/X months ago

### 生成步骤映射

动态映射后端返回的步骤状态到国际化文本：
- `queued` → "排队中" / "Queued"
- `intent_analysis` → "分析学习目标" / "Analyzing goals"
- `curriculum_design` → "设计课程架构" / "Designing curriculum"
- 等等...

## 注意事项

1. **用户数据 vs 界面文本**
   - ✅ 翻译：界面元素（按钮、标签、单位、提示文本）
   - ❌ 不翻译：用户生成的内容（路线图标题、阶段名称、描述等）
   - 示例：
     - "计算机/GIS方向考研系统备考路线图" - 这是用户数据，不应翻译
     - "FEATURED"、"View"、"concepts" - 这些是界面文本，需要翻译

2. **保持格式一致性**
   - 确保中英文版本的符号使用一致（如：空格、标点）
   - 保持数字格式化的一致性
   - 英文：`5 concepts`，中文：`5概念`（无空格）

3. **翻译质量**
   - 英文翻译使用简洁、专业的表达
   - 中文翻译符合本地化习惯
   - 保持术语一致性（如：concepts → 概念，hours → 小时）

4. **扩展性**
   - 新增状态时，记得同时更新 `en.json` 和 `zh.json`
   - 遵循现有的命名规范（如：`featuredCard.xxx`）
   - 使用语义化的键名
