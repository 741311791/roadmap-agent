## 技术细节

### 国际化实现方式

使用 `next-intl` 库的 `useTranslations` hook，与已有页面保持一致：

```typescript
const t = useTranslations();
// 使用方式
t('newRoadmap.title')
t('newRoadmap.hoursWeek')
```

### 动态标签生成

对于数组循环中的动态内容（如难度级别、内容类型），使用模板字符串动态获取翻译：

```typescript
// 难度级别
levelOptions.map((level) => (
  <>
    <div>{t(`newRoadmap.${level.id}`)}</div>
    <div>{t(`newRoadmap.${level.id}Desc`)}</div>
  </>
))

// 内容类型
contentOptions.map((option) => (
  <>
    <span>{t(`newRoadmap.${option.id}`)}</span>
    <div>{t(`newRoadmap.${option.id}Desc`)}</div>
  </>
))
```

### 数据结构简化

原有的常量定义包含硬编码的标签文本，国际化后进行了简化：

```typescript
// 简化前
const contentOptions = [
  { id: 'visual', label: 'Visual', icon: Eye, desc: 'Videos, diagrams, demonstrations' },
  ...
];

const levelOptions = [
  { id: 'beginner', label: 'Beginner', description: 'New to this topic' },
  ...
];

// 简化后
const contentOptions = [
  { id: 'visual', icon: Eye },
  ...
];

const levelOptions = [
  { id: 'beginner' },
  ...
];
```

## 注意事项

1. **用户数据 vs 界面文本**
   - ✅ 翻译：界面元素（标签、按钮、提示、描述）
   - ❌ 不翻译：用户输入的内容、语言选项的原生名称

2. **保持格式一致性**
   - 确保中英文版本的符号使用一致
   - 保持数字格式化的一致性
   - 英文：`10h/week`，中文：`10小时/周`

3. **翻译质量**
   - 英文翻译使用简洁、专业的表达
   - 中文翻译符合本地化习惯
   - 保持术语一致性（如：Beginner → 初学者，Intermediate → 中级）

4. **扩展性**
   - 新增表单字段时，记得同时更新 `en.json` 和 `zh.json`
   - 遵循现有的命名规范（如：`newRoadmap.xxx`）
   - 使用语义化的键名
